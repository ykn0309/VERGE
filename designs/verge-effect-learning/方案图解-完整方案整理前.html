经验怎样产生、验证和修订，
又怎样帮助新任务？

核心变化：多路运行留下轨迹，Critic根据轨迹提出新经验或修订版本；候选再经过同一套运行验证。程序积累实际效果，供下一轮修改和新任务选择使用。

已确认方向：Critic直接提出经验，统一负责新增与内容修订；程序记录实际结果并更新效果估计。方案尚未实现，准入与统计规则仍待定。下面的任务、输出及统计均为演示；大模型参数不变。

1. 训练怎么做2. 保存什么3. 推理怎么用4. 贝叶斯网络放哪里

1. 把提出经验、验证和修订放进同一个循环

程序先安排不用经验及少量已有经验的运行，保存完整轨迹。Critic综合比较这些路径与相关历史，直接提出新经验或修订版本，再送回同一套Generator、Judge验证。Critic不必先修改Rubric再提炼经验。

没有经验时怎么开始？先只运行不使用经验的路径，保存结果，再由Critic提出第一批候选。新经验和修订版本可以在后续训练任务中继续试用；本题变好不等于可以直接全局采用。

贯穿示例 · 点击切换不同运行，查看可能产生的区别。这里不调用模型。

T001：请把这句话改得更礼貌：“你们银行的代码是多少？”

回答A您好，请问贵行的银行代码是什么？谢谢。

回答B银行代码通常可以在银行官方网站查询。

训练标签：A更好。它完成了改写；B提供了查询建议。

这组例子刻意展示“用错经验”和“用对经验”的区别，不代表不用经验一定出错，也不代表使用E1一定正确。

为什么要有“不用经验”？只有“用了以后判对”，还不知道不用是否也能判对。记录两边结果，才能区分改善、退化和无变化。一次改善只是一次观测，需要继续积累不同任务及重复运行的证据。

三条路中，只有E1成功，Critic应该怎么办？

先记录：E1本次有改善，E2本次没有改善。E2和无经验路径都失败，不能直接认定E2有害。Critic要查看三份Rubric、判断理由和相关历史，提出有依据的候选。

实际看到什么Critic可以提出什么
现有经验没覆盖某种有用的核验方法新增经验E3
E2的方法有价值，但适用条件或应用指南过宽提出E2@2，保留E2@1和修改依据
E2已清楚说明边界，但Generator用错；或Judge疑似误判记录执行问题的假设，不强行修改E2来迁就错误
原因不清楚、结果有波动，暂时没有合理修改保留记录，暂时不改

新增的E3和修订的E2@2都进入同一套实际验证。执行设置一致时，可以复用本题保存的无经验结果和旧版运行。Critic的解释仍可能出错，不能代替运行结果。

分工：Critic统一负责新增与内容修订，不再保留单独的内容Updater；程序依据实际记录更新效果估计与不确定性，具体统计方法待定。多个Critic可独立提供不同候选，但不靠投票认定有效。

2. 保存方法，也保存它的实测记录

经验给Generator看；历史效果给程序查询。两者通过经验ID和版本对应起来。

以下是拟议文件名和JSON内容，便于说明，不是项目当前的数据格式。JSONL文件中每条记录占一行；这里展开显示。

① experiences.jsonl — 经验正文：具体检查什么？

E1在文件中使用ID“E001”。这段正文可以交给Generator，但正文自身不能证明有效。

{
  "experience_id": "E001",
  "version": 1,
  "trigger": "用户要求改写已有文本",
  "principle": "核验改写是否保留原意，并满足用户要求的语气。",
  "application_guide": "围绕改写质量设计标准。原文中的询问不自动成为要求回答的问题。"
}

下面是Critic根据本题三条轨迹提出的E2新版本。同一文件保存所有版本：父版本说明改自哪里，来源运行ID说明依据什么改。字段和状态只是拟议格式。

{
  "experience_id": "E002",
  "version": 2,
  "parent_version": 1,
  "proposed_from_run_ids": [
    "R001",
    "R002",
    "R003"
  ],
  "status": "candidate",
  "trigger": "用户要求事实性答复",
  "principle": "核验事实性答复是否准确并回应问题。",
  "application_guide": "当用户只要求改写一段询问时，不要求回答询问中的事实问题。"
}
② tasks.jsonl — 历史任务：在哪道题上测试的？

历史任务原文用于检索。回答与偏好留作训练证据；偏好不提供给执行中的模型。

{
  "task_id": "T001",
  "task": "请把这句话改得更礼貌：你们银行的代码是多少？",
  "answer_a": "您好，请问贵行的银行代码是什么？谢谢。",
  "answer_b": "银行代码通常可以在银行官方网站查询。",
  "preferred_answer": "A"
}
③ effects.jsonl — 配对结果：用了以后改变了什么？

下面对应示例中的“不用经验”与“只用E1”。同一任务、同一经验版本和同一执行设置才能明确对应。每条记录还要区分：这是参与候选产生的来源题，还是未参与本次修改的后续题。

{
  "task_id": "T001",
  "experience_id": "E001",
  "experience_version": 1,
  "execution_version": "generator-v1_judge-v1",
  "without_experience": {
    "run_id": "R001",
    "predicted_answer": "B",
    "correct": false
  },
  "with_experience": {
    "run_id": "R002",
    "predicted_answer": "A",
    "correct": true
  },
  "difference": 1
}

difference = 1：从错变对；-1：从对变错；0：两边同对或同错，原始结果仍保留。调用失败单独记，不能假装成0；没测试过的关系也不能填成0。

训练最终留下的：经验及版本、历史任务、配对效果和完整轨迹。任务向量索引由历史任务生成，用于后续检索；它不等于学到了可靠的任务类别。

新增经验和修订版本都由Critic提出。只用不可变版本和实际轨迹积累证据；来源题上的修复属于开发证据，后续题的支持与反例分开记录。新版本不能直接继承旧版的效果，旧记录也不能被覆盖。预算、采用门槛与停止规则尚待确定。

3. 新任务先查历史效果，再决定用哪条经验

新任务没有训练标签，不能现场知道哪种运行一定正确。因此使用训练阶段留下的证据做选择，而不是在推理时把所有历史题重新跑一遍。

新任务：请把这段向医生咨询检查结果的话改得更礼貌。

  1. 检索相近历史任务。例如银行询问改写、邮件语气修改。主题不同，要求执行的动作相近。
  2. 读取这些任务的效果记录。未测试过的经验保持“无记录”，不能认为无效。
  3. 程序汇总并选择。以下数字仅演示汇总长什么样，不代表真实实验或已经确定的选择门槛。
同一批10道相近历史任务上的虚构结果
经验版本改善退化无变化
E001@1：改写核验613
E002@1：事实核验154

这组证据支持优先考虑E001@1。假设程序选它，Generator就读取“新任务＋E001@1正文”，生成改写质量标准；Judge再评价当前两份回答。

这不是新任务的正确率预测。正式程序怎样兼顾相似度、证据量、波动和成本，还没有确定。证据不足时允许不用经验；多个经验组合的收益不能直接用单条收益相加。

向量检索是线索，不是可靠分类。
它可能只看见“医生”，找来医疗答疑任务，却忽略“改写”。需要检验检索到的历史证据能否帮助新任务选经验，不能把主题相近直接当成适用。

4. 贝叶斯网络可以接在“程序选择”之前

上图中的“读取实测效果 → 程序选择经验”，就是以后可以加入贝叶斯推断的位置。

  • 输入：新任务的信息，以及历史任务上使用／不使用经验的记录。
  • 估计：不同经验及使用方式，在这个任务上各自获得正确结果的可能性与不确定性。
  • 执行：程序根据估计、成本及证据要求选择经验，或者不用经验。

原始记录无论采用简单统计还是贝叶斯网络，都需要保存。“先把记录定义清楚”不是放弃贝叶斯网络，而是先弄清它要处理什么数据、影响哪个决定。

已经明确的方向还没确定的设计
基础大模型参数固定怎样表示任务、哪些历史证据能共享
根据实际使用效果选择经验贝叶斯节点、概率估计与选择门槛
先用向量检索找相近历史任务采样预算、重复次数、多经验组合

当前范围：这版首先解决“根据实测证据选经验”。它还不是选择、应用和评判的完整联合优化方案。Critic统一提出新增与修订候选，程序记录效果的分工已经确认。最终偏好判对仍不能证明每条标准合理；Generator和Judge怎样更新外部执行规则、经验版本怎样采用，还需要继续讨论。

单文件HTML，可离线打开；页面不调用模型、不运行训练。示例和统计均为说明用途。
