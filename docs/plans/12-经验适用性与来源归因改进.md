# 计划 12：经验适用性与来源归因改进

> 状态：**A/B/C 规则、提示词和离线测试已实现；评估基线与 D 尚未执行**。本文件规划方法与验证；不修改现有实验结果或宣称改进有效。问题证据见[实验 11 经验机制分析](../实验分析/11-Chat-Hard-经验机制问题.md)，方法边界以[设计总览](../设计方案.md)及子文档为准。

## 1. 目标与范围

解决训练经验从生成到后续使用的三处衔接问题：

```text
Reflection/Admission：trigger 是否能只凭未来 task 判断？
→ Retrieval/Selection：当前 task 是否真的适用、能否产生具体 rubric 价值？
→ Initial Generator：经验是否实质影响标准、source_experiences 是否如实标注？
→ Existing Credit：来源错误是否把 task 本身的收益记到经验上？
```

实验 11 的冻结测试为 43/60；其 31 条选中样本、53 次选择与 47 条带来源标准已经被逐例分析。子代理将 53 次选择中的 39 次标为“过宽”，**只是单模型诊断，不是人工真值或可直接作为上线目标的错误率**。`llmbar-natural:2619` 用于排查不匹配 trigger 如何影响标准；`llmbar-natural:2602` 用于排查任务自带标准的来源误标；`llmbar-adver-GPTInst:2849` 用于提醒负贡献不必然是负迁移。

本轮优先改**生成、准入、选择和来源标注的语义规则及测试**。新增共同的模型输出语言要求：供人阅读的 rubric 标准、critic 反馈、经验 `content`/`trigger` 等以中文表达，机器字段名/ID/枚举保持原样；真实后端只校验结构与类型，中文表达交给提示词，不按汉字数或中英比例拒绝/重试，不宣称可以自动审计语义或语言。暂不增加新的 LLM 筛选阶段，不改变向量 TopL、Beta 更新公式、最多 5 条的选择上限、Rubric Judge 或 revision credit；这些需要各自的证据和独立消融。保留 Selector 可返回空集，不把 confidence 设为硬准入门槛，也不通过删除所有 `source_experiences` 回避错误归因。

## 2. 先建立不泄漏的评估基线

1. **冻结历史材料**：保留实验 11 的配置、轨迹、经验池、prompt 版本与分析文档。已审查的 60 条测试只用于错误诊断和回归，不再作为反复调提示词后的无偏最终成绩；`runs/` 产物不提交，发布统计时需在受控实验中重建可审计记录。
2. **另备开发任务与独立终测**：确定新的开发任务及最终 held-out 数据，先固定来源、版本、划分、归一化去重和评估脚本；开发集用于迭代，最终集仅在冻结方案后运行一次。跨数据源评估另行规划，不把 Chat Hard 同源分数冒充泛化结果。
3. **人工盲标小规模“task × 候选经验”**：只给标注者 task、`content`、`trigger`（不提供 chosen/rejected/Judge）；分别标注 trigger 是否可由 task 核验、经验是否适用、能具体增加什么标准。对 rubric 来源再单独盲审“标准是否由 task 已足以推出/是否实质受经验影响”。保留分歧与存疑，不把 DeepSeek 子代理标注直接当真值；至少复核 `2619`、`2602`、`2849` 这三类易混案例。
4. **确定指标与分母**：报告已召回候选中的适用经验覆盖率、选中经验的适用率、选中但未引用比例、带来源标准的误标率、初始判别的配对正确数，以及请求/token 成本。选择适用率只在“已选”上计算；要测漏选，必须同时标注未选候选。按样本与按经验两种口径分开报告，展示不确定案例及人工分歧。

## 3. 分阶段实施与消融

### A. 把 trigger 限定为事前可观测条件

- 更新 [经验反思](../设计方案/08-经验反思.md)、[修订信用分配与准入](../设计方案/09-修订信用分配与准入.md)的拟议规范，再调整 `verge/prompts.py` 中 `reflector` / `admission_checker` 的要求：trigger 只能引用未来当前 task 中可见的题型、显式要求或上下文，不得以“初始判断错误”“已有标准失败”“回答出现幻觉”等 Judge、rubric 或 response 才能知道的事件为前提。
- `content` 仍可以讲 rubric 生成原则；不要把具体训练回答或 gold label 塞进 trigger。对无法写出可核验 task 条件的候选，允许 Reflection 不生成或 Admission 判 FAIL；不强迫模型编造宽泛条件。
- 用 Fake backend / 定向测试覆盖合格条件、事后条件、混合条件和拒收路径。不要用简单禁词正则代替语义判断，也不向 Selector 暴露 chosen/rejected。**旧池中的 trigger 不自动改写或追溯修改**：需要从空池重训，或另外经人工审计后形成新的实验输入。

### B. Selector 把适用性置于 confidence 之前

- 更新 [经验检索与筛选](../设计方案/02-经验检索与筛选.md)的拟议说明及 `verge/prompts.py`：逐候选先判断 task 是否满足 trigger，再判断能给 rubric 增加何种可执行标准；条件不成立或贡献不明则不选。confidence/evidence amount 只用于**同样适用**经验的排序，不抵消不匹配；允许 `[]`，不为填满名额选择经验。
- 保持当前输出 schema `{selected_experience_ids: [...]}` 与 0–5 条上限，先不新增每条经验的一次额外 LLM 请求；选错与漏选同时测量，避免只靠少选换得虚高 precision。
- 在**固定经验池、固定开发任务**下只改变 Selector 提示词，对照旧提示词的召回后选择结果；固定池试验**不能验证 A 阶段新生成 trigger 的作用**。

### C. Generator 来源必须有实质贡献

- 更新 [初始 Rubric 生成](../设计方案/03-初始Rubric生成.md)的拟议说明及 `verge/prompts.py`：先根据 task 确定要求，再使用真正适用的所选经验补充/改变标准；task 自身足以产生的标准填 `source_experiences: []`，未实际使用的已选经验不得挂名。保留合法 ID 的现有确定性校验，不假装它能证明语义来源正确。
- 用成对的 task-only 与 task+experience 离线生成、人工来源审查来衡量误标和真实贡献；禁止利用 chosen/rejected 给 Generator 做来源判断。对 `2602` 类“直接回答”标准增加语义回归案例。
- 只有训练中真实生成的有来源标准才进入现有 downstream credit；**本阶段不修改信用公式**。如果语义误标仍明显，再另立来源审计或信用消融，不先上未经验证的自动信用过滤。

### D. 串联验证，不混淆来源与结果

- 单独比较 A、B、C 每步的开发集指标与成本，最后从**空经验池**按同一训练协议跑基线和完整方案，并在新 held-out 上比较初始判别；配置、数据版本、seed、prompt 版本、运行目录与模型请求均需留痕。不同经验池下的变化不能单独归因于 Selector；报告各阶段选择、引用、来源、Judge 指标及配对差异，而不只报告准确率。
- 在样本量允许时重复运行/报告置信区间，记录质量—成本权衡。失败或无提升同样记录；不因个别负方向标准断言负迁移，应核查任务适用性、Judge 判断与偏好标签的关系。

## 4. 实现边界、验收与后续

- **先改权威设计，再改代码**：A/B/C 获确认后先更新第 02/03/08/09 节设计文档和总览的中文输出约束；真实后端不做语言校验的边界同步到 `docs/工程设计.md`。若后续改变配置、数据结构或运行产物，仍须先更新工程设计。`PLAN.md` 将 12 列为进行中，D 未完成前不能勾选为全部完成。
- **测试验收**：现有离线测试全部通过；新增 Fake backend 的 Reflection/Admission、Selector 空集/不匹配、Generator 来源约束与偏好隔离用例；保留旧行为的必要兼容测试。涉及真实模型时记录原始请求量、token 与失败重试，不把日志 token 当作金额。
- **评估验收**：发表人工标注口径与分歧、新开发集上每一阶段的适用/漏选/来源指标，以及冻结新测试集上的配对判别结果；事先设定有意义的改善目标和可接受的成本，再看终测。若仅减少选择次数却大幅漏掉有用经验，或来源误标减少但判别退化，不宣称成功。
- **暂不处理**：信度的置信区间/证据独立性、向量池大于 TopL 时的漏召、gold 噪声处理、并行与旧运行断点恢复。它们属于后续议题；测试时保持训练写回、测试冻结和事前不可见 preference pair 的现有隔离边界。
