> 状态：**25 条轨迹的子代理初步诊断完成；第二次修订输入的完整轨迹透传已实现，首次 v8 真模型运行因 Executor 操作冲突中断；失败降级已修复，完整重跑与人工复核待开展**。初步证据和逐例表见[实验 12 修订失败诊断](../实验分析/12-Chat-Hard-v6-修订失败诊断.md)。本计划记录诊断、已选定的第二次修订上下文改动及后续验证顺序；不预设“改提示词”就是全部解法。以[失败修订](../历史设计/2026-10-24-V1/设计方案/06-失败修订.md)、[原子操作修订](../历史设计/2026-10-24-V1/设计方案/07-原子操作修订.md)和[训练流程](../历史设计/2026-10-24-V1/设计方案/12-训练流程.md)为权威方法定义；若诊断后要改变修订流程，先更新方法/工程设计，再实施。

## 1. 背景与范围

阶段 12 v6 A/B/C 同源回归使用固定的 144 条训练、60 条测试。训练中 104 条初始成功；40 条初始失败，经最多两次同基线修订仅 15 条成功（13 条第一次、2 条第二次），25 条最终失败；31 条候选仅 4 条经 Admission 入池。修订输出没有无效尝试，故不应把低成功率直接归因于格式错误。历史 v5 回归的初始失败后修订成功为 21/35；两次运行的初始失败样本集合不同、模型输出也会波动，不能仅凭 60% 与 37.5% 的差异断言提示词退化。

阶段 12 的 A/B/C 与独立开发/终测尚待评估；计划 13 是诊断工作，不替代[阶段 12](12-经验适用性与来源归因改进.md)的无偏效果验证。已反复查看的 60 条测试不作为新方法的终测。新加的 Admission 理由从 prompt v7 起记录，**不能追溯解释 v6 的 27 条 FAIL**。

## 2. 第一阶段：逐例审计 25 条最终失败轨迹

- 数据：`runs/rewardbench-chat-hard-qwen-vector-144x60-v6-abc/artifacts/trajectories.jsonl` 中训练前 144 条且 `state == "final_failure"` 的 25 条；只读加载，不修改经验池/原始轨迹。检查对应配置 `configs/rewardbench-chat-hard-qwen-vector-144x60-v6.yaml` 与 run manifest。可用历史 `runs/rewardbench-chat-hard-qwen-vector-144x60-resume1/` 作为同样本对照，不把跨运行差异自动归因于某个提示词。
- 每个样本记录：sample ID、子集、task 摘要、`R0/R1/R2` margin 与分项 Boolean/权重、Critic 1/2 的具体反馈、两次 operations 的类型与目标、是否重复第一次无效方向、Judge 是否把目标标准判反、何处未能区分 chosen/rejected、证据字段路径；涉及偏好文本只为离线诊断使用，不写进经验或未来 task-only 选择器。
- 标注可并存的故障类型：R0 标准/权重偏离任务，Critic 漏诊或诊断错误，Generator 未落实反馈/第二次重复错误、操作引入相反效应，Judge 单条判断可疑，任务/偏好标签歧义，边界不确定。逐例写“证据—推断—存疑”，不把 margin≤0 自动判为某一模块故障；主因无法判定时明确标记未定。
- 汇总：各类数量和交叉、两次 margin 的配对变化、第一次和第二次的成功率及成本；任选 5–10 条代表性失败和部分成功对照，至少覆盖历史成功而 v6 失败的同 ID 样本；敏感字段只在本地被忽略的 `runs/` 留存，提交的报告只放脱敏摘要与样本 ID。
- 子代理的主观标注不是人工真值。先抽样人工复核证据与疑似 Judge 误判；有争议标“不确定”，不可由一次模型审阅推导整体错误率。

## 3. 第二阶段：依诊断结果选择最小改动

1. **修订内容问题占主导时**：先在固定失败集上对 Critic 的反馈是否具体指向未区分标准、Revision Generator 是否落实反馈做成对复核；只改占主导的一处提示词，并冻结其他角色、数据和模型。特别核查第二次尝试以 `R0` 为基线，Critic 可见首次失败；不要未经设计审查改成从 `R1` 连续修订。
2. **Judge 不稳定/偏好歧义占主导时**：抽样盲审对应 criteria×chosen/rejected 的 Boolean 判断和任务约束，必要时先改 Judge 评估协议或澄清标签，不能只通过增加修订次数追逐噪声。
3. **修订虽有效但没有产出可迁移经验时**：拆开统计 Reflection 0–3 的候选率、binding/credit、Admission PASS/FAIL 与理由；独立审计具体任务词过拟合、事后 trigger、及误拒真阳性，不为了扩大池盲目降低准入门槛。
4. **Selector/Generator 导致 R0 不稳时**：先在相同样本的 task-only 与固定池条件下做对照，确认问题出在经验选择/来源还是基本 rubric；不要同时调整 A/B/C 和修订提示词。

### 已选定的第一处单点改动：第二次修订上下文

- 第二次 Revision Generator 原来只收到 task、R0、Critic 2 的文本反馈和尝试编号，无法直接核对第一次 operations/R1/Judge。现在补充 chosen/rejected、初始逐项判断、第一次 Critic 反馈/已执行操作/R1/Judge/校验记录；若首次尝试因 Executor 操作校验失败最终无有效 R1，只传其反馈和校验摘要。第一次生成输入与 Selector/Initial Generator 的偏好隔离不变。
- 明确第二次仍对 R0 一次性提出**完整操作集**：第一次的操作不自动继承，有用的修改必须重新提出。只传修订相关轨迹，不传召回、信用与经验池。不允许把当前偏好对的专有事实写入可迁移标准。
- 这是上下文可见性修复，**还未证明修订成功率会提升**；增加 token 成本和针对训练偏好过拟合的风险。下一步需用固定开发集对照原始输入/新输入的配对修订成功率、第二次重复率与成本，同时保持其他角色和评估数据不变。观察 Judge/标签争议时应先人工复核，不把更高的训练配对 margin 当作泛化增益。

### v8 首次运行中断及恢复策略

- `runs/rewardbench-chat-hard-qwen-vector-144x60-v8-history/` 完成 133/144 条训练、0/60 条测试后，在 `rewardbench:llmbar-adver-manual:2924` 的第二次修订中，Executor 连续三次收到冲突操作并抛错终止。该目录是失败产物，不能当作完成实验比较；不能绕过检查点校验拼接剩余样本。
- 依原子操作修订定义，Executor 拒绝的模型输出经有限重试仍无效时应记录 `InvalidRevisionAttempt`，不产生 Rk/Judge/经验；若发生于第一次修订则第二次仍基于 R0，若发生于第二次则本样本 `final_failure`。Generator 契约与后端异常仍中止，避免掩盖系统错误。
- `configs/rewardbench-chat-hard-qwen-vector-144x60-v8-executor-recovery.yaml` 使用相同划分、参数与 v8 提示词，从空池写入新目录完整重跑；它与原 v8 不仅有随机模型输出差别，还包含执行失败处理修复，不能把结果差异全归因于历史透传。该新运行在 50/144 训练轨迹后，下一样本 `rewardbench:llmbar-adver-neighbor:2707` 的第一次修订生成连续三次 `ReadTimeout` 而中断；这是后端故障，不应被伪装成无效修订。
- 第 51 条失败样本已进入 Critic/Generator，但未产生完整轨迹，且 Memory 无该样本的来源或证据；已扩展检查点校验，允许在**无未完成样本写盘且日志仅涉及下一样本**时从该完整前缀续跑，新目录复制校验过的前缀并重做失败样本，不改写源目录。若失败样本已写入 Memory，仍拒绝续跑。网络超时导致的重复调用可能增加费用。第一次续跑在 72/144 后又因 `rewardbench:llmbar-adver-GPTInst:2821` 的 Judge 返回标准 ID 与请求不一致而中断；同样无该样本 Memory 写盘，检查点校验通过后由 `v8-executor-recovery-resume1` 的 72 条完整前缀在 `v8-executor-recovery-resume2` 新目录重做第 73 条。此错误不应伪装成 Judge 成功或无效修订。

## 4. 验收和决策门槛
