# 计划 15：Chat Hard 全量在线经验演化实验

> 状态：主实验与 baseline 均完成 456 条，已完成配对比较和初步演化分析；224 项离线测试通过，改动尚未提交。基线代码：`430899b`。
> 方法沿用现有[设计方案](../历史设计/2026-10-24-V1/设计方案.md)，不改变信用、准入和融合规则。

## 1. 实验设置

- 使用固定版本 RewardBench 的全部六个 Chat Hard 子集，核实实际总数，不再每子集截取 34 条。
- 全部作为训练集，不设测试集；seed=42 全局打散，从空经验池顺序遍历一次。
- 保留合法同题记录，不新增内容去重；重复源 ID 或非法数据报错。
- 沿用 Qwen3.5-flash、1024 维 embedding、top_l=20、最多选 5 条经验、两次同 R0 修订、结构错误额外重试 2 次。
- 使用独立数据、配置和运行目录，不覆盖阶段 14 产物；保存数据来源、顺序、哈希和代码版本。

## 2. Web 运行概览

| 关注点 | 展示指标 |
|---|---|
| 首次正确率是否上升 | 累计、最近 50 条滑动、每 50 条分段正确率；各段子集构成；Judge 错误数 |
| 经验是否积累和合并 | 池大小曲线、候选→绑定→准入漏斗、ADD/MERGE 数及合并率、合并事件详情 |
| 置信度是否反映有效性 | 使用前 confidence 分桶与后续正/负/零 downstream credit；证据量、使用次数和异常案例 |
| 池变大后检索是否有效 | 按池大小分桶的召回→选中→引用及请求/token 成本 |

口径：

- 首次正确率只统计初始 rubric，不包含修订成功；展示有效 Judge 分母，错误单独列出。
- 合并率为 `MERGE / (ADD + MERGE)`；区分同任务内与跨任务合并。MERGE 保留 canonical 文本，并非重写综合经验。
- 用**使用前**的置信度观察后续反馈，避免循环验证；confidence 是证据分数，不是已校准概率。
- 引用率不是检索准确率或召回率；池未超过 top_l 时不能说明大池检索有效。
- 没有数据、窗口不足或旧日志缺字段时明确标记，不补造指标。

## 3. 实施顺序

### A. 主实验启动前

1. 增加全量 train-only 数据准备、配置与 provenance 校验，保留旧 train/test 模式。
2. 从现有轨迹、memory 的 evidence_history 和请求日志重建指标，不新增独立演化日志；检索耗时和相似度本轮暂不做。
3. 将上表指标加入只读 Web 概览，支持运行中刷新、train-only 和旧运行。
4. 完成离线测试及浏览器检查，核实数据总数、估算费用；经用户确认后启动新实验。

重建按任务顺序，在使用前重放 Beta 证据；零信用从初始 rubric 和 Judge 复算。缺失轨迹、部分写入或证据不一致须显示警告；当前磁盘 memory 与完整轨迹前缀不一致时不能混为一条池曲线。

### B. 主实验启动后

编写独立无经验 baseline：同一任务和模型设置，仅 `task → Initial Generator → Judge`，不修订、不写经验池。先完成离线测试；另经确认才启动真实请求，默认不与主实验抢额度，不修改主运行配置或产物，不绕过续跑代码指纹校验。

### C. 实验结束后

核对完整性，汇总趋势、合并案例、置信度关联、检索规模指标及成本。后续 baseline 按 sample_id 配对比较首次结果；检索漏检和合并收益的专门审查/消融另行安排。

## 4. 验收与解释边界

- 测试覆盖：全量且无 test、顺序确定、旧模式兼容；使用前状态正确；ADD/MERGE 与指标分母可复算；空桶、Judge 错误、日志不完整和续跑处理。
- `python3 -m pytest -q`、`git diff --check` 通过；浏览器检查空运行、运行中、完整 train-only 和旧 train/test 概览。
- 这是在线演化观察，不是独立泛化评估。曲线上升或出现 MERGE 不直接证明因果收益；若无上升、无合并或池仍很小，也如实报告，不为获得预期曲线运行中改规则。

实施记录：全量数据为 **456 条**（37/100/134/92/47/46），合法同题重复 1 条，保留。固定数据已制备并通过 provenance/哈希校验。运行配置为 `configs/rewardbench-chat-hard-qwen-vector-full-train.yaml`。以阶段 14 训练的 770 次请求、603,740 已报告 token 外推，约 2,440 次请求、191 万 token；预算可先按 2,000–3,500 次请求、150–300 万 token 留余量，非硬上限，池规模/重试可能继续推高；金额以实际账户计价为准。之后经用户确认已启动主实验（后台任务 `ba2d3027c`），未重启或修改其配置/产物。启动后实现 `verge/baseline.py`：仅两个模型角色、独立目录和请求日志；无经验更新、修订或 embedding 调用。配对比较按 sample_id 使用双方有效初始 Judge，支持每 50 条分段、子集统计及未完成标记。Fake 与模拟 HTTP 测试覆盖隔离、编号、重试耗尽、网络错误和数据来源校验。baseline 真实请求仍待另行确认；新源码会改变后续续跑指纹，不绕过严格校验。

容错与续跑：首运行在第 35 条的 Critic 第二轮格式纠错耗尽后停止，完整轨迹 34 条、池大小 2，失败样本无 memory 写入。新增仅针对 Critic 的格式耗尽容错：记录无效修订，analysis 无合法值则为 null，不叠加操作重试，不伪造判定；网络/鉴权仍中止。224 项测试通过，完整恢复校验通过后复制前缀到 `runs/rewardbench-chat-hard-qwen-vector-full-train-resume1/`，后台任务 `b7e1aa791` 从第 35 条重新处理。保留原目录与初始生成重试设置（0）；配置、数据及提示词协议一致，新旧源码指纹由 manifest 真实记录。新增的 baseline 文件不禁止源码修复续跑，实际恢复策略要求协议兼容而非源码指纹完全相等。

结果：主实验首次正确 327/456（71.71%），baseline 326/456（71.49%）；配对净差 +1 条。修订修复 78/129，ADD 21、MERGE 4，最终池 21。初步分析见[实验分析 15](../实验分析/15-Chat-Hard-全量在线经验演化实验.md)，语义复核及大池检索审查仍待后续安排。
