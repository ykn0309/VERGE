# 计划 16：角色专属提示词与自然语言输入

> 状态：实现完成；完整离线测试 262 项通过，`git diff --check` 通过。未发起真实模型请求，不修改历史产物；本次及上一阶段实现尚未提交。

## 目标

为八个 LLM 角色分别提供有明确职责、证据边界、判断步骤的 system prompt。模型输入改为带字段解释的自然语言分节，输出仍为 JSON，保留数字 ID 和现有结构校验。

## 改动

1. 改 `verge/prompts.py`：专属 system；自然语言 user；提示词版本升级，禁止旧检查点跨提示词版本续跑。
2. 保留其余角色的 payload 投影、credit/融合公式和输出 schema；Initial Generator、Reflector 和 Critic 只返回内容字段，由系统按列表顺序分配新增对象编号；Critic 的 MODIFY/DELETE 使用已有标准引用，Judge 每次接收单份 response，系统并行调用两次再合并 Boolean 判断；Admission 采用任务与候选文本投影，不向 task-only 角色增加回答信息。
3. Admission 明确：可以理解 task 语义；信任上一步操作绑定，不重复审核操作支撑，输入仅保留 task 与候选 ID/content/trigger，不发送操作、信用和修订轨迹；拒绝理由引用候选本身，不能把 task/rubric 内容算作候选泄漏。Reflector 明确生成 rubric 方法，不复述响应要求或事后条件。
4. 说明 task、chosen/rejected、经验、rubric、操作前后、权重、margin、置信度及历史失败各自的含义；空数据和缺失判断明示，不用整块输入 JSON。
5. 输入文本是待分析数据，不是新指令；输出协议明确字段含义；已有对象引用与枚举保持原规则，生成标准、候选和操作的编号由系统负责。共用语言/JSON 协议可保留，不能代替角色职责。

提示词采用正向的角色身份、任务、字段含义及输出要求，移除反向禁止措辞和具体案例；保留方法条件、JSON 协议及代码校验。
