# 经验文本融合与弱修订证据

## 已确认决策

- MERGE 不再仅限全文语义等价，允许同一核心评价设计机制的兼容扩展；冲突或无关机制仍 ADD。
- Fusion 只看候选及召回经验的 content/trigger，一次返回匹配位置和融合后的完整 content/trigger。不让 LLM 计算信用。
- trigger 必须仅凭未来 task 核验；扩展机制需明确适用条件，不将局部规则无条件推广。
- ADD/MERGE 一致追加弱修订证据：`credit = 0.25 * min(1, M(R_success) - M(R_previous_valid))`，`evidence_weight=1`。第二轮用最近有效 R1 而非 R0；第一轮无效则用 R0。
- 新增 `fusion_credit` 证据类型，与下游证据及历史原子修订信用分开；正信用增加 alpha，beta 不变，confidence 派生计算。
- MERGE 继承旧 Beta/证据，但旧证据不证明新扩展有效；保存文本版本与来源，后续 R0 信用继续更新。
- 候选仍 0–1 条，无原子操作/绑定/操作信用分配。不恢复旧操作模块。
- 旧运行只读保留，不能跨方法续跑；新配置新输出目录，不运行真实实验。

## 验收范围

离线覆盖结构协议与消息边界、完整文本融合、ADD/MERGE 证据一致、第二轮信用基线、拒绝/无效融合不记账、存储快照及旧日志兼容、Web 版本/文本历史与信用区分。保留既有前端样本预览改动。

## 风险

margin 增益是弱关联证据，不是候选机制的因果贡献。重复发现可增加正证据；扩展继承历史信用存在版本偏差。当前仍不承诺跨文件事务式恢复，不修复旧实验部分记账。
