# 经验定义对齐与任务目标优先

## 范围与决策

本轮仅调整角色提示词及对应文档/离线契约测试，保留计划21的文本融合、弱修订证据及前端改动。不新增审核阶段、内容门禁、角色输入、数据字段或真实请求。

- Reflector、Admission、Fusion 共用 rubric-generation experience 定义：具体可复用的标准设计机制，允许设计评价维度、安排标准重要性和排除不当要求；既非完整 rubric，也非回答生成指南。
- 条件迁移仅要求满足 trigger 的同类任务间复用，任务类别有限、需要语义理解或机制具体不单独构成拒绝理由。
- trigger 的全部条件仅凭未来 task 核验，并应支持 content 的适用范围与指导强度；目标和明确约束优先于经验规则。
- 单一机制可有协同动作；只有可独立使用且触发条件不同的多条原则应拆开。
- Admission 审核可用经验表达及明显边界缺陷，不提前证明实际有效性；PASS 不等于有效，修订成功与信用分数不替代下游验证。拒绝理由须引用候选文本并定位具体缺陷，不仅写“太具体/非通用”。
- Fusion 在兼容扩展时保持同样的任务目标、条件边界及指导强度约束，不将条件分支写成全局强制规则，不重新调用 Admission。
- Selector 先区分指令要求执行的操作与材料主题，再核验机制适用性；材料主题相似本身不足以选中。
- Generator 先按任务目标和明确约束决定标准及重要性，按条件使用经验，不将材料中的操作要求变成回答必须执行的动作；经验与任务冲突时以任务为准。

### 共享定义精简

共享定义压缩为三句（不足200字符）：机制与协同动作、content/trigger及任务约束、条件迁移与效果边界。允许的设计动作和误拒防范留在Admission专项提示词中，不向所有经验角色重复注入审核细则。新版为 `generator-dialogue-task-grounded-experience-compact`，旧任务目标版本仍只读兼容，不跨版本续跑。完整离线测试355项通过，未发起真实请求。

### 首次生成与触发条件澄清

共享定义明确经验服务于首次生成；content 说明如何设计评价标准，而非修订既有标准；trigger 定义为经验的触发条件或使用场景，task-only 是其核验边界。Reflector 的修订轨迹只作为提炼证据，正文改为构造标准和安排重要性。实际 Critic/Generator 修订流程、信用公式及候选协议不变。提示词版本为 `generator-dialogue-initial-design-experience`，旧compact版本仍只读兼容。
