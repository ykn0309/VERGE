# 事前经验与保守融合

## 实验依据

只读复核 `generator-dialogue-concise-revision-feedback` 的30条运行：8条候选、4 PASS/4 FAIL、1 ADD/3 MERGE，经验池最终1条。核对实际 role_io、轨迹及融合历史，文本与裁决一致，非展示或存储拼接错误。

- 2857：Admission 把判断输入缺失误读为禁止的二次推断；2818：把合法维度/权重设计误读为评分操作，但原文也含不支持的否决规则，不能简单将所有FAIL改成PASS。
- 2501、2769、2530：PASS候选的trigger分别依赖既有标准/Judge、已出现占位符回答、既有标准与得分。2501的成功margin 0.1579全部来自可读性标准，事实维度贡献均为0；反思却主要归纳为事实准确性。
- 3次MERGE将事实/可读性、成品完整度、术语门槛及能力诚实拼接。content从134增至545字符，trigger从74增至196字符。最后新增能力边界是不同设计问题。
- 信用是弱关联证据，不能替代适用条件审核或认证扩展文本；本轮不改信用公式、不推断因果贡献。

## 决策与范围

1. **Reflector**：对照实际修订前后标准及两侧判断，Critic叙事仅作参考；将事后诊断转为首次生成前可使用的设计指导和场景，不复述样本答案或偏好身份。允许多个协同动作，仍返回0–1候选。
2. **Admission**：删除“仅凭未来task核验”和“单一设计机制”，允许任务语义、输入完整性、上下文和领域知识推理。审核具体、连贯、可复用指导及明确缺陷；区别content评价未来回答性质与trigger依赖已出现回答性质。复杂/具体不是拒绝理由，不把评分维度和重要性设计视为非法产物。
3. **Fusion**：默认ADD；仅对同一设计问题、等价指导或同一方法必要细化、且条件兼容的经验MERGE。去重提炼，不以主题/质量目标相似为由串接，不为压缩经验池而合并。不确定、无关场景或必须修复事后条件才能合并时ADD。长度是诊断信号，不增加字符阈值。
4. **Selector/Generator**：简短补充合理任务推理、实际输入完整性与任务约束优先，不恢复旧长篇共享定义或通用输出协议。

只调整角色提示词及离线契约/对照材料。保留7角色、现有JSON字段、公开反馈、两轮最近有效基线、0–1候选、Beta公式和存储逻辑。不新增语义审计门禁、融合后的Admission调用、原子操作绑定或信用方案，不自动修复旧池。

## 语义对照集与验收边界

`tests/fixtures/prospective_experience_cases.json` 固定本次8条原候选及人工审核意见，增加5条事前/复杂协同指导正例和6对融合正反例。原文有缺陷与可保留核心分别说明；原2857预期PASS，2501等事后条件预期FAIL，多个协同动作不因复杂拒绝。能力边界例以当前无提醒工具的文本模型为前提，不推广到有执行工具的助手。

pytest检查实际system契约、输入隔离、字段/版本、候选文本保留及Mock HTTP传输；模拟裁决由测试桩预设，不能证明真实模型遵循上述语义标签。对照集来自开发/诊断样本，不是held-out，不作为泛化指标。同步旧提示词措辞测试为当前设计意图，不通过塞回旧措辞或跳过失败来追求全绿。

后续若获授权，先对冻结候选/经验对执行小规模真实语义复核，观察误拒、漏放、错误合并和文本去重；再从空池在新目录运行同序30条。经验池条数或准入率上升不单独作为成功指标，初始判别需独立对照/重复验证。
