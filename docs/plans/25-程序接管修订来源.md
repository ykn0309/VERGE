# 程序接管修订来源

## 授权与目标

用户确认修订来源由程序接管。修复计划24中2559/2812复制历史编号导致的 `unknown numbered experience`，不依赖模型纠错，不增加重试、角色或审核调用。

## 实现边界

- 仅当可信调用payload标记Generator修订轮时生效，不从模型输出判断模式。
- 仍保留原JSON字段和基本类型要求；修订输出的source_experiences须为字符串数组（HTTP正整数ID仍由既有backend规范化）。在编号反解之前，程序在返回值副本上统一置为[]，不反解这些无用途的来源值。
- R0来源继续严格反解/白名单检查；Selector/Judge等其他编号检查不放宽。问题、分数、标准数量、缺字段、类型错误、多余字段等既有校验保持不变。
- 同时覆盖HTTP数字协议与Fake/自定义内部ID协议。保留backend原始回复、解析输出和真实assistant历史；轨迹的修订Rubric存程序规范化结果，两者不是同一个审计层。
- 不变更信用公式、最近有效基线或反馈；修订Rubric不计算已有经验下游信用。规范化来源不使判别自动成功。按用户补充要求，system/user均不告诉Generator“修订来源由程序置空”，删除原要求模型修订时返回空来源的句子。
