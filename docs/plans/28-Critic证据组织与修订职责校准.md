# Critic证据组织与修订职责校准

## 授权与范围

用户基于计划27诊断，授权实现输入组织与提示词改善的第一阶段（此前建议1–5）。不改模型、数据、Judge、评分/信用公式、经验链角色、两轮上限、语义门禁或字段协议；不启动真实实验、不提交/push。不实现逐项贡献展示、temperature配置或耗时统计（此前建议6–7）。

## 输入组织

Critic第一轮看任务、偏好对、即将执行的轮次、当前有效基线R0与标准/逐项判断/得分。第二轮有有效R1时只看上一轮修改前标准/判断/得分、上一轮公开建议以及当前有效R1标准/判断/得分，各版本只展示一次。去掉重复的上一轮修改后副本和上一轮私有analysis，避免错误叙事锚定。

上一轮无效时基线仍R0，只附尝试轮次、校验失败摘要及“未形成有效修订，无Judge结果”，不附无效rubric、分析或公开建议，不伪造判断。完整私有分析、公开建议、校验失败及实际回复仍按原契约存储于轨迹/role_io；Reflector既有投影保持不变。数字编号仍由已有codec按本次输入生成，不按位置匹配前后标准或假定新ID等于新内容。

## 角色职责

- Critic先核对标准/回答/判断与实际前后变化，分清有依据的标准缺陷、Judge疑点和证据不足；判别失败本身不证明标准有错。旧公开建议只是待核验意图，不是完成情况或正确性的证据。
- 仅建议调整问题与重要性；评价是归一化重要性加权Boolean，不支持部分分、一票否决、不适用项自动排除，不要求每条都区分两侧。
- 新增要求须有任务/上下文/合理领域推理依据，严格/详细不自动等于改进。不为偏好分差放宽任务约束，重要性表示任务重要程度。
- 公开建议自然说明哪个评价要求有问题、如何调整及任务依据；允许task本身提供的信息和独立领域知识，不包含候选特有细节、偏好身份、评分或比较评价。无可靠修改依据可建议保留合理标准，仍返回非空两字段，不新增跳过修订分支。
- Generator结合任务判断公开建议是否适用，任务目标与明确约束优先于经验和建议；保留合理标准，仅调整有依据的问题，在原analysis中简述关键调整依据。仍输出完整rubric、不恢复原子操作或额外角色。

system保持角色局部精简，输出要求仅在_ROLE_INSTRUCTIONS；修订user沿用简短失败/建议/重新生成请求，不重复schema，不说明内部来源清空。
