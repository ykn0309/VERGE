# 经验实例抽象：Critic、Admission与Fusion提示词重写

## 1. 授权与范围

依据[计划35诊断](35-候选经验任务实例残留与泛化原因复核.md)，用户同意修改提示词，并明确要求整体重写、融入新要求、处理旧要求冲突，不在原提示词后追加约束。本阶段已完成三角色职责重写及相关方法文档同步。

实现集中在`verge/prompts.py`的Critic、Admission、Fusion专属职责；其JSON输出协议、消息投影、编号、应用预算、角色数量、准入重生成、独立应用、来源白名单、信用及Memory写入机制保持既有契约。Generator、Selector和Judge职责未改。没有增加共享定义、输出块、审核角色或关键词过滤器。

## 2. 三角色的统一边界

| 角色 | 重写后的职责 | 处理的旧缺口 |
|---|---|---|
| Critic | 私有analysis诊断当前task与回答；公开content写核验性质、评价维度及重要性安排，trigger写生成前能识别的语义条件。将本题特有的实体、数量、时长与措辞转为语义角色或由新task提供的参数 | 旧提示词强调具体方法，只禁止回答特有细节，未要求抽象task实例，容易把原题诊断或回答方案写进经验 |
| Admission | 检查公开方法是否明确、content/trigger范围是否一致、可变参数是否被本题常量固化；允许必要任务类型、领域知识及同一目的的协同动作 | 旧“具体/限定任务类型不能拒绝”没有区分合理专业方法与样本绑定；只称“不通用”也无法定位缺陷 |
| Fusion | 只合并同一设计问题的等价指导或必要细化，统一方法与必要条件，不拼接题内例子、答案对照或不同方法 | 旧去重要求未规定实例抽象层级，MERGE容易积累题内对照；Fusion不应补做准入或成功后清理 |

公开content/trigger直接表达方法与条件，不举例、不复述本题答案或提供回答方案；具体实例留在私有analysis。必要任务类型和领域边界可直接表达，不因专业术语或领域知识而要求跨所有领域通用。应随新task变化的参数由新task提供，固定专业规则不能与本题常量混淆。

适用条件支持任务、实际输入、上下文及领域知识推理；不要求task逐字声明，不用关键词匹配代替语义识别。content可以指导核验未来回答，trigger不能依赖已观察到的回答特征、现有评分标准或Judge结果。

## 3. 保留的判断与证据边界

- 判别失败不证明评分标准有错，Critic仍须区分设计缺陷、Judge疑点与证据不足；无可信可复用方法返回空候选。后续轮使用真实生成与采用记录，拒绝重生成针对实际reason，不沿用旧私有叙事。
- task目标与明确约束优先，不为偏好分差放宽要求、添加无依据门槛或把加严/增细节当作改进；禁止偏好身份、私有评分和比较结论进入公开候选。
- 不要求部分分、否决、自动跳过或修改已有Judge状态。没有新增自动语义门禁。
- Admission PASS只允许原文试用，不改写候选，不认证迁移效果。理由定位实际content/trigger中的缺陷及需抽象的细节或缺失边界。
- Fusion保守匹配；若合并须修复原文准入缺陷、拼接不同方法或扩展无关场景，返回空匹配。ADD继续使用实际应用候选原文；MERGE保留既有版本与信用边界，历史证据不认证新增内容。

抽象在Critic提出、Admission通过之前完成；不会成功后另写一条未经实际应用的经验替换候选。

## 5. 人工核对示例

| 类型 | 当前要求 |
|---|---|
| 原题橱窗灯/电视与庭院加热器对照 | 公开经验改成核验任务指定主体与回答主体一致性，原题实体只留在analysis |
| 原题10秒、25词、4句 | 指导依据task提供的时长设置评价，不把同一组预算用于所有短脚本 |
| trigger涵盖多个领域，content强制NLP | 拒绝范围错配；合理限定NLP领域的方法仍可成立 |
| 指定长度单词任务 | 用task指定字母数核验，不固化原题8字母；仍可保留必要的字母计数规则 |
| 多动作同一目的或专业领域经验 | 保留协同动作和必要边界，不能仅因具体或专业拒绝；指导仍须明确，不能退化成质量口号 |

这些用于审阅提示词覆盖范围，不是新增真实模型结果。
