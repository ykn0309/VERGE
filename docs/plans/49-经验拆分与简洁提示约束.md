# 计划49：经验拆分与简洁提示约束

2026-10-12实施，覆盖计划48的一条经验归纳输出；候选延迟入池、固定E与R0信用流程不变。

## 已确认规则

- 归纳员读取当前经验及全部有限正向案例卡片，返回保持/更新一条或拆成两条，每条包含content、trigger、sample_ids。最多两条，每组非空，可只有一个样本；所有案例恰好归属一次。
- content≤150字符、trigger≤60字符仅写入提示词，不程序计数、不截断、不因超长纠错。未新增“允许替换、删除、重组原文”等额外要求。
- 只在新案例收录后的原有归纳调用中判断拆分，不新增模型调用。第10条案例最后一次调用可拆分；未拆分则冻结，第11条起不再归纳或拆分。
- 拆分产生两个新ID，父经验退役但完整历史保留，退出检索及信用/文本写入。每个子经验按分配案例数计算自己的10条容量，可继续收录、归纳和拆分。
- 子经验保留案例当时真实source_id、content/trigger、text_version和Judge，不篡改为新子经验曾经被验证；新文本版本从1开始。

## 信用计算

父经验累计P=alpha−1、N=beta−1，全部归纳案例中的P总和为P_cases。子经验j分到m_j个案例，父经验共有m个案例：

```text
P_j = 该组案例P之和 + (P − P_cases) × m_j/m
N_j = N × m_j/m
alpha_j = 1 + P_j
beta_j = 1 + N_j
```

全部历史N只按案例数量分配一次，不再另加案例内的N；剩余P包括未收录案例的正向信用和前次拆分的剩余继承P。每次拆分P/N总量守恒，Beta先验各自为(1,1)。未要求模型分配具体负样本。

子经验inherited_credit明确记录父ID、案例P、剩余继承P和继承N，不写伪造样本证据；子经验evidence_history只保存拆分后实际使用证据。父经验原始信用记录继续供审计。
