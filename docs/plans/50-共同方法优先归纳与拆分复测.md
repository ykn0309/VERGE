# 计划50：共同方法优先归纳与拆分复测

2026-10-13，用户确认实施提示词优化并用已有27次拆分输入有限复测。

## 范围与规则

- 仅调整ExperienceUpdater职责提示词：从实际核验动作和证据规则寻找共同方法，先尝试一条，再判断是否必须拆分。场景、对象、术语、格式或参数不同本身不构成拆分理由；单条表达会丢失必要边界或只能堆成不同方法列表时才拆，不确定时保持一条。同一核验目的可包含协同动作，不按动作数量机械拆分，也不强造空泛共同原则。
- 引用和局部正信用只是线索。核对任务、标准、回答及Judge理由；仅相关、未落实的方法、明显Judge误判、task无依据的标准不能成为追加规则或拆分的依据。证据不足案例仍保留归属，不自动移除案例、撤销P/N或新增方法。
- 不增加analysis或拆分理由字段，不要求逐项输出核对报告，不增加模型调用。输出仍为experiences/content/trigger/sample_ids。
- 保留最多两条、单案例分组、完整唯一归属、每条10案例冻结、信用继承和有限结构纠错。150/60字符仍只由提示词约束。
- Prompt改为`local-credit-bounded-experience-common-method`以区分真实请求；Manifest6/Memory4/Trajectory6不变，不做旧版本兼容或跨Prompt续跑。

## 有限复测

`scripts/replay_experience_splits.py`读取原100条实验的27份实际归纳输入，并逐一核对原始role_io、父案例顺序和旧输出。保持原输入、Qwen3.5-Flash、enable_thinking:false以及原超时/重试配置，只有归纳提示词改变。

复测每组独立，不把新输出反馈到下一组，不更新原Memory、轨迹、案例或P/N。输入不含旧审查结论；旧27次定性分类只用于结果汇总和复核参照，不视为金标。保持格式/结构有限纠错及网络故障fail-fast，可在新复测目录完成同一次中断复测；固定源文件与提示词哈希，已成功结果不重复调用。

命令：

```sh
/opt/anaconda3/bin/python -m scripts.replay_experience_splits \
  --source-run runs/helpsteer3-general-split-experience-qwen-flash-100-resume3 \
  --output-dir runs/helpsteer3-common-method-replay-27
```

保存每组新旧输出、请求/原始消息/回复、耗时、纠错次数及源文件哈希核验。人工阅读新文本，检查原“无需拆分”案例是否形成有含义的共同方法、原合理差异是否保留、是否丢失明确约束或强化错误事实。不单凭拆分率下降判定改善，不推导整体准确率或下游泛化收益。
