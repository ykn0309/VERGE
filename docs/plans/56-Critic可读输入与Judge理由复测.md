# Critic可读输入与Judge理由复测

用户授权将生产Critic输入改为更易读的版本，并验证Judge理由及标签表达的影响。仅改消息展示，不改角色输出、信用、候选准入或多轮控制。

每条标准先展示问题、权重和来源，再分别展示两回答的Judge判定及解释；完整任务、回答与理由原文保留。二轮仍保留真实assistant消息，追加本轮反馈。Prompt更新为`local-credit-bounded-experience-critic-readable`。

独立复测使用原100样本运行的Critic trace 163、167、724、4、390、281，共6条输入、5个任务。其中167保留实际首轮assistant；新增281作为另一故事任务对照，其历史诊断也不是金标准。

固定Qwen3.5-Flash、关闭思考；6个版本共36份输出，每份沿用backend最多3次有限格式/传输尝试，不另增语义纠错调用。只比较：

- Judge解释放在每侧判定之后、放在同标准的独立解释区、完全不提供（仅诊断对照）。
- 在同样可读布局及完整理由上做2×2标签对照：优选/非优选或A/B，满足/未满足或true/false。

所有版本使用相同映射说明，避免某版本额外获得核对指令；任务与回答原文不做全局替换。输入、源码指纹、配置、原始请求/回复、错误与新旧输出另存`runs/critic-readable-input-replay/`，原运行manifest/日志/Memory/轨迹哈希须不变。

人工复核关注：判定方向和回答归属、标准缺陷与Judge误判的区分、无依据规则及正常行为是否退化。不能以候选数量或空候选判定优劣；一条输入每版本仅一次生成，结果只说明局部表现，不证明内部原因、稳定性或全链路收益。生产可读布局按用户要求生效，标签和理由保留方式根据证据决定，不默认删理由。

实现：`verge/prompts.py`、`scripts/replay_critic_readable_inputs.py`；输入关联及历史保留测试随同运行。

完成：36份结构有效输出/37请求（1次相同消息超时恢复，零格式/结构纠错），301项测试通过，原产物及测试代码指纹核验通过。理由删除或分离均未稳定改善；A/B部分案例改善，true/false与组合没有一致优势，生产仅上线可读布局、保留中文标签及完整理由。详见[复测简报](../实验分析/历史运行归档/critic-readable-input-replay/实验简报.md)。
