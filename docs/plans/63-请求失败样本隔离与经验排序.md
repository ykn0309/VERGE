# 63 — 请求失败样本隔离与经验排序

用户要求单个样本用尽有限重试后记录并跳过，无需重启整个实验；经验页面支持置信度与引用次数排序。

上次200题多次中断的直接原因是请求超时在后端重试耗尽后抛出全局错误，而非样本隔离。配置为单次120秒、最多3次请求；第25/46/168题的恢复经过见[实验记录](../实验分析/62-新版200样本完整链路实验.md)。第168题中断发生在R0记账之后、轨迹写入之前，造成需要独立检查点修复的未完成信用；不能据此断言是沙盒引起超时。

## 实现

- 增加LLMSampleError：超时/连接失败、408/429/5xx仍按原max_retries有限重试，耗尽后隔离当前样本；400/413/422视为当前请求输入被拒绝，直接隔离。Embedding适用同一边界，非法向量回复也隔离；鉴权、其他终止HTTP错误、配置、存储、Calculator和程序错误继续明确中止，不伪装成模型输出失败。
- 样本错误保存阶段、类型、原因及已有过程，停止当前样本的后续提案，不入池候选；有效R0信用保留一次，收录合法案例后写完整轨迹，继续下一题。归纳失败保留旧文本、信用、案例及窗口，记归纳错误后继续；不改变当前样本判断状态。下一新案例仍可按原窗口规则尝试归纳。
- Judge并行两侧同时出错时，鉴权/程序错误优先于可隔离请求错误，后者优先于格式错误；不伪造缺失一侧判断。训练和冻结评价共用样本错误隔离，CLI有序保存并正常统计处理数。
- WebUI经验池增加默认顺序、置信度升/降序、引用次数升/降序；引用次数沿用R0引用该经验的不同样本数，不计仅被Selector选择或R1/R2引用。排序同值按原序，原始索引不变，选中详情、搜索和点击滚动保持正常。候选页不提供池经验排序。

## 验证与边界

用离线HTTP故障注入核验有限预算、错误类型及隐私；按角色阶段注入一次请求失败，确认下一样本运行、有效R0信用/案例/轨迹完整且不重复；核验归纳失败后下一案例可继续归纳、CLI整个数据集继续处理。Node执行真实前端排序和事件，核验升降序、同值、引用口径、原始ID、选中详情、搜索及滚动位置。

本轮代码只实施请求隔离与排序，信用计算尚未改动。讨论中用户已改为：同判不参与归纳、不占10条额度、不计3任务窗口；混合案例的归纳输入仅保留有区分的标准。该部分待可靠性展示/公式讨论完成后一并实现，不能把当前源码的同判25%负信用误读为新决策。区分率若仅在WebUI展示不会影响Selector，是否纳入选择尚未确定。

不重算历史产物、不启动真实实验或重启正式Web服务。此修改不提供跨文件事务、断电或进程被杀的自动恢复；代码变更后不跨版本resume。
