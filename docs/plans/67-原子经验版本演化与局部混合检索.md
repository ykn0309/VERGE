## 1. 变更边界

| 当前实现 | 目标实现 |
|---|---|
| Critic/Updater提示词自行约束原子性 | 独立Atomizer输出原子trigger/content列表 |
| 每题最多一条候选入池 | 每轮原子候选独立引用和信用；最新合格轮的合格集合入池 |
| 同一ID改文本并继承全部信用 | 文本版本固定；修订/拆分生成新ID、Beta(1,1)，旧版退役保留历史 |
| 每3条下游案例归纳，含来源最多10条后冻结 | 每5条新的本版本下游案例，用最近5条归纳，持续演化 |
| 类别名称/描述/成员拼成一个向量 | 类别和成员分别建索引，成员命中映射到类别 |
| 纯向量Top20任务检索 | 向量＋BM25＋RRF，Top20任务单位、Top10归类类别 |
| 全池分类方案同时改名和归属 | 局部归类只改目标归属，独立描述更新只改name/description |

保留P/N算法、同判计次、不向Selector提供区分率、最多两轮Critic与固定E、有限错误隔离。不开新Judge审核、Admission/Fusion或探索名额，不自动清理历史、提交或启动200题完整链路。

方案14中的工程初始参数与边界（例如RRF k=60、分类展示最多3条相关成员、多候选按轮选择、失败窗口重试）须配置化或明确固化并测试，不能在实现时默默改变信用/验证语义。

## 6. 阶段E：局部归类和描述演化

涉及：`verge/models.py`、`verge/prompts.py`、`verge/modules.py`、`verge/memory.py`、`verge/pipeline.py`。

- [x] CategoryOrganizer只接收单个待分类经验及Top10候选摘要/相关成员，输出assign/create/unclassified。
- [x] 待分类队列默认5条触发，同批稳定顺序处理，后项可见前项新类别；收尾处理余量。
- [x] 归属局部提交，dirty类别与成员增删事件持久化；父版本退役也触发原类别dirty或空类删除。
- [x] 新增CategoryDescriber，严格只输出name/description；每批受影响类别最多一次调用。
- [x] 描述失败保留旧描述及已经提交的归属，记录dirty版本和有限重试；不在同批循环重新归类。
- [x] 索引在归属变化后更新映射，在描述更新后刷新类别文档，重启可从Memory重建。

## 8. 独立局部复测与调用预算

离线测试通过后，分别运行模块，不运行整条训练流水线。各案例独立，新输出不反馈到下一案例，不写回源池。可以把真实上游输出作为固定夹具测试下一模块，但标注来源和固定条件，不将其算作端到端收益。

| 模块 | 首轮固定规模与对照 | 重点 |
|---|---|---|
| Atomizer | 候选20＋修订20；原文本/新输出人工对照，共40次有效目标调用 | 独立方法拆解、必要条件、原样保持、无新增规则 |
| Updater | 至少20个独立来源，旧/新提示各20次；输入差异单独记录 | 正负反馈利用、keep、必要边界；不能把输入机制变化归因于提示词 |
| CategoryOrganizer | 20组独立历史来源，旧全池/新局部各20次 | 归类合理性、错误新建、未分类、权限 |
| CategoryDescriber | 20组真实成员变化派生输入，20次 | 名称/描述正确覆盖变化、无成员操作 |
| Selector | 20个不同任务，固定候选集合旧/新表达各20次 | 低证据版本被正确理解、适用性与回归 |
| 检索 | 任务检索20查询＋归类检索20查询，固定快照比较纯向量/混合 | 相关类别/经验覆盖、词法误召回、大小偏差、成本 |

初始有效目标LLM调用预算共180次，检索的Embedding独立计数并缓存；若候选或输入完全相同，已有可复用原始baseline应明确标注而不重复请求。每次请求最多沿用2次格式/结构纠错，网络重试单独按既有配置记录，不追加无限尝试。失败结果保留，不为凑有效数悄悄换题或扩大样本。

源数据不足时先提交可用清单与缺口，不以重复题/少案例冒充20条目标协议输入。Generator、Critic或Judge的提示词若在实现中超出必要的集合接口调整，也须分别新增至少20条独立复测及预算；本计划没有授权无上限增加真实调用。

报告保存独立目录，包含样本选择理由、原输入/转换/新旧输出、代码和提示词指纹、模型/思考设置、真实请求/回复、错误与人工复核表；验证原产物哈希未变。示例若新增须原创，不从数据集改写。
