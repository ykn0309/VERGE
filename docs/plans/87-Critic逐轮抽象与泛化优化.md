# 87 — Critic逐轮抽象与泛化优化

优先改进Critic，不要求单条经验绝对正确，但候选必须适度抽象：不举例、不保留原题专名/数值/原句/剧情及其改名版本，仍表达可落实的核验动作和必要任务边界。analysis可以引用本题证据。其他角色、准入、反馈及数据协议保持现状，不增加生成后过滤或额外审核调用。

每轮沿用计划84冻结的20个不同真实任务（15个初始失败、5个成功边界）；Qwen3.5-Flash关闭思考，案例并发4，网络/格式重试各最多2次。新输出互不反馈，不写原经验池，不跑完整流水线。逐轮保存提示词、原始输入/输出、版本、错误、SHA256与逐题语义审阅；未达标则继续修订。使用独立编写的写法示例时不取材或改写数据集案例。

验收优先级：全部20题候选无举例、无不必要原题残留；非空候选必须保留具体核验方法及合理任务类型，不靠全部不提案过关。逐题记录合理性、原子性及证据问题，不以结构通过冒充内容通过。达到后再用同样20题独立重复一轮，检查是否仍满足；这只能说明本组输入，不保证线上零泄露。
