## 4. 当前方法协议

```text
task → Retrieval / Selector得到固定E
→ Generator(task+E)生成R0 → Judge
→ 由R0实际来源计算已有经验P/N并更新Memory
→ R0成功：结束
→ R0有效失败：最多两轮

每轮：
Critic一次提出0–1条C
  空候选：no_candidate，结束
  有候选：独立Generator(task+原始固定E+当前C) → Judge
    成功且声明采用C：同一候选Fusion，结束
    成功未采用C：任务成功，C不入池，结束
    失败：剩余轮次内提出下一条C
```

业务预算最多两次Critic提案、两次应用。没有同轮Admission拒绝重生成；格式/结构纠错单独有限计数，耗尽消耗本轮机会，不伪造Judge失败或增加业务次数。

Generator每次使用全新消息，只看task和本次可用经验：固定E在前、当前C在后。第二轮只替换C，不积累旧候选、不重新筛选E，不输入旧评分标准、analysis/assistant历史、偏好对、Judge或Critic私有分析。实际消息统一一份“本次可用经验”列表；审计payload分别保留E/C。

C标注“当前候选、尚未验证，无历史置信度”。E/C均自主采用、组合或忽略；来源标注只允许本次E与当前C，R0只允许E。至少一条criterion引用C即adopted=true，这是模型自报。

## 5. 信用、Fusion与错误边界

对标准i，`d_i = chosen_i - rejected_i`，归一化权重为`omega_i`，来源集合为`S_i`：

```text
P(e) = sum[omega_i * max(d_i, 0) / |S_i|]，仅累计引用e的标准
N(e) = sum[omega_i * max(-d_i, 0) / |S_i|]
alpha += P
beta += N
```

多来源均分，权重1，无折扣、不先抵消、不用lambda或margin增益。只有P=N=0不追加数值证据；净方向只展示。整体成功也可以有负信用或零信用，不另设正信用入池门槛。

- 已有经验本样本只从R0更新一次，后续失败不撤销；应用里的E来源仅审计，不重复记账。
- C仅在实际提供、声明采用且有效Judge成功后可Fusion。失败候选P/N留轨迹，不给不相关池经验扣分。
- ADD保存实际应用的候选原文，从Beta(1,1)开始；MERGE只合并兼容的同一设计问题，保留ID、旧证据及前后文本。
- 零信用合法ADD可存在fusion_history而没有evidence_history。不要为使池看起来有效而补造证据。
- held-out冻结池、文本与Beta，仅执行检索/选择/R0/Judge，不提候选、不Fusion、不回写。
- 角色输出错误保持有限纠错及样本/无效轮隔离；Judge错误明确留档。鉴权/网络、数据/存储、Calculator和程序异常fail-fast，不用宽泛catch吞掉系统错误。
- Memory和trajectory不是跨文件事务；续跑须源码/配置/数据一致及完整检查点审核，复制到新目录，不覆盖来源。

核心实现入口：`PipelineRunner`、`LLMInitialRubricGenerator.generate()/apply()`、`LLMCritic.propose()`、`LLMFusionJudge.find_match()`、`calculate_experience_credits()`、`ExperienceMemory.apply_downstream_credits()/fuse()`、`NumberedIDCodec`、CLI `_components()` / `_resume_checkpoint()` / `_code_version()`。
