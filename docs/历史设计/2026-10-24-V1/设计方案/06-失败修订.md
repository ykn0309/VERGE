# Critic草稿、原子化与应用控制

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../../../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../../../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

## 1. 触发与业务预算

仅训练R0有效Judge失败后启动。每轮Critic返回私有analysis及0～1份content/trigger草稿，无可信设计动作可返回空候选并正常结束。最多两轮，每轮一次业务提案、一次Atomizer处理和一次独立Generator应用；底层格式/结构纠错有界，不增加业务机会。

```text
Critic草稿 → Atomizer原子列表C → 新Generator(task＋固定E＋当前C) → Judge
  每条实际引用且自身P>N：暂存合格候选
  整体成功：结束轮次
  整体失败且有预算：Critic接续实际反馈，下一轮替换整个C
  空草稿：正常结束，按最新合格轮回退
```

原子列表为空或结构无效不是正常“无可信方法”，属于Atomizer输出错误；不能绕过原子化直接应用草稿。格式/结构耗尽记无效轮，有剩余轮次可继续；请求耗尽/拒答/Judge错误按[训练流程](12-训练流程.md)处理，不能伪造应用结果。

## 2. Critic输入及消息历史

首轮输入原始task、chosen/rejected、R0标准、权重与来源、逐项两侧Boolean及理由、分数/margin和轮次。逐标准分块，两侧判定与理由分行，Judge解释标为待核对而非事实认证。

第二轮保留真实system/user及Critic原始assistant草稿，追加实际Atomizer输出、每个原子候选的采用/P/N资格、应用rubric/Judge及错误。原子化结果是派生产物，不能改写首轮assistant原文使其看似由Critic直接生成。每条消息使用本条短编号，真实ID和对应关系由程序保存。

无效轮提供真实错误及最近有效证据，明确没有新的Judge结果。消息不跨样本，历史analysis不代替事实。Generator不接收这些诊断消息。

## 3. 草稿要求

Critic区分任务要求、标准问题、回答事实、Judge执行、偏好冲突及证据不足。只有Judge疑点而无可信标准设计动作时可以空候选；不能为了分差创造任务无依据的限制。

content表达生成前可用的方法，trigger从task、实际输入、上下文或领域知识识别；保留必要领域前提，将专名和固定数量抽象为语义角色或任务参数。不保留答案片段、偏好身份、私有分差，不提出部分分、否决或跳过协议。

Critic仍应尽量提出一个方法；Atomizer负责对可能捆绑的方法做独立整理，不成为Critic任意罗列规则的理由。

## 4. Atomizer输入输出

输入仅待整理trigger/content和来源类型；来自Updater时也不提供父文本，仅标记来源类型，以防恢复已删除的旧规则。不给完整案例、Judge或信用，不重新诊断问题，不新增独立方法，不输出analysis。

输出为非空experiences列表，每条有自己的trigger/content。原子方法原样返回；复合方法直接拆开，保留各条必要条件。一个方法加其必要边界不能机械拆成两条。程序校验字段、非空、精确重复和预算，不按标点判断原子性。

content≤150字符、trigger≤60字符仅提示词约束。不存在自动最多两条/每组案例数约束；预算超限或部分结构无效整次纠错，不静默保留部分输出。语义原子性仍需独立复测。

## 5. 资格和收尾

每个原子候选分配独立ID，在本轮Generator可用列表中独立引用，P/N沿用多来源均分。合格只表示实际引用且自身P>N，与整体判断成功独立。

工程初始约定：正常收尾选择最新有合格候选的轮次，入池该轮所有合格原子候选；第二轮没有合格项则回退第一轮集合，不跨轮拼接。取消每题最多一条限制。错误结束不做正常回退，详见[候选生命周期](09-修订信用分配与准入.md)。
