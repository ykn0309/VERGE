# 版本可靠性、信用继承与演化惩罚

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../../../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../../../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

## 1. 信用与置信度

实际反馈按原归一化权重、多来源均分公式累计P/N，alpha+=P、beta+=N；两通道不先抵消，不衰减，不用margin增益。已有经验仅计训练R0，候选只计最终选中轮的实际应用；同判只计次数，不计信用或归纳案例。

每个版本有独立(1,1)先验。设本版本观测为P_o/N_o，继承信用为P_h/N_h，继承旧惩罚H及出生时本次惩罚D，则：

```text
alpha = 1 + P_o + P_h
beta = 1 + N_o + N_h + H + D
confidence = alpha / (alpha + beta)
evidence_amount = P_o + N_o + P_h + N_h
```

惩罚不是实际观测，不计证据量；因此证据量不再等于alpha+beta−2。置信度是带先验、信用继承及稳定性惩罚的应用分数，不是已校准的内容正确概率。

## 2. 修订与拆分的分配

本版本最近5条不同下游有区分案例的信用总量W=Σ(P_i+N_i)，本次总惩罚D=0.2W。仅在成功replace/split时计算，不把历史累计信用、来源案例或继承信用再次放进W。λ=0.2是用户同意的初始参数，尚未证明最优。

父版本的总正信用P、总负信用N、已累计惩罚H分别包含它自己的实际反馈和继承部分。输出k条时，各子经验分别获得P/k、N/k、H/k及D/k，再加各自(1,1)先验。单条修订k=1，全部继承；拆分k>1，正、负及惩罚总量守恒，不能每条复制整份历史信用，也不拆分先验。

InheritedCredit单独保存parent_id、event_id、positive_credit、negative_credit、inherited_penalty、evolution_penalty；真实反馈仍保存于evidence_history。EvolutionRecord保存窗口信用量、λ及总惩罚。连续演化时旧惩罚继承一次，本次惩罚另加一次，不丢失、不重算旧窗口。

keep、修订后最终文本完全相同和失败均不扣分；不产生子经验继承账本。父退役后账本原样保留，不再参与检索或接收反馈；活跃统计不可再把父信用与子信用相加视为新增证据。

例：父P=8、N=2、H=0，最近5例W=1，则D=0.2。拆为两条后各P=4、N=1、本次惩罚0.1，加先验后alpha=5、beta=2.1，置信度约70.42%，证据量为5。父仍为原账本，不因退役扣分。

均分不是每个方法历史贡献的精确归因。即使无惩罚，独立先验也可能让拆分后的分数向50%靠近；低分经验改写后的分数仍可能上升。不能把这些算术变化解释成真实正负反馈或质量证明。

## 3. 本版本验证和案例窗口

子经验usage、evidence_history、案例和归纳窗口均为空；信用继承不复制祖先原始事件或案例，也不计作本版本已验证任务。自己的下游实际反馈立即累计，每5个新有区分任务用最近5条归纳；来源、祖先、同判不计窗口，P=N>0仍计一次。

每次引用记录positive/negative/both_true/both_false标准数，与信用额度及不同任务数分开。区分率=(positive+negative)/全部引用数，无引用时未知；反向区分也计入分子，故不是正确率。区分率仍只展示，不接入Selector。

## 4. 选择、展示和冻结

Selector仍参考当前confidence及evidence_amount；提示词明确总量含继承、不含惩罚，不代表本版本验证次数，适用性优先。Generator不接收信用。Web分别展示实际反馈、继承P/N、历史惩罚和本次惩罚；时间线先展示先验、再展示出生分配和本版本实际事件。

接受Judge噪声，不因单次误判撤销合法反馈或删除经验。演化子版本不额外验证，仍需后续使用逐步检验；本次只改变程序记账，不增加新的审核角色或调用。

held-out冻结所有信用、usage、案例、演化与类别。Memory8、Manifest/Trajectory10拒绝旧协议和跨方法resume；旧产物只保留原协议解释，不迁移。
