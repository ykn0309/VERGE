## 1. 目标与确定的规则

每个可独立采用的核验方法独立引用和记账；通过正负应用反馈产生修订，再由独立原子化器整理为一个或多个方法。类别只承担组织和检索，经验正文、信用和归属由不同接口管理。

| 事项 | 目标规则 |
|---|---|
| 原子化 | 独立Atomizer调用，直接输出各条trigger/content；已经原子化则原样返回 |
| 经验版本 | 已获得反馈的版本不原地改写；实际改写或拆分生成新ID，旧版本退出检索、保留历史 |
| 信用 | 各版本独立Beta(1,1)先验；修订继承历史P/N与旧惩罚，拆分均分，再均分本次惩罚 |
| 归纳 | 当前版本每获得5个不同下游任务的有区分反馈，使用最近5条归纳 |
| 案例窗口 | 正负案例都可进入；同判不进入；来源和旧版本案例不占这5条；完整历史另存 |
| 持续演化 | 不再达到10条就永久冻结；没有新的5条反馈就不归纳 |
| 类别 | 稳定ID、名称、描述，无信用；局部归类，不输出全池分配 |
| 归类候选 | 混合检索Top 10类别，不足时提供全部可用候选 |
| 检索索引 | 类别名称/描述与每个活跃成员的trigger/content分别建索引 |
| 混合检索 | 向量＋BM25，经RRF融合；成员命中映射到类别，类别按最相关命中计分 |
| 类别演化 | 先提交成员变化，再按批更新受影响类别的名称/描述，最后刷新索引 |

保留相对权重、Judge Boolean及理由、Critic样本内最多两轮、新Generator会话、固定E、R0已有经验信用、同判独立计次、有限纠错与样本错误隔离。区分率仍不接入Selector。模型角色默认Qwen3.5-Flash、关闭思考。

下文明确标注的“工程初始约定”用于使实现可执行，不代表已经测得最优参数。代码和独立模块复测已按用户后续授权完成；未清理历史、提交代码或启动完整真实链路。

## 2. 三层对象与写入权限

### 2.1 原子经验版本

保留experience_id作为实际引用ID；新版本分配新experience_id。content/trigger是该ID的固定公开文本，alpha/beta、案例、usage等仍可随实际应用变化。无需再设一份与版本并行累计信用的“逻辑经验”。

建议领域字段：

- experience_id、content、trigger、status=active/retired、category_id；
- alpha/beta、evidence_history、usage_history、inherited_credit（独立记录父P/N、旧惩罚和本次惩罚），均属于当前ID；
- origin_kind=candidate/evolution、origin_refs；
- working_case_refs：最近最多5个有区分下游任务的案例引用；
- last_consumed_feedback_seq、last_attempted_feedback_seq：归纳窗口及有限失败重试边界；
- created_by_event_id、retired_by_event_id：演化来源和退出事件。

模型只见本次局部短编号，真实ID由程序生成。案例正文保存在可追溯轨迹/案例记录中，窗口移出不删除历史信用、真实请求或案例原文。

### 2.2 演化记录

一条记录包含parent_id、child_ids、触发sample_id、实际5条案例引用、Updater草稿、Atomizer输出、结果状态、窗口信用量、λ=0.2、本次总惩罚和错误。keep不惩罚，replace/split采用统一信用继承公式。关系是一对一或一对多，不合并不同父经验。

记录和版本均无“家族汇总置信度”。继承P/N只能提供历史支持，界面不得把祖先证据显示为子版本已验证次数。

### 2.3 类别和角色权限

| 角色/程序 | 可输出或修改 | 无权修改 |
|---|---|---|
| Critic | 一份方法草稿或空候选，原有私有analysis | 入池、信用、类别 |
| Updater | keep或一份修订草稿 | 直接写池、转移信用、修改类别 |
| Atomizer | 一个或多个trigger/content | 信用、ID、成员归属、额外独立方法 |
| CategoryOrganizer | 待分类经验的归属、新类别初始name/description | 其他经验归属、经验正文和信用 |
| CategoryDescriber | 指定类别的name/description | 成员增删迁移、经验正文和信用 |
| 程序 | 校验、引用ID、P/N、状态转换、索引与持久化 | 用字符串规则宣称语义原子性或正确性 |

## 3. 原子化契约

一个原子方法是可独立采用或忽略、独立产生评价效果的核验动作及其必要条件。不是按句号、逗号或“并且”切分。

Atomizer输入包含待整理的trigger/content及来源类型；Updater调用只标记evolution来源，不提供旧版本trigger/content，避免已删除的旧规则重新进入输出。不给它完整案例、分数或Judge理由，它只整理已有方法，不承担重新诊断。修正方法的事实依据由Critic/Updater处理。

输出示意：

```json
{"experiences": [
  {"trigger": "任务要求根据数量关系进行计算", "content": "核对运算方向是否符合题目中的数量关系。"},
  {"trigger": "任务要求计算带单位的量", "content": "核对结果单位是否与所求量一致。"}
]}
```

约束：

1. 模型只返回一条时程序逐字保留输入草稿，不授权润色、补例子或扩充范围；多条输出才进行拆解。单条原样保留不证明输入已原子化。
2. 各子经验保留其方法必需的前提，不能拆掉条件，也不能一律复制过宽的共同trigger。
3. 不凭空新增方法、不把“方法＋必要边界”拆成两个方法，不通过拆分删除原方法的必要部分。
4. 不新增analysis、每条content≤150字符/trigger≤60字符仍仅为提示词要求。
5. 程序检查非空结构、字段、精确重复和预算；不以文本长度、关键词或标点判断原子性。
6. 首次调用及格式/结构纠错有界，不增加另一个检查模型。结构有效不保证语义原子性，必须独立复测。

不恢复计划49的案例分组、每组最低案例数或最多拆两条协议；当前信用均分依据计划68独立定义，不要求模型分配案例。输出条目数量由实际方法决定，完整输入输出预算统一配置，超预算不得静默截取部分子经验。

## 4. 新候选：先原子化，再应用

```text
Critic草稿 → Atomizer → 本轮原子候选集合C
→ 新Generator(task＋固定E＋当前C) → Judge
→ 按实际原子候选ID分别计算P/N与eligible
→ 正常样本结束选择入池集合
```

每个原子候选有独立短ID及内部候选ID，实际引用且自身P>N才具资格，不要求整体成功。同一标准引用多条经验时保留现有按来源数均分的算法，不能给每条复制整份标准权重。Generator可只采用候选集合的一部分。

Critic仍最多两轮，第二轮看到首轮真实分析、原子化结果及逐条应用反馈；Generator第二轮只收到固定E＋第二轮C，不叠加第一轮C。不得把已拆分候选伪装成Critic原始回复，真实消息和派生记录分别保存。

工程初始约定：延续“最新合格轮优先”，以集合为单位选择。正常收尾若第二轮存在合格候选，入池该轮所有合格原子候选；否则回退第一轮合格集合，不跨轮拼接。不再限制同题最多一条，未引用、不合格及未选择轮候选只留轨迹。此约定控制相近的两轮方法重复入池，须在局部验证中检查其取舍。

来源应用给新候选记Beta(1,1)＋该轮实际P/N；来源案例不计入5个下游任务。Judge/请求错误结束不执行正常回退入池，有效R0已有经验信用不撤销。新增Atomizer失败按本轮无效处理，不能使用未经原子化的草稿绕过契约。

## 5. 当前版本的反馈和五案例归纳

### 5.1 记账与触发

现有信用公式不改：对标准i，归一化权重为w_i，来源集合S_i，d_i=J(chosen)-J(rejected)。对引用经验e：

```text
P_e = Σ_{i:e∈S_i,d_i=+1} w_i / |S_i|
N_e = Σ_{i:e∈S_i,d_i=-1} w_i / |S_i|
alpha_e += P_e；beta_e += N_e
confidence_e = alpha_e / (alpha_e + beta_e)
```

两回答同判分别记录both_true/both_false，不加P/N，不进入窗口。P+N>0即为有区分案例：P=N>0的混合任务也计入一次；同一任务多标准只占一个案例。同一版本/任务/阶段的事件去重，不能重复加分或触发。

已有经验仅累计训练R0反馈，候选应用阶段对E的引用仅审计。R0信用先提交，整个样本候选过程结束后才执行演化，保证当前样本固定E不变。

### 5.2 归纳输入和窗口

每获得5个尚未消费的不同下游任务案例，使用当前版本最近5条归纳。每张卡保留完整task/chosen/rejected，以及引用该ID且有区分的标准问题、两侧Boolean/reason和positive/negative标记。不给Updater无关标准、整体分数、P/N、权重或私有分析。

来源案例、祖先案例仅作历史追溯，不是本版本已经接受的验证，不放入5条窗口，也不自动补进Updater输入。同判标准在混合任务卡中仍被过滤。保留完整请求预算和短ID，不截断回答。

正常情况下：1–5归纳后保持原样，则6–10再次归纳；产生新版本后，新版本从自己的第1条下游反馈开始计数。新旧版本不混用案例。

工程初始约定：Updater显式返回keep或revise；keep无需再调Atomizer。revise调用Atomizer，最终只有一条且与父版本文本完全相同时也按keep处理。成功keep消费本批5条；不因保持原文立即重试。

失败时保留父版本和窗口，不消费反馈，同一个最新案例不重复调用。后续新有区分案例到达时，取最近5条再尝试，移出的案例仍在历史中；这是失败情况下允许窗口重叠的例外。暂停/结束不为不足5条强制归纳，不在原输入上无限重试。失败重试边界、请求数须记入审计。

### 5.3 版本替换与拆分

合法修订经过Atomizer后，一个不同输出为replace，多个输出为split。程序在一次Memory状态提交中完成：保存所有新版本、演化记录、父版本退役、分类队列更新。结构/请求失败或部分输出无效则整次不写，不能只保留一部分子经验。

演化子版本不额外进行入池验证。设父历史信用P、N，已有惩罚H，最近5例累计信用W=Σ(P_i+N_i)，本次惩罚D=0.2W；输出k条时每条alpha=1+P/k、beta=1+(N+H+D)/k。单条修订k=1；keep、同文本及失败D=0且不创建子版本。inherited_credit分别保存父P/k、N/k、H/k和D/k，真实反馈仍在evidence_history；证据量只计P+N，不含惩罚。子usage/案例窗口为空，父完整账本原样退役留档。子初始未分类，不强制继承父类别。

例：父P=4、N=1、H=0，最近5例W=1，则D=0.2。拆为B、C后各继承P=2、N=0.5、惩罚0.1，alpha=3、beta=1.6，置信度约65.22%、证据量2.5，但本版本验证任务仍为0。父仍保留4/1原账本。仅改变trigger也执行同一规则；不把父先验(1,1)均分。

输出结构正确并不证明修订更好；直接激活可能替换掉有用父经验，继承信用也不能证明新文本有效。均分并不能还原每个方法的真实贡献；演化惩罚与独立先验会改变分数和选择机会，不增加额外准入、探索名额或自动回滚。局部复测要明确检查必要条件是否丢失、旧方法是否被不当替换。

## 6. 两处检索共用混合检索引擎

当前计划65的“类别/未分类混合召回”只是两类检索单位的混合，算法仍是纯向量。这里才加入BM25及RRF。

### 6.1 文档索引

| 索引文档 | 文本 | 命中后的检索单位 |
|---|---|---|
| 类别文档 | name＋description | 该类别 |
| 已分类活跃经验文档 | trigger＋content | 所属类别 |
| 未分类活跃经验文档 | trigger＋content | 该经验（任务检索）；不参与类别候选 |

不索引退役版本、案例、分数、程序ID。文本不变而归属改变，只需更新映射；信用变化不重编码。成员移出或退役立即移除相应映射，空类别立即退出索引。

### 6.2 排名与两类查询

向量按余弦相似度排名，BM25按固定中文分词/英文归一化策略排名。对文档d进行等权RRF：

```text
score(d) = 1/(k + rank_vector(d)) + 1/(k + rank_bm25(d))
score(unit) = max(score(d) for d mapped to unit)
```

未出现在某一路有效结果中的文档，该项为0；BM25无词项命中不能凭任意次序获得词法分。工程初始参数k=60，确定性并列顺序、分词规则及参数写入配置/manifest；这不是本项目已验证的最优值。按最相关命中取max避免直接累加成员数量，但不宣称消除了所有大类别优势。

- 任务检索：query=task，聚合去重后取Top20类别/未分类单位，保持现有规模；命中类别完整展开，Selector仍最多选择5条活跃小经验。
- 归类检索：query=待分类经验trigger/content，只返回类别，取Top10。排除待分类经验自身的成员文档，避免自身命中强化原归属；类别描述仍可能包含其旧信息，记录此限制。
- 先聚合再截取单位，不能先截10篇成员文档后宣称得到10个类别。当前规模初版可对全部缓存文档计算两路排名，日后若采用近似召回须单独记录候选损失。

分类器只看每个候选类别的名称/描述和最相关成员摘录（工程初始上限3条成员，保留完整trigger/content及真实成员数），这是明确的输入投影，不是模型上下文溢出时静默截断。全部活跃成员仍参与检索。任务Selector继续完整展开，类内规模增大导致其输入预算超限仍可能发生，不把局部分类输入有界误称为所有模型输入有界。

## 7. 局部归类和类别名称/描述演化

### 7.1 入队和局部归类

新候选入池、演化子版本激活进入按经验ID去重的待分类队列。保留现有默认5条的批量时机，样本结束处理，训练暂停/结束处理剩余；这与归纳5个案例是两个独立计数器。信用变化不触发分类。

每次只给CategoryOrganizer一个待分类经验和其Top10候选类别，不给全池。输出为下列之一：

- assign：选择本次候选类别的短ID；
- create：新类别初始name/description，由程序生成真实类别ID；
- unclassified：保持未分类。

程序校验局部白名单，只修改目标经验的归属。不能借局部归类迁移其他成员，不自动执行全局重聚类或类别合并/拆分。选择已有类别不会修改其描述。

工程初始约定：同一批按稳定队列顺序执行，后项能看到前项已提交的归属和新类别，避免整批都依据空快照创建相同新类。已有类别描述在批次结束前不反复更新，成员索引映射反映已提交状态。失败项保留队列、其他已成功局部归类不撤销；同一经验及同一候选索引版本的失败请求不连续重试。

### 7.2 类别描述更新

成员加入、移出、退役触发类别dirty标记；新建类别初始描述也可由本批末校准。每批每个受影响的非空类别最多更新一次。没有成员变化不调用，没有dirty标记不做全池扫描。

输入为原name/description、本批新增/移出成员的trigger/content及最终成员数；不读取全部成员，也不改经验。更新器只输出：

```json
{"name": "数量关系与量纲核验", "description": "组织核对计算中的数量关系、运算方向和结果量纲的方法。"}
```

程序不接受成员列表或归属指令，字段白名单从接口上禁止它移动经验。只提交元数据；空类别由程序删除，不调用模型。成功后刷新类别文档向量/词法索引，供下一批使用。本批不因新描述再反复归类。

描述更新失败：保留已确定归属和旧描述，持久保存dirty增删记录；下次有新成员变化或明确的后续收尾机会再有限重试，同一dirty版本不在每个样本重试。多次失败累积的变化仍受完整请求预算限制，超限记录错误，不私自摘要或删变化。

分类和描述两步不需要跨调用回滚；归属是事实，描述是可暂时滞后的检索元数据。增量描述可能失真、类别检索可能漏召回并产生重复类别，首版记录这些问题，不加入第二个审核器或全局整理服务。

- 每个模型调用保存实际请求、回复、局部编号映射、使用的快照/索引版本及错误。记录两路排名、文档到类别映射、RRF结果与最终候选，不把类别ID当经验来源。
- Memory内演化状态一次提交；跨Memory/trajectory故障不声称已有事务保证。必须通过完整前缀检查拒绝不一致resume，不静默重复写信用。
- 版本文本不变时不产生新版本；所有归纳、原子化、分类失败都不能撤销此前合法R0信用。请求失败有限重试后隔离；鉴权、配置、存储和程序故障fail-fast。
- held-out冻结信用、案例、演化和类别元数据；可构建只读检索缓存，不调用演化/分类角色。
- Web分别展示活跃/退役版本、演化关系、实际版本证据、5条工作窗口/完整历史、归纳触发案例、类别归属和描述更新事件；保留类别专页、独立经验分区、排序、列表滚动和只读行为。分别展示本版本实际反馈、继承P/N、历史惩罚及本次惩罚，不将继承分数标为本版本验证结果。

## 9. 验证标准和不作出的承诺

先确定性测试状态/账本，再按模块独立复测。每个改动模型模块至少20条按任务去重的真实历史输入，覆盖问题、正常、边界；新角色无旧请求时保留源轨迹及确定性转换记录，不能把人工合成输入标为历史实参。

原子化重点看：非原子方法是否拆开、必要条件是否保留、已有原子方法是否原样返回、是否凭空增加规则。归纳重点看：正负案例是否帮助修正、是否错误改写已合理方法、是否丢失旧文本必要边界。类别重点看：合理归类/未分类、新类重复、增量描述是否覆盖实际变更、是否误扩大类别。

检索用相同冻结快照、候选数和输入分别比较纯向量/混合检索，记录人工相关集合覆盖、误召回、类别大小分层及成本；查询数量至少20个不同任务，两种用途分开。历史本次池最多19单位、旧Top20几乎全召回，不能用这部分结果宣称Top20召回收益；额外采用预先固定的更小K诊断曲线或明确标注的组合快照，不能隐瞒池规模边界。

本方案不保证经验必然原子、分类必然准确、新版本必然更好或混合检索必然更准。均分及演化惩罚造成的降分不是实际反向反馈；信用继承也不是新版本质量证明。完整链路和长期收益需要另行实验，不自动从局部通过扩大运行。
