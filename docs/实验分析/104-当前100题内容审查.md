审查产物位于本地`artifacts/audit104-current100/`：原始输入、分片、各模型完整回答、通道失败、覆盖检查、`combined-review.json`、`root-decisions.json`及更正后的`review-after-root.json`。原运行的四份关键文件摘要均未改变。

## 2. 哪些预期已经做到

### 选择和使用原因确实能帮助追查

68题选中过经验，57题实际引用；另外11题选中但最终没有正权重引用。可以从使用说明区分“Selector选了但Generator拒用”与“使用后没有区分”，不再只靠经验ID猜测。

其中10题明确以任务不适用等理由弃用全部所选经验：编号27、47、53、54、59、60、74、81、84、92。例如：

- **53：替代历史。** Generator明确说明用户已要求hypothetical场景，不应套用“信息不可得”经验或纠正虚构前提。
- **74：保留格式重写聊天。** 明确说明必须保留原文本结构，不适合“避免复述开场”的续写经验。
- **27、60：角色资料。** 明确区分资料整理与场景续写，不把已知资料当应排除的信息。
- **47：作品剧透。** 将公开剧情与难核实事实区分，拒用“未知数据”经验。

这说明Generator有实际拒用能力，未始终照搬；同时也表明Selector先选后被拒的情况仍存在。11题不能都算拒选成功：例如11只是认为无需额外独立标准，引用追踪与自称采用方法还有边界。

### 有正常的经验应用，不只是“少用经验才不出错”

- **32：文学社续写。** 围绕结尾仍在熟睡的状态检查新互动是否合理，没有再要求逐字复述已经发生的开场。该检查仍引用经验。
- **35：英语润色。** 引用经验检查机械重复、句间衔接与不地道搭配；另将不适用的格式变体经验舍弃，没有硬加空格格式门槛。
- **62：摘要。** 将“四句以内”落实为句子数检查，是用户明示约束；不能因它借用了数量检查方法，就把它一律算成错误迁移。
- **40、78：有数量要求的列表。** 数量核查有任务依据；初审将“不是短句任务却用计数方法”判错，过于字面化，不能据此否定合理迁移。

这些是当前表现符合预期的证据，足以说明机制不是处处失效；不表示整份Rubric或Judge都正确。

### Critic有时能删除经验带来的错误要求

**17（节目变更博客）**是直接证据：原标准要求Lamput与被撤节目形成“设计原则的直接否定或极端反转”；Critic指出用户只是要求宣布撤下A、加入B，删除该标准。后续只评价保留的两项，未为制造分差强行把双方都符合的标准改判。这是一次有依据的修复，即使后来没有得到可准入经验，也不能算作毫无作用。

但其修订后复核文本仍读到了描述旧缺陷的analysis，并讨论一个已不存在的“标准3”，说明输入组织还有混淆风险，见下文。

因此，**“经验只提供方法，前提和义务由当前任务决定”的预期尚未达到稳定执行。**问题发生在多个不同场景，并非只凭第87题的一个表述推断。

选择与应用往往连着出错：55和93的选择理由先接受了错误任务解释，Generator再沿用；82甚至在有“按最合理意图回应”的经验时，把多义短语强制当成已知产品。这些材料支持联合问题，不能精确分配Selector与Generator各占多少责任。

### 纠正此前对第87题的归因

原标准并非无条件禁止复用台词，而是限定“机械照搬且不进行反应演绎”。Chosen重复开场后，实际紧接着有Naruto的回应和多轮对话；Judge却称它“未进行实质反应演绎”。这是更直接的Judge误判证据。不能截掉标准的限定从句，将该题当作Generator一律禁止复述的确证。

初审及部分二次复核也犯了这类错误，主代理已把对应Generator指控降为不确定。类似地，67的“保持泡沫浴缸等状态连续”不等于要求逐字复述；57的前缀和字符上限均来自task，合并为一项不自动构成使用失败。

## 4. 经验组织是否有帮助，经验内容是否可靠

**帮助主要体现在说明与追踪，以及部分显式拒用；尚未使经验自带的错误前提、量词和强度消失。**多字段并没有防止把同一个不可靠观点拆写到多个字段。

全读35条活跃经验后，有以下可直接定位的风险：

- **未来不可见的信息仍写进选择条件。** `d29687e6`和`6cd00355`的trigger要求先知道“候选回答更自然”或“候选回答有哪些格式变体”；`f0d53f93`与`d1a72737`要求先知道“原标准”写成什么样。正常Selector只有任务和经验，没有候选回答或尚未生成的标准，因此无法按这些条件选择。它们不是字段缺失，而是字段内容设计错了。
- **从“每项”偷换成“至少一项”。** 编号49的原改动描述“每个列出的细分领域是否包含限定”，入池经验`a6bcab30`却写“只要列表中至少存在一个实体具备目标属性就为真”，并要求忽略其他不符合条目。不能从本题一个Boolean标准的解释，推出所有未来列表都适用的通过规则。
- **从“颜色创意”缩成“名称里必须有颜色词”。** `09b05475`要求创意项名称部分显式含颜色词；能用描述传达颜色、但标题没写颜色词的合理方案可能被排除。39的任务没有规定名称—描述格式。
- **把一个时序例外概括成矛盾规则。** `a179ffcc`的trigger允许动作结束之后，principle却“不允许动作完全结束后”，guide还把“先A然后B此时C”改成可在A进行时。这不是缺少更多案例而已，已有字段彼此不一致。
- **把“给出不确定性”持续扩成“还必须提供后续查找路径”。** 多条事实经验都有这个固定义务，能用于确实需要查证建议的任务，也容易侵入简短事实询问或文本改写。94中创作任务还被要求说明历史不存在并提供官方记录。

35条全部入池不代表这些风险都被后续纠正；15条活跃经验尚无有效Q更新。不能用其初始0.6或核对通过解释为已验证可靠。

## 5. Critic验证和核对是否达到预期

### 有更直接的验证，但仍会用错评价对象

Critic直接修改标准，确实绕开了“先提炼，再期待Generator正确使用才能验证”的环节；17等案例能直接修掉额外要求。但margin是按Critic最终认可的Judge判定算的，**Critic错误解释标准或回答，会把不合理的修订也送去提炼。**

- **28：十个劝说短语。** 本来把数量与说服力分成两项，Critic复核时却以“数量不达标”为理由更正“逻辑链条”的判断。拆开的维度又被混回一项；它还把恰好10个改为至少10个。
- **69：Scratch自定义积木。** 初始标准只检查列表与循环；Critic发现没有定义头，却把这种标准遗漏当原Judge误判。应该补标准，不能拿新增封装要求推翻旧的列表／循环判定。
- **78：25个长名称。** Critic用条目重复来否定长度／风格项，即使重复已经有独立标准。总分更符合偏好并不能证明每次更正都按原标准执行。
- **98：Oscar Bait。** 新标准允许类别描述，不必使用固定“现象／趋势”标签，最后复核仍受旧措辞影响，对简明定义提出额外要求。具体材料有语义争议，不能把所有模型指控都当确定事实，但新旧标准混用值得重点检查。

8题接口失败也需与语义问题分开：程序拒绝重复原值、无明确关联的更正，是运行失败，不等于所有这些候选都必然无效。

### 提炼仍可能比实际修改更强

49的“至少一项即可”、39的名称格式、66的时间窗口，都表明验证通过的是整份修订Rubric，不是提炼出的每条通用规则。**“修订有效”到“经验忠实且可迁移”之间仍有缺口。**这也是当前数量与质量权衡最值得处理的位置：不必把所有候选都重新跑一遍Generator，但要检查提炼有没有改变条件、量词、允许范围或判断对象。

### Checker的错误不只是假阴性，也有错误指责

例如40的角色党派列表明确给出12—17个，数量标准有任务依据；Checker却将跨任务的数量方法应用直接说成不适用。67中保持初始状态连续也被误说成强制复述。反之，17的额外设计反转义务、55对假设前提的否定，又曾被执行核对认可。

这些报告会按假设参数进入Q，可能给Updater错误方向；本文没有测出这种影响在未来累积多少，也没有证明贝叶斯模型能够消除它。正负报告需连同依据保留，不用顶层error/correct代替内容判断。

## 6. 初筛数字怎样使用

审查覆盖：选择68题、实际引用57题、Critic处理45题、实际产出提炼条目27题、执行Checker57题、经验核对27题。不是每个环节100题都有输出。

二次审阅加程序覆盖核查后，应用曾被标为明确问题34题；主代理针对跨场景合理使用、合并核查、限定从句和错误归因等撤回／降级14题，剩20题被保留为模型问题线索，25题未见明确应用问题、12题仍不确定。**这些是审阅状态，不是真实错误率。**主代理确认的重复问题见第3节，而不是宣称20／57已经是可靠标注。

同理，初筛标记选择问题42／68、Critic问题37／45，含过窄匹配、主观深度、外部事实无法核验及纯技术失败等，不能直接据此排序哪个模块最差。完整标签与保留意见可追溯，不把不确定样本当通过，也不为了给出漂亮比例隐去模型分歧。

## 7. 现在该如何理解预期，以及下一步

| 预期 | 当前判断 |
| --- | --- |
| 能知道为什么选、为什么用 | 已做到，能支持具体追查；理由仍可能为错用辩护 |
| Generator可拒用不适用经验 | 有实际证据，10题明确全部弃用；不能替代Selector做好筛选 |
| 经验不增加未经确认的前提／义务 | 尚未稳定做到，多个任务类型反复出现 |
| Critic能直接修Rubric | 有有效修复，也有对象混淆；不是全部失败 |
| 修复验证后提炼的经验可靠 | 保障不足，量词、格式、时序、未来可见性仍会走样 |
| 下游异常能改对经验字段 | 两次实际采用的修订体现了按报告改trigger／guide；回放接受不保证跨任务正确 |

下一步建议优先处理**经验提炼是否忠实于有效改动**与**哪些选择条件在运行时能确认**，而非继续只让Generator“更加注意任务”。同时检查Critic更正是否仍对应同一项标准，不让一个维度的不合格扩散到其他维度。针对这些具体问题先讨论改法，本轮不自动改提示或追加训练。

本轮已完成只读审查与文档同步，无代码行为修改，原100题结果和经验池未变。模型审阅全文、错误与更正均保留。看板记录转向原因；新增研究认识写EXPERIENCE。
