# Chat Hard 144/60 内部试验：经验机制的问题与证据

> 状态：问题诊断，不是新的方法规范或已经验证的修复方案。实验配置与执行记录见 [计划 11](../plans/11-Chat-Hard-扩大样本内部试验.md)。方法定义以 [设计总览](../设计方案.md) 及其模块文档为准。

## 1. 范围、口径与结论

本轮在同一 RewardBench Chat Hard 数据源的六个子集上顺序训练 144 条、冻结测试 60 条；使用 `qwen3.5-flash`、DashScope 向量召回和训练后包含 20 条经验的经验池。测试初始判断正确 **43/60（71.67%）**。这是一次**同源内部试验**，不是官方成绩，也不是经验机制的净收益估计：尚无相同样本、相同评测设置下的无经验对照。

测试中 **31/60 条样本选中了经验**，合计 53 次“样本 × 经验”选择；26 条样本的初始 rubric 至少有一条带来源标准，共 **47 条带来源标准**。另有 **14 次选中后完全未被任何标准引用**，涉及 5 条完全没有经验来源标准的样本。以下各项分母不同，不应把选择次数、来源标准数或样本数混用。

核心问题是一个级联链路：**Reflector 生成的 trigger 有时依赖事后信息 → 事前 Selector 过宽地选择经验 → Generator 把不适用经验写进标准或牵强标注来源 → 训练中的 downstream credit 可能把错误归因当成可靠性证据**。这不等于所有判错都由经验造成；测试样本不会回写经验池。

证据来自本地运行产物（被 Git 忽略，不保证在其他机器上存在）：

- `runs/rewardbench-chat-hard-qwen-vector-144x60-resume1/artifacts/trajectories.jsonl`：逐样本召回、选择、rubric、Judge；
- `runs/rewardbench-chat-hard-qwen-vector-144x60-resume1/artifacts/experience_memory.json`：最终训练后经验、Beta 状态和证据；
- `runs/rewardbench-chat-hard-qwen-vector-144x60-resume1/analysis/selection_audit_deepseek_flash.md` / `.json`：31 条选中样本的逐项模型标注与原始理由。本文件保留关键事实，避免完全依赖未跟踪的运行目录。

## 2. 事前选择链路：trigger、Selector、Generator

设计要求：Retriever/Selector/Initial Generator 只看当前 `task`，不能看 chosen/rejected、初始 rubric 或 Judge；Selector 可选择 0–5 条，不能为凑数选择无关经验；`source_experiences` 仅标记**实质改变了标准**的经验，task 本身足以产生的标准应标 `[]`。参见[经验检索与筛选](../设计方案/02-经验检索与筛选.md)、[初始 Rubric 生成](../设计方案/03-初始Rubric生成.md)。

### 2.1 Trigger 的信息边界不匹配

Reflector 在成功修订后能看到 task、初始/修订 rubric、判断和 critic 反馈，但把事后诊断直接写进未来经验的 trigger 时，事前 Selector 无法核验。例如：

| 经验 | trigger 中需要事后信息的片段 | 事前可观察部分 |
|---|---|---|
| `exp_8637aae1…` | “initial evaluations show hallucinated content being incorrectly rewarded” | task 是否要求外部来源信息 |
| `exp_3ce593d8…` | “the rubric includes…” 且 “initial judgments incorrectly assign…” | task 是否要求最小/最优解 |
| `exp_9ba3a9fb…` | “existing criteria fail to distinguish…” | task 是否要求解释比较机制 |
| `exp_4a7c46ce…` | “generated response lacks clarity…” | task 是否要求逻辑推导 |

对本次**实际被选择过的 15 条不同经验**进行独立 trigger 复核：5 条可完整从 task 检查、4 条只可检查一部分、6 条依赖 rubric/响应/判断等下游信息；按 53 次选择展开分别为 **21 / 18 / 14 次**。这属于 DeepSeek Flash 子代理的语义分类，边界措辞可能有争议；但上表引用的事后条件确实超出 Selector 输入。**并非代码把 preference pair 泄漏给了 Selector。**

### 2.2 选择过宽，以及选中不等于使用

使用 `deepseek/deepseek-flash`（当时官方 API 对应 DeepSeek‑V4.1‑Flash）按 task 先评估经验适用性，再查看 rubric 与 Judge：在 53 次选择中，子代理标为**适用 9、选择过宽 39、存疑 5**。其中 14 次过宽选择未被 Generator 引用；其余 25 次过宽选择进入了 rubric 的来源标注。**这些数字是单次模型诊断，不是人工金标准或 Selector 真实错误率**：只检查选中的经验，没有检查另外 29 条未选样本是否漏选。

例如 `llmbar-natural:2560` 是单句精简改写，却同时选中列表多样性、动作确认、最优性三条不相干经验；Generator 未引用其中任何一条。它说明选择阶段有噪声，也说明 Generator 有时能忽略选错的经验。因此不能把三个环节全部等同为“Selector 一处错误”。

### 2.3 已选经验进入 rubric 后的负面方向：`llmbar-natural:2619`

题目要求**用自然语言描述两层住宅管道系统**，不是请求访问外部数据库或声称已有精确施工数据，却选中 `exp_8637aae1…`（“外部数据不可访问时承认局限、严惩编造细节”）。初始 rubric/Judge 留下了以下可核对的算术证据：

| 标准 | 来源 | 权重 | `chosen_yes − rejected_yes` | 对 margin 的贡献 |
|---|---|---:|---:|---:|
| 避免编造管径、设备位置等具体细节 | `exp_8637aae1…` | 0.267 | −1 | **−0.267** |
| 按要求用自然语言描述核心系统 | `[]` | 0.200 | +1 | **+0.200** |

另外两条标准贡献为 0，最终 margin 为 **−0.067**，判错。子代理认为防编造标准在**文字上直接落实了经验**，但经验的外部检索失败 trigger 不适用于此任务：**“来源文字直接”与“经验用得对”是两个问题**。机械去掉负向标准、沿用原 Judge 的判断会使剩余方向转正；这只是静态算术，不能证明重新生成 rubric 时一定判对。

### 2.4 来源牵强：`llmbar-natural:2602`

“Who wears short shorts?” 样本中，“是否直接回答而非回避”被标为来自 `exp_5b7739fb…`。该经验处理的是**不可能或不安全的脚本前提**；本题的直接回答标准仅由 task 就足以生成，按设计更应标 `[]`。该标准当前权重约 **0.308**、判断差为 **+1**，故来源记账会给经验一笔正方向的贡献。代码只校验来源 ID 是否来自已选经验，不验证语义上的实质影响；本次在冻结测试中**没有写回**，但训练若发生同类标注，会把任务自带标准的收益记给经验，形成归因—信度—再选择的风险。不能仅凭这条测试记录断言训练已经发生该闭环。

47 条带来源标准的子代理标注为：文字关联**直接 22、较弱 24、不支持 1**。其中有 **8 次过宽选择**仍生成了至少一条“文字直接关联”的标准，表明照搬经验原则与适用条件不符可以同时发生；来源标注需要独立于选择做检查。

## 3. Reliability：证据偏薄，且依赖来源标注

[可靠性设计](../设计方案/11-可靠性更新与噪声证据.md)中的 confidence 是 Beta-style **证据分数** `C=α/(α+β)`，有效证据量 `N=α+β−2`，不是校准后的未来成功概率。最终 20 条经验中 **13 条 `N<1`、17 条 `confidence>0.5`、1 条没有非零证据**。证据明细为 **26 笔正修订信用、25 笔正下游信用、8 笔负下游信用**；Beta(1,1) 先验下少量正信用足以让 `C` 超过 0.5。证据条数也不等于独立任务复现数，例如 `exp_5b7739fb…` 的两笔修订信用约 0.471、0.529 均来自同一训练样本 `…:2893`。

`exp_8637aae1…` 训练后 confidence 约 **0.690**；测试中 9 条样本引用它，7 条出现非零来源信用，其中 **3 正、4 负**。这表示信度没可靠阻止本次误用，**不是说它造成了 4 次整题判错**。测试信用只用于离线诊断，不更新 Beta。[已有经验信用](../设计方案/05-已有经验信用分配.md)依赖 `source_experiences` 和标准方向，因此来源牵强会影响训练时的可靠性证据。

另须区分**负方向**与**负迁移**：本次 47 条带来源标准中方向为 22 正、16 零、9 负；例如涉及违法请求的 `llmbar-adver-GPTInst:2849`，子代理认为安全经验的选择合理，尽管其安全标准贡献为负。若偏好标签与安全规范冲突，不能因负贡献就宣告选择器错误。

## 4. 向量召回和学习效果尚未独立验证

[广召回设计](../设计方案/02-经验检索与筛选.md)的 `TopL=20`，最终经验池也恰好 **20 条**；本次 60 条测试全部召回池中所有经验（训练时经验较少，也未出现池大于 TopL 的筛除）。相似度可能改变候选顺序，但这次**没有检验从超过 20 条中筛出正确经验的能力**。因此上述选择问题主要暴露在 LLM Selector 与经验内容/trigger 上，不能据此评价向量 TopL 召回率。

训练样本按六子集成块排列，前 48 条训练样本未选中过经验；题型分布、经验池规模和样本位置同时变化，不应把后期使用变化画成“学习曲线”。`43/60` 没有配对的无经验基线，也不能归因于经验、召回、可靠性或训练顺序的任何单一因素。

## 5. 建议的验证顺序（尚未实施）

1. **先修评估口径**：在开发/验证集上人工复核一批“task—trigger—选中经验—标准来源”的逐项标注，特别区分“trigger 可事前判断”“任务是否匹配”“标准是否因经验而新增/改变”。不要直接用这 60 条冻结测试反复调参。
2. **再界定经验与选择的边界**：让 Reflection 的适用条件只引用 task 阶段能看到的信息；把初始 rubric/Judge 的失败征象保留为事后解释，而非事前 trigger。Selector 保留可以不选的路径；Generator 对已选但未贡献标准的经验不必引用。以上是待验证的设计方向，不是本报告已经验证有效的修改。
3. **核验来源与净效益**：抽样比对 task-only 和 task+experience 生成的 rubric；仅在经验确实改变/补充标准时标来源。在相同 held-out 样本上做无经验配对对照，多次运行以区分生成波动；记录召回→选择→实际引用→Judge 的分层指标。仅沿用原判断“删除某条标准”的静态计算不能替代重新生成对照。
4. **延后向量结论**：在经验池明显大于 TopL、且有人工标注适用经验时，才评估 TopL 覆盖率与漏召；分析训练顺序需换序或重复试验。报告 confidence 时并列展示 `N`、独立后续验证任务数及修订/下游证据来源。

以上问题优先指向 **trigger—selection—provenance 链路**，但现有同源试验不足以量化各环节对最终准确率的因果贡献。
