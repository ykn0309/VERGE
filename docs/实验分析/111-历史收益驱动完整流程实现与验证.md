# 新流程实现与验证

2026-11-07，分支`codex/experience-premise-research`。实现前快照`9faede2`；本次未提交或推送新改动。

## 实现范围

- 经验只有适用范围、核心方法、生成指南；新增／改写都产生独立ID。删除旧Q／贝叶斯参数表、版本升级、Updater、Checker修订和Rubric补丁提炼链路，不保留旧运行格式兼容。
- 检索最多10条：6条历史收益＋4条全池语义；重复不占名额，缺额用语义补齐，无达标任务组时全语义。历史先按任务组求单经验均值，再按查询相似度加权；证据量单列，未知不算0。经验组仅作分析。
- Selector最多选5条，可不选并输出理由；Generator说明实际使用情况，一条标准最多引用一条经验。两者看不到回答或标签。Judge只看task、标准和当前匿名回答，双侧独立请求，程序归一化并评分；严格正margin才判对，平分不算判对。
- 训练有经验时同题有／无经验对照，无经验仅一路。实际路径判错才触发Critic，纯技术失败不作为内容反证。
- Critic每轮最多2条、最多2轮，直接提经验。每条单独经过Generator、Judge；必须有正权重标准实际引用且最终判对才准入。同轮通过者都入池；有通过项即结束本题，否则只将内容失败反馈给下一轮。技术失败留档，不教Critic为其改内容。来源验证不记独立下游收益，入池后不重复应用来源题。
- 滚动5样本并发：不等待整批；新案例读取启动时的已提交状态，完成后把完整轨迹、经验、聚类和收益一起原子提交。收益由共享账本记录计算，不用启动时的后验覆盖当前状态。冻结前等待全部案例及即时验证完成。
- CLI支持训练／断点续跑、单独冻结评价和检查点摘要。模型／提示协议、代码或数据摘要变化时不盲目续跑；旧格式直接拒绝。正式配置训练／测试任务重叠会拒绝；单独冻结评价会报告与训练的重叠数量。
- WebUI改读新检查点，展示两路、候选来源、选择理由、使用与判定理由、Critic尝试、分任务组收益及模型完整消息／回复／错误。仅监听127.0.0.1。

最终代码用离线后端跑通20题训练、1题冻结评价，并单独加载同一冻结文件再次评价；文件摘要未变。产物：`artifacts/learning110-final-smoke/`和`runs/history-learning-final-smoke-110/`。离线后端是确定性流程夹具，不能把它的正确数当作研究效果。

Playwright实测桌面和390像素窄屏均无横向溢出，调用详情能展开输入提示词；浏览器控制台0错误。截图保存在`artifacts/candidates110-historical20-v1/web-*.png`。苹果翻译首次报告语言包缺失，重启后复核返回“你好，世界”；只报告最后可用状态，不推断变化原因或长期稳定性。

## 内容结果：旧问题仍然存在

这次实现不等于已经解决经验过强的问题。人工检查了20题生成标准、20题Critic候选的适用范围与核心方法，并重点核对了使用指南、选择理由及以下案例：

- `da0103c8`短讨论回复仍被要求延续输入者的呼吸动作；`3dcca89b`仍要求先声明实体不确定性；`2e3dd77b`仍要求首先指出术语疑似错误。它们延续了已有的“把经验条件当事实／加任务外义务”问题。
- `605c1c30`的Generator标准直接问“是否作出了肯定事实断言”，满足它反而可能是坏行为，暴露标准布尔方向问题。程序不能仅靠JSON检查判定语义正确。
- Selector在`3dcca89b`拒选全部经验，但在`2e3dd77b`的理由中仍自行断定术语缺少公认定义。这两次现象不能推成整体改进；Selector与Generator是固定输入独立复测，没有把新Selector输出接到Generator。
- 新Critic候选也可能过强：术语定义要求严格禁止操作步骤，历史冲突案例要求必须实质终结冲突；角色反应的指南中仍有来源专名Brevon和举例。这是新提出的候选，尚未经过即时准入与后续效果验证，不能称作已可靠经验。
- v2的20次Critic都输出2条候选。这里只记录数量，不据此断言它们都必要、原子或有效。

因此没有语义通过率、整体准确率提升或速度提升结论。模型解释不是标准答案；有用检查、额外义务与事实判断仍可能混杂。新机制提供了下游检验和按效果选择的执行基础，能否减少坏经验的实际选择与使用，必须在新经验池和新任务上另行检验。
