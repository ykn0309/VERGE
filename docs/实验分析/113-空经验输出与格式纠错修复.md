# 空经验输出与格式纠错修复

2026-11-09。**修复已完成；20个不同任务的22份Generator输入，修复前失败4份，修复后0份。**这是输出协议复测，没有恢复暂停的100题训练，也没有运行Judge或评估最终正确率。

## 改了什么

- 提示明确：`experiences=[]`时，`experience_usage`及每条标准的`source_experiences`都必须为`[]`，不另写“没有经验”的占位记录。
- Generator纠错反馈使用当前输入：空经验直接给出上述结构；有经验列明唯一允许的短编号，要求逐条覆盖、引用与used一致。重试预算仍为2次，不清除非法输出来冒充成功。
- 严格校验不变；空经验说明增加明确的错误信息。不存在的ID和非法引用仍拒绝，耗尽记录路径错误并继续其他样本。
- 所有角色的提示词源码按语义拆成多行；除Generator字段约束外，其余实际提示文本保持不变。修改入口为`verge/prompts.py`与`verge/modules.py`。

## 固定输入和结果

冻结13份历史失败的空经验输入、6份正常空经验输入、3份实际提供经验输入，共22份、20个不同任务。其中两题同时保留有／无经验输入，不算额外独立任务。两版使用同一批输入、Qwen3.5-Flash、关闭思考、相同重试预算，修复前后代码快照分开运行。协议见[计划113](../plans/113-空经验输出与格式纠错修复.md)。

## 内容审查与限制

主代理逐项阅读了22份修复输出及任务，并查看对应基线；完整观察保存于`content_review.json`，不把人工观察称为可靠真值或计算“语义准确率”。

- 病房反馈摘要保留了100词、仅用原文、主题加粗及无法总结时的固定回复要求；赛事题保留了第30位出场和获胜要求。有经验输入的真实ID和使用说明也仍一致。
- 旧的内容问题仍在：`Chloe Warm`仍被套入角色扮演和初期关系，且出现违规时判true的问题；`Serb Armenians`仍由主体聚焦经验占满权重。
- 正常任务也有风险：Monika故事遗漏明确的对话要求；26标题逐项判断被压成单个因果判断；Merlin故事修复版加入了与任务内容冲突的禁令，基线此次有更具体的叙事核验。单次独立生成无法确定差异是否由本次提示引起，但不能称为内容保持或内容改善。

本次采用的是明确空输出及有限纠错的接口修复，**没有解决经验误用、任务覆盖或Boolean方向问题**。不据此宣布方法有效，不改原经验池，不恢复旧运行。
