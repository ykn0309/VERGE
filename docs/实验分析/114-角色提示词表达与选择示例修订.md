# 角色提示词表达与选择示例修订

2026-11-09。按用户要求改写表达、补全Selector示例，**不改变方法流程，也不宣称效果提升**。

## 修改

`verge/prompts.py`的四个`_GUIDANCE`改成自然连贯的多段文字，依次说明职责、判断依据和边界。保留既有约束，包括可不选经验、经验不等于任务事实、正向Boolean标准、Critic直接提案与通用性要求。

Selector原示例只有两个空数组，看不到选中后的说明结构。现在展示一条完整记录，`selected_experience_ids`中的编号与`selection_reasons[].experience_id`一致，说明使用`reason`字段；同时明确可返回两个空数组，不要求照示例选择。实际发送时，示例编号取自本次候选，不引入候选外的编号；无候选或选择上限为0时，示例也为空数组。模板按请求复制，不共享可变数据。

这些改动不放宽校验、不增加重试次数。上轮13条无经验路径失败来自Generator，不能追溯归因于Selector示例。

## 内容检查

主代理检查了要求覆盖，并抽查实际输出与任务，具体记录在`content_review.json`。格式与说明变完整不等于方法正确：

- Selector仍将`low nefa`当疑似拼写错误，短回复也会被当成要延续感官体验；理由完整仍可能在为错误前提作解释。
- Generator仍有强制先声明术语存疑、强制角色标签、把所有角色缩成主要角色的情况。
- Critic仍会输出带具体例子、过强要求或依赖候选回答的适用条件，不能认为连贯表达就消除了旧问题。
- Judge使用的是固定历史Rubric，其中有坏标准；不能把它按坏标准判false一概当成Judge误判。

因此只完成文案和示例修订，没有独立证据证明语义或整体准确率改善。原100题实验继续停在53题。
