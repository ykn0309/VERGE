# WebUI可观测性与聚类浏览

2026-11-09。直接重做现有WebUI，仍只读、本机监听，无外部框架或字体；不修改模型方法，不启动新实验。

## 页面

- **运行总览**：提交进度、初始路径结果、技术失败、准入、请求与重试；有无经验比较可切换“全部提供经验”及“实际引用”，数字与筛选使用同一口径。
- **单题追踪**：初始经验选择、两路Generator及Judge之后，每轮独立展示Critic提案→候选Generator→候选Judge；候选标准、逐项依据、分数与准入分别对应当前轮次和候选。原始调用入口独立保留。支持搜索、筛选、直达及苹果翻译。样本列表按用户后续要求不显示task正文（正文留在右侧），以序号和短ID标识。基线（无经验）与已有经验路径并排显示；保留选中／引用数量和配对结果，每条Critic候选用一行显示轮次、判对／判错／技术失败、实际引用及准入，提案失败单列。减少留白与重复说明，保持紧凑。候选通过不覆盖初始路径结果，尚未执行或无法确认的信息明确单列。
- **经验池**：经验正文、来源验证、下游使用、任务组收益，能跳转具体轨迹。
- **任务与经验分组**：组数、单成员组、成员、引用关系、关联组、聚类参数；按任务组查看各条经验参与收益。经验组明确只作分析，不参与排序、不合并正文。

正文、理由和原始消息提高字号与行距，减少重复导航说明。长表局部滚动，技术细节折叠，状态同时有文字；自动刷新及样本切换保留列表滚动位置；实测滚到2800像素后连续切换两题，列表均保持2800，右侧内容正确更新。

## 原始输入输出

单题第5项“原始输入／输出”自动按需读取本题日志。每次调用展示模型、HTTP状态、传输尝试、格式尝试、两侧Judge标记和耗时；输入按原顺序显示system/user/assistant完整消息，回复保留原文换行，不截断日志内容。另行折叠展示解析JSON及完整日志（含输入JSON、编号映射、校验和耗时记录）。失败和重试保留，不能用解析结果伪装原文。

日志未保存回复时明确显示缺失。嵌入调用展示保存的文本输入和返回向量，旧日志没有完整HTTP响应；整个页面也不声称展示完整HTTP报文。读取有既有大小／条数上限，跳过／缺失会显示警告。尚未返回调用不一定已写日志，观测API只报告已保存调用，不推测精确实时阶段。

## 轮次与阶段

按日志实际轮次生成导航，未运行Critic的任务不虚构轮次。每轮有独立的提案、生成、评判入口，候选选择只包含本轮；从候选卡可直达标准或Judge。轮次与候选进入URL，刷新和历史导航保留对应关系。未准入经验在标准引用处显示候选编号，不错误跳到经验池第一条。生成阶段只展示标准及使用说明，Judge阶段展示判断、理由与得分；标准已生成但Judge失败时，两阶段分别显示成功／失败。

真实浏览器核对同一任务第1轮1条候选、第2轮2条候选，切换后分析、标准与Judge依据和保存轨迹一致；原有候选直达链接能恢复正确轮次，刷新保留候选。Node增加`test_web_trace.mjs`检查轮次顺序、失败轮次、旧候选隔离与直达恢复。
