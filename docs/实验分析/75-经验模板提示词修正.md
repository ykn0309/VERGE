# 75 — 经验模板提示词修正与单候选复测

用户要求修正空模板引导，并后续确认Critic每轮0或1条候选。本轮只修改方法提示词、候选数量限制及对应配置/文档；不重跑30题，不改变其日志或经验池，不执行Generator/Judge应用验证或概率标注。

## 修改

- Critic/Updater共用方法说明由反复展示null/{}，改为一条完整原创单位换算Boolean核验模板，parameters按参数名嵌套description/source；另给出不应强造模板的礼貌要求排除例。示例独立编写，不提取或改写数据集案例。
- 明确模板不是答题文本、固定台词或只有占位符的答案模板；可稳定表达核验问题且task可绑定时提供模板，不强制全部模板化；允许无参固定核验问题。
- 补清JSON null不能写成字符串；只定义参数、不输出当前绑定值，不把回答行为、待判结果或臆测约束作为task参数。
- Critic每轮0或1条，LLMCritic、装配默认、CLI及全部随附配置max_candidates=1，配置和构造器拒绝更大值；输出多条走有限纠错。最多两轮、候选净正向资格、第二轮优先/第一轮回退不变，同题最多入池一条。Updater仍Keep/Revise一条。

旧版区别：V1 Critic草稿0或1条→Atomizer可拆多条；删除Atomizer后的V2此前直接0至5条。本次收紧为直接0或1条，不恢复Atomizer。

### 语义抽查

- Critic-10的计数模板将目标数量/对象类型取自任务，结构清楚；Critic-06的句数上下限来自task明确条目，具有可核验来源。未运行Generator，不能称已完成真实绑定验证。
- Critic-17错误地将“task中不存在的相关领域概念”列作参数来源；这违背提示词，无法提供task原文绑定。
- Critic-19将角色行为、台词和特质都作为参数，来源依赖隐含知识/常识推导，仍有把待判断内容塞进参数的风险。
- Critic-07仍把“使用例子”强化为必须出现公司名/事件名，模板有形式不代表该要求合理。
- 原第29题最终无候选且结构通过，不代表原问题已修复或模板提高了效果；其分析将问题与“单位换算等可模板化问题”对比，仍可见被格式示例锚定的风险。

这次解决了示例只有空值及参数嵌套说明缺失，模板开始正常出现；没有解决所有无依据规则、样本细节和参数可绑定性问题。不继续无限改提示词，不新增验证角色，不修改当前可选模板机制。
