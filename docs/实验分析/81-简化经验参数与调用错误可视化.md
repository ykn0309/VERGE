## 调用状态

原问题是：HTTP返回合法JSON后，角色字段校验才发现错误；旧日志仍只有HTTP200与模型回复。因此Web错误标识看不到这层失败。

现在每次角色请求分配call_id，模型事件与追加的contract_validation事件通过ID关联。结构校验事件保存valid/invalid、错误及纠错轮次。Model解码错误包含字段路径，例如`Criterion: bindings: expected a dictionary`，而非只报`Criterion: expected a dictionary`。

Web将校验结果合并到对应调用，折叠列表直接显示“请求失败”“结构校验失败”“校验通过”与错误摘要，展开可看完整错误及实际输入/回复。历史日志没有校验事件时，只从已保存的下一轮validation_feedback及对应候选轮次终结错误补充可确认的失败；其余显示“模型已返回”，不冒充已通过校验。日志本身不改写。校验事件不计为额外模型请求。
