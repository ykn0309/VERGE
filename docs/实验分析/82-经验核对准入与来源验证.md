# 82 — 经验核对准入与来源验证

设计方案先更新，实现随后完成：Experience Checker决定候选准入，Critic重提只接收其报告；通过即入池，再用全新task+C会话生成/Judge，并运行三个执行Checker记录来源验证。应用失败不撤销入池，也不把应用结果反馈给Critic。无真实完整训练、参数估计或held-out运行。

## 实现

- 新ExperienceReview仅approved布尔值和简短reason。合理性、原子性、可复用性、无必要的本题细节及参数可绑定性由核对器检查；明确缺陷才拒绝，不因场景限定、无模板或措辞不完美拒绝。
- 每轮Critic0/1候选，最多两轮；拒绝才进入下一轮，初始轨迹固定，真实消息接续。无候选则结束。技术/格式纠错耗尽单独记candidate_review_failed，不伪造拒绝原因、不额外无穷重试。
- 通过后保存来源sample和admission_review，立即激活。新Generator仅task+C，不传E、旧标准或旧候选。应用失败记录source_validation_failed，经验仍在池。整体失败/同判/未引用都不撤销；不再采用按两轮应用净正向择优回退的旧准入机制。
- 首次应用为source_validation。引用后照常运行三个执行Checker，满足有效F/明确O/可用参数时更新Q；未引用/无有效结果/O未知/参数不可用仍跳过。来源只入账一次，不计独立下游任务；参数重估保留其首次证据并按task去重。
- 参数metadata要求admission_protocol=experience_checker_v1，旧净正向准入先验被拒绝。项目仍无实际可用概率表，不能声称真实Q已校准或真实更新已验证。
- 新Memory13、Trajectory/Manifest15、提示词v12。旧13/14实验仅Web只读显示，不用于训练恢复。Web显示核对结果、入池理由、来源验证及其执行Checker，调用记录支持新角色。审计按来源/下游分开统计。

## 测试

223项离线测试通过，含Web DOM与新核对结果展示。覆盖：

- 拒绝后只有核对器报告进入下一轮Critic，应用前不调用Generator；通过后停止提案循环。
- 正向、反向、tie均可成为来源Q证据；未知O不更新；来源不计下游；重复来源/来源别名与参数重估不重复记账。
- 未引用、整体失败和Generator技术失败仍保留入池经验；核对器技术失败不入池且不生成伪内容反馈。
- 冻结评价不调用Critic或新核对器；旧先验协议拒绝、轨迹与Memory往返保留review。
- HTTP后端与CLI显式注册新角色。

Q变化测试使用明确标注的虚构单元测试参数，不是参数估计实验。

## 独立真实复测

Qwen3.5-Flash，enable_thinking=false，有限格式纠错及请求重试；每模块20个不同历史真实任务。新输出不反馈其他角色或案例，不写经验池。

| 角色 | 输入 | 最终结构有效 |
|---|---|---:|
| Critic | 计划81冻结的20条历史首轮失败输入，保留其既有转换说明 | 20/20 |
| Experience Checker | 旧真实轨迹中首个候选非空、标准至多单来源的20个不同任务；候选content→principle、缺少可选模板时null/{}，任务/回答及Judge等保留 | 20/20 |

Critic21次模型调用（1次占位符/参数定义错误后纠正）；核对器20次调用，8通过、12拒绝。准入通过率不是准确率，没有独立人工真值。Critic真实复测只覆盖首轮；接收新核对反馈后的重提由离线流程测试覆盖，尚未用真实LLM完整串联验证。

首轮复测发现新角色未注册到真实传输后端，程序fail-fast；当时Critic20题已完成，经验核对器尚未发出HTTP请求。修正注册、增加回归后，仅在新目录补跑核对器20题，没有重跑已完成Critic或掩盖该错误。代码快照分别保留实际两个阶段。

### 语义抽查与边界

核对器第12题拒绝理由称候选硬编码了“7页、25页、人名”，但候选实际写的是“X页、Y秒”，这些具体细节来自案例而非候选正文。这是明确的错误归属风险；第5题通过理由又同时写“引入任务外强制要求”，说明approved/reason的语义一致性也不能由格式通过保证。没有根据这20题继续调严或反复改提示词，避免把未标注的拒绝数量当效果。

来源验证使用经验产生时已见过的案例，必须标明证据来源，不等同于后续泛化验证。概率参数未来需要按新准入群体及来源/下游证据口径估计，不能自动保证可靠归因。
