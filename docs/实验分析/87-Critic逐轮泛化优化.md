# 87 — Critic逐轮泛化优化

## 结果与采用决定

采用`verge-v2-critic-generalization-23`。最终版在固定20个真实历史任务上运行两次，共40条候选，本助手逐题审阅未发现举例、原题专名/固定数值/原句/具体剧情残留；方法仍表达可执行的核验关系，没有靠全部不提案过关。这是本组输入上的观察，不是线上零泄露保证，也不是经验内容正确率或独立泛化验证。

修改仅涉及Critic指导与消息末尾提醒，经验核对器和其余角色未变。保留0–1条候选、现有analysis、样本内真实消息及最多两轮提案。未新增模型调用、过滤器、语义硬校验、限长硬校验或内容重写后处理，Memory14、Trajectory/Manifest16不变。

## 固定输入与执行

每轮固定计划84同样20个按任务去重的真实输入：15个首次失败任务、5个首次成功边界任务；保留完整任务/回答/rubric/Judge，不截断或改写原文。成功题是边界复测，不声称历史上在这些成功题调用过Critic。

模型Qwen3.5-Flash，enable_thinking=false；案例并发4，网络最多重试2次、格式最多纠错2次。8轮修改、2轮重复确认，总计200项Critic角色调用与200次HTTP请求，均最终结构有效，未出现合同纠错或网络重试。重复调用只有20个不同任务，不是200个独立任务。各轮输出不进入其他模块或经验池；没有完整流水线、Checker、参数估计或held-out调用。

开始前与结束后均校验冻结输入、原输出及原运行Memory/Trajectory/role_io的SHA256不变。各轮独立新目录保存提示词、代码快照、输入、原始请求/回复、用量、结果、错误与人工编写的逐题审阅意见。

## 验收口径

1. analysis可以引用原题；trigger/principle不举例，不保留专名、固定数字、原句、独特情节或改名版本。
2. 不是删掉名字就算抽象。保留原故事走向或对方法无用的题材细节，仍记需继续抽象。
3. 可以保留方法必要的任务类型与边界，不要求一条方法适用所有任务。普通对象类别不是自动判定泄露的禁词，按它对核验动作的必要性审查。
4. 经验必须让Generator知道核验哪种关系，不接受只剩“保证准确完整”的口号，不靠全部不提案通过。
5. 此轮优先改进写法的泛化，允许内容有噪声；诊断误读、过强要求、适用性和原子性风险仍逐题记录，不能把它们混入“内容全部正确”的结论。

语义审阅均由本助手完成，未委托独立标注模型，不是校准真值。词语扫描仅辅助统计，识别“如/例如”不等于识别全部举例，不能代替逐题语义审阅。专业领域外部事实未另行核验。

## 最终版改了什么

- 明确写的是可复用的rubric设计方法，不是给本题重新出一条标准。trigger说明何时需要核验，principle说明核验关系。
- 系统提示以独立编写的方法展示抽象粒度，涉及按规则筛选、阶段转换和测量前提，不从数据集提取或改写示例。
- 本题事实留在analysis；方法不举例、列场景、引用原句或改名复述故事。
- 长轨迹之后再次附加简短的输出提醒，避免要求只放在上下文前部。该提醒是同一次Critic输入的一部分，不是另一次模型调用；第二轮及有限结构纠错也会附加。
- 采用版仍先analysis后candidates，没有保留R5的候选优先顺序。

R8同时改变指导语言、方法表述和示范，属于提示词组合优化。不能从这组顺序试验断言某一条提醒或英文指导单独产生了改善，也不能认定换成英文总是更好。

## 实际候选的变化

早期输出保留“世界异常、机械重复预设台词”的具体剧情。R8对应候选为：

> trigger：任务要求按阶段改变行为模式
>
> principle：设计标准时核验初始阶段是否满足正常状态条件，并确认后续阶段变化是否符合指定的突变触发机制。

重复确认中的对应候选为：

> trigger：任务要求展现主体对异常状态的渐进认知
>
> principle：设计标准时核验叙述是否呈现从常态到异常的连续演变阶段，且后续状态需与前序状态形成逻辑递进而非突变。

两次均不再保留特定角色、游戏世界、预设台词或本题例子；保留的是变化过程与前后阶段关系。第二条仍有认知变化这一任务类型，属于适用边界，不要求抹去所有任务类型。两条对“突变”的要求不同，说明经验内容仍有噪声：抽象达标不证明方法正确或一致。

其他最终候选：

- 指定时间与来源的一致性：核验结论是否匹配指定时间范围内的事实依据，不再写具体州、年份和数值。
- 多阶段结构与总量：核验各部分与总量约束是否一致，不再举广播片段和商业广告。
- 现实属性核验：核验关键属性是否具备现实存在性，不再举原回答中液体遇火产生火花的现象。

## 尚存的内容问题

逐题审阅仍发现：把代写回复误作模型自述；沿用错误字数估计；把未显式重述背景当作遗漏；把续写错误地视为必须复述原句；部分标准中多个核验要求捆绑；有trigger依赖未来已生成回答。最终版两轮均全部提案，说明“不需要经验时不提案”也未被本次优化证明改善。

这些问题没有隐藏，也不因没有例子而宣称经验合理。但按照用户本轮优先级，不以要求经验绝对正确为前提增加更复杂的流程。没有自动修改经验核对器、采用后处理删除案例词、重新筛选最优候选或跑完整链路。
