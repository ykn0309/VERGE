# 延迟归纳与正负案例独立复测

实现已完成：Beta初始值/累计公式保持；同判按标准额度25%计负信用，反向按完整额度；取消拆分及父子信用分配。正负案例共同收集，每3个不同下游任务归纳，成功后重计；第10个案例强制最后尝试、之后只记信用。归纳只输出content/trigger，原文使用版本和更新历史保留。

程序验证301项通过，覆盖窗口、去重、三种信用、失败续试、强制最后调用、冻结、候选精确资格、HTTP输出及前端渲染。Manifest/Trajectory7、Memory5；旧协议拒绝，原产物保留，不跨协议resume。AGENTS未修改。

## 实验范围

20个不同历史目标任务：8正向、8负向、4同判应用。每组使用该经验在目标事件之前已有的真实有限案例，并加入目标任务的实际R0标准/两答/Judge，不输入未来案例；案例原文、回答及Judge理由完整保留，旧使用文本不同则明确展示。多数来源是叙事任务，另含交互游戏、实体歧义、数学、标志描述及短视频脚本，不能代表所有任务分布。

目标是归纳模块独立复测，不运行Selector/Generator/Judge/Critic或主流水线。新旧版本输入完全相同，显式转换包括补feedback方向、删除数值字段及短编号；输出只留各组，不更新池、信用或其他组。对照旧生产归纳system与新system，并分别按旧分组协议和新单条协议验证；这是协议及提示词共同变更，不能归因为单个提示词句子。

输入集合保留历史窗口，含2–5个案例，并非新主流程累计3个下游任务后的真实运行输入。窗口时机与冻结由程序测试验证；本次不能证明延迟归纳的下游收益、10条饱和后的长期表现、完整准确率或最终好坏经验分化。
