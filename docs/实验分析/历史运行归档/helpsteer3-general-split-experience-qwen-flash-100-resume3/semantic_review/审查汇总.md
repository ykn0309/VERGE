# 六条多案例经验与27次拆分的语义审查

2026-10-13。按用户要求指定三个`gpt-6-luna`子代理，分别审查六条多案例经验、第1–14次拆分和第15–27次拆分。主代理复核关键证据并要求修订词面/语义混淆、开篇要求、信用计算及外部事实边界。没有修改核心代码、提示词、原始轨迹、Memory或信用。

这是一轮模型辅助定性审查，不是人工金标、外部事实核验或因果实验。下述“支持”指案例对规则有较直接的证据，不证明其在未来任务有效；“部分支持”指仅支持部分子句、适用场景或正确应用正例。

## 拆分

27次原始拆分的审查结果：10次有合理分化依据、16次无需拆分、1次不确定。这些分类是语义判断，不是下游收益估计。

- 无需拆分的典型：第25次把“匹配动作与角色，避免张冠李戴”拆成另一条“剧本中行为归属正确主体”。角色身份、动作、语言等都可以按同一主体—属性关系核验；新场景并不自动产生新方法。
- 有合理分化依据的典型：第16次新创作的故事完整性与对给定故事的忠实摘要。两者证据来源、容许的新增内容及核验动作有区别，可分别检索。合理分化不等于两个子经验的所有文本规则都正确。
- 需要保留的不确定性：第26次跨作品实体核验与真实历史物品出处核验，既共享来源/存在性原则，又可能需要不同证据规则；当前案例不足以决定独立经验是否必要。

额外发现：第21次“England、两段”的任务被Generator加入“19世纪”要求，Judge接受并产生正信用；归纳员因此学习到任务没有要求的历史边界。原飞船故事明确要求从坠毁开场，而“背景可分散呈现”的子经验删除了“除非任务明确指定开篇方式”的原边界。两例均说明正确分组与信用守恒不保证方法文本正确。

## 原因及拟议修改（尚未实施）

1. **拆分条件太宽。** 实际提示词允许“两种不同方法或适用边界”拆分，使模型容易按场景/术语分组。应先比较核验动作，而非场景标签；同一动作的对象、参数、格式变化优先归纳为一条。
2. **经验引用不是方法落实证明。** “核验故事起承转合”的已有经验在后续被引用到“解释作者想完结却拖延的动机”标准，该标准获得P=0.3。归纳输入因此包含不同方法的局部正向案例。应在同一归纳调用内先核对相关标准实际实施了经验哪部分；只引用、Judge错误或遗漏其他要求不自动成为新方法证据。
3. **当前输出没有决定依据。** 实际结构只有`experiences`，程序检查一/两条、非空及案例恰好分配一次，没有可追溯的归纳/拆分理由。可新增私有`analysis`记录各案例核验动作、共同方法、必要差异与为何单条不能覆盖；不向Generator公开。

建议同一次归纳调用按以下顺序处理：逐案核实证据 → 先尝试一条清晰共同方法 → 只有实质不同核验动作/证据规则，且单条表达会丢失必要边界或堆成不同方法列表，才拆分；证据不确定默认不拆。并非必须存在逻辑矛盾才允许分化，独立方法也可以合理拆分。

输入保持当前精简卡片，模型调用次数不增加；保留最多两条、单案例分组合法、全部案例唯一归属、150/60字符只提示词、10案例冻结及既有P/N继承规则。不恢复MERGE或Admission，不引入外部核验。若实现新增analysis，需更新角色输出契约、有限结构纠错及归纳历史审计；程序只能检查结构，不能保证拆分理由在语义上正确。
