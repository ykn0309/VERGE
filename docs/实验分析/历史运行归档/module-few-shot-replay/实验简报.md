# 五角色原创few-shot独立复测

2026-10-13。用户授权分工给子代理，使用过去运行的模块问题输入做独立小规模测试。结论：原创few-shot可改变局部行为，但本轮没有观察到稳定改善，各角色都有残留问题或退化，暂不加入生产提示词。

## 分工与范围

三个子代理分别负责Updater、Generator、Selector/Judge/Critic的独立构造示例、历史输入选择、真实调用及语义复核；主代理负责通用工具、示例契约检查、历史消息/源哈希审计、关键输出复核及汇总。教学示例使用虚构设备、盘点、数据操作等内容，独立编写，不从数据集提取或改写。

每例分别用当前baseline和追加2–3个原创few-shot调用一次。Updater发生一次有限结构纠错；Judge两次ReadTimeout在原API重试预算内恢复。34份输出均结构合法，不代表事实或方法正确。292项离线测试通过。

固定Qwen3.5-Flash、enable_thinking:false及原30秒超时/2次API重试；仅调用目标模块，未运行完整流水线、Judge配套评估Generator或训练/held-out。源manifest、Memory、轨迹及role_io哈希保持不变，新输出不写回原经验池、信用或后续案例。

从原100条运行提取实际成功请求，保留完整输入与真实Critic历史；除system更换为当前baseline或追加few-shot外，其他实际消息保持一致。旧Updater长案例ID明确转为计划51的短编号，两变体同样转换；不做输入摘要或截断。selection.json保存一基trace_line及问题/核验要点，各目录results保留完整新旧输入输出、真实消息、原始回复、模型配置和错误。核验见[audit_summary.json](audit_summary.json)。

## 语义观察

|角色|局部改善|仍存在或新增的问题|取舍|
|---|---|---|---|
|Updater|第06组近似方法拆分改为一条；第16组摘要方法更强调准确复述|第21组无依据历史时代方法更强；第25组原本共同角色归属方法被错误Judge证据带成两条|不直接采用|
|Generator|England案例移除无依据19世纪要求|仍强制具体场景并挂名引用；原11人覆盖被缩至首镇4人；角色比较无核验断言实体不存在；正常方法建议的可操作性弱化|不直接采用|
|Selector|两变体均修正一次情感经验误选；正常空选保留|人物抽取仍选创作背景经验；few-shot还少选潜在适用关系方法，少选不是改善证据|不直接采用|
|Judge|条件化语义案例两变体均较稳定|人数理由仍写10但列11；baseline同一reason自称应true却输出false。其他判断仍误读回答中表现出现的时间或忽略事件前提|不直接采用|
|Critic|第二轮few-shot的trigger更能从task识别|首轮把实际Judge第4项chosen=false误读成true；另一例强制A/B关系有风险，trigger又依赖观察回答|不直接采用|

“正常例”只是相对正常行为参照，旧Judge或诊断仍可能有错，不视为金标。第16组本轮baseline也已重新保留摘要分组，不能拿其few-shot与上次27组旧结果的差异都算成示例收益。Critic视频风险例的原文确有回应读写问题不足的线索，不能仅因从空候选变非空就认定错误；但新方法强制构建A/B关系及观察回答的trigger并不可靠。

## 示例自身的限制

主代理审查发现Selector示例要求提取“故障编号”，记录却只有故障名称，表达不严谨；Judge示例将“共两件”与三个列举并存，true输出可能教模型直接替Generator纠正标准，混淆核验职责。两角色已开始真实调用，故保持输入冻结，没有修改后偷偷重跑；这两点也使当前示例不适合直接上线。Critic示例在启动前已补齐2条标准及一致的权重/两侧判断，符合现有生产标准数量契约。

## 后续方向

先完善示例自身一致性及角色职责边界，再决定是否更换示例和开展另一轮有限复测。当前主要观察是任务覆盖、引用落实、Judge事实和Critic轨迹读取仍未可靠，不能仅靠few-shot数量增加推断会改善。Updater仍可能把不可靠引用证据带进方法，这次不增加案例过滤、信用撤销、分析字段或额外验收调用。

旧文本锚定只是待验证假设，本次没有去掉旧文本或改其顺序，不能宣称证实。每变体每例一次、选例有限，这些结果仅支持暂不采用当前候选示例，不能证明few-shot普遍无效，也不估计整体准确率、下游泛化或因果收益。
