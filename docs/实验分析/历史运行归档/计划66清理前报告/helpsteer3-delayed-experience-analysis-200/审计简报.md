# 新版200题：机制、经验质量与置信度审计

结论：新机制按预期执行，纠错链路有实际救回样本的能力，也出现了合理方法升分、过强规则降分的例子。但本次尚未形成稳定的“好的经验高置信度、坏的经验低置信度”。关键障碍是：信用同时反映经验内容、检索适用性、Generator如何应用以及Judge判断；一条经验中的不同规则也可能得到不一致的验证。

## 范围与证据

来源为 `../helpsteer3-general-delayed-experience-qwen-flash-200-resume5/`，使用现有200题账本重建审计及当前真实轨迹，不调用模型、不重跑流水线、不改经验池。查看全部31条当前经验及相关文本版本；先记录不看置信度的文本问题，再计算信用演变。另完整阅读24个不同任务的原始任务、chosen/rejected及引用标准、Judge布尔值与理由：37、51、57、66、73、90、101、109、110、111、114、133、135、137、139、145、148、160、161、174、183、187、194、198。

这些是针对适用错误、规则混杂、正负反馈和创作边界选取的诊断案例，不是随机质量估计。文本初判保存在 `text_review_before_scores.json`，其中 plausible/flawed/mixed 是初步方法判断，不是已经建立的经验好坏金标准；例如66题的logo前缀存在任务解释空间，不能单靠初判断定整条经验错误。本审计不核验外部作品事实或课程是否真实，不把Judge理由当独立事实证明。

`semantic_cards.json` 保存所读24题完整原文和引用依据；`confidence_evolution.json` 给出每条经验、每次信用事件的前后置信度；`feedback_channels.json` 区分同判与反向信用。经验编号1–31对应最终经验池的顺序，文件中保留完整ID以追踪。

## 新机制的实际表现

| 机制 | 观察 | 可以得出的结论 |
|---|---|---|
| 同判计轻负信用 | R0引用标准333项：正确区分86、反向23、同判224；同判产生15.400信用，反向产生5.905信用 | 过去无数值反馈的应用现在确实受罚；下游负信用约72.3%来自同判 |
| 每3个下游任务归纳 | 13条经验共31次归纳，案例数4/7/10对应13/10/8次 | 调用时机符合设计，文本可先接受多次反馈；本次没有“每次使用都改写” |
| 正负案例共同归纳 | 收录109条下游案例：28净正、80净负、1平局；其中68条纯同判 | 负反馈进入了归纳，且大量是“本次无区分力”，不能统称经验内容有错 |
| 取消拆分 | 始终31条独立经验，无子经验或退役父经验 | 避免拆分造成的数量扩张与信用分配复杂度；不能由此证明文本更正确 |
| 短文本约束 | 31次归纳输出正文最长73字符、trigger最长32字符 | 已归纳经验明显压缩；18条未归纳经验中仍有10条正文超过150字符，约束没有统一约束候选生成 |
| 10案例冻结 | 8条冻结，之后169次信用事件继续计分，未再归纳 | 文本与信用冻结边界正确；一些方法在第48/74/84题即冻结，之后的新证据只能影响分数 |

负案例的加入是否改善归纳内容，证据较弱。例如经验22在第198题更新后以could/would描述假设性质，保留了合理的创作与事实区分；但没有不提供负案例的对照，不能认定改动由负案例造成。反例是经验14：经历三次含负信用的归纳后，仍保留“情绪必须有生理或视觉细节”；经验16也仍把首句人物指定为优先对象。输入包含负反馈，不等于模型必然纠正过强规则。

本次31条新候选入池时所在样本均为application_success，因此“自身P>N但整体失败也允许入池”的放宽规则没有出现可观察入池实例，不能声称它改善了本次结果。

## 整个方法的效果

200题初始判断110正确（55%），最多两轮纠错后156正确（78%），救回46题；3题Judge错误也计入200题分母。说明当前完整纠错流程能在这些训练题上改善偏好判别。

这不是“经验池提升23个百分点”的实验：初始判断已可能使用已有经验，纠错又同时加入Critic诊断、候选和重新生成，不能把救回全部归因于长期经验学习。没有独立的无经验对照或held-out结果。可以说链路有实用信号，不能说可复用经验已被证明提高新任务表现。

## 好经验是否升分，坏经验是否降分

31条经验中22条得到过新下游信用，9条只有原题证据。相对于入池时：8条升、14条降、9条不变。278次下游信用事件中75次使置信度上升、203次下降；“202净负、1正负平局”与下降203并不矛盾，正负相等也会把原本高于50%的分数拉向50%。原有alpha/beta累计没有发现账本异常。

| 经验 | 入池→最终 | 语义核对结果 |
|---|---:|---|
| 22：区分虚构构想与商业事实 | 57.4%→65.0% | 核心方法合理。198题chosen用could/would构造广告，rejected直接把联名机制写成既定活动，正反馈有原文支持。194题也给正反馈，但两回答都明确说alternative titles，该次部分信用并不可靠 |
| 14：情绪必须用生理/视觉细节 | 52.1%→45.4% | 将一种写作技巧升格为强制要求，适用过宽。114题要动作电影梗概，引用标准却要求心跳/颤抖，两回答都不满足，产生轻负信用；下降方向符合对过强限制的判断 |
| 6：核对角色来源、区分既定能力与虚构技能 | 55.1%→46.0% | 核心方法有合理用途。51题rejected把任务指定TWD的角色写成另一名Power Rangers角色，来源检查可识别。57题任务只有we need space却套用角色能力标准，两回答同判，合理方法也因错误应用被扣分 |
| 16：首句人物优先、次要角色偏差可豁免 | 53.0%→64.5% | 人设连贯性有价值，但“首句人物天然优先”缺少通用依据。最终版本15次下游应用仍获得多次正反馈，许多标准只核验一般角色一致性，并未检验首句优先或次要角色豁免；整条高分不能证明附加规则有效 |

以上不能简化成4条经验分别“绝对好/绝对坏”。每条可能包含合理核心和不合理附加限制，表格的重点是具体规则与实际引用是否一致。尤其经验16的正反馈不是纯粹误判：一般角色连贯标准可能确实区分正确，但它支持的是经验的一部分。

另一个实证例子是经验20。109题任务只要求20条消息、多个用户和一些emote，候选却要求至少5名用户、每条消息都有emote；Judge布尔值将拥有20名用户的rejected记为false，理由又说应该true。随后137题本来问两个which从句，却被套上“至少两种总和表达方式”的多样性标准，得到同判负信用，归纳仍保留量化多样性规则。后续139/181题又通过较合理的多样性标准获得正信用，最终56.0%→62.2%。可以沿这条具体轨迹确认：有问题的起点、负反馈与后续合理应用可以共存；不应据此泛称全系统反复强化错误。

有后续信用的22条也不能全部代表当前文本被充分检验：13条归纳经验中，只有9条最新版本得到过下游反馈，其余4条改写之后尚未再使用。改写前信用保留是设计约定，应解释为累计历史应用信用，不能自动解释成当前每一条规则的验证。

## 当前最值得处理的问题

1. **经验是否用于适合的任务。** 57题的角色能力经验、137题的数量多样性经验都是直接可见的错用。允许噪声并不意味着无关应用的扣分能准确评价经验核心方法；当前分数混入了选择与应用质量。
2. **到底是哪部分方法获得信用。** 同一条经验含多个规则时，Generator引用了合理部分，整条经验升分，未被使用的限制也留在高分文本中。经验16比单纯的Judge偶发误判更值得关注。
3. **负反馈是否改变适用范围或方法。** 本次已证明反馈进了输入，但一些过强要求并未收窄。8条冻结经验后续只能降分，不能再根据新问题修正文案，这是现有调用上限的实际取舍。

不建议据本次结果换模型、加审核角色或修改已确认的累计公式。下一步可优先围绕上述已定位的错用和“只验证部分规则”设计一个小规模模块衔接实验，检查同一方法是否被真正应用，再决定简化经验内容或调整应用契约；无需再盲目搜索更多提示词。接受Judge噪声与这一步不冲突：目标是让已有正负反馈更明确地作用于所要学习的方法。

本报告为只读历史审计，所有原实验产物哈希在生成前后保持一致。没有提交代码、修改置信度或新增模型调用。
