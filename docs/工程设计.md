# VERGE 工程设计

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 方法见[总览](设计方案.md)、[方案14](设计方案/14-原子经验版本演化与局部混合检索.md)及[可靠性](设计方案/11-可靠性更新与噪声证据.md)，验收见[计划68](plans/68-演化信用继承与稳定性惩罚.md)和[报告68](实验分析/68-演化信用继承与稳定性惩罚局部验证.md)。未启动新版完整训练。

## 1. 结构、角色和调用预算

verge源码保持扁平，不引入外部检索服务或数据库。训练单进程顺序执行，冻结评价可有界并发并按固定顺序提交。

角色为Selector、Generator、Judge、Critic、Atomizer、ExperienceUpdater、CategoryOrganizer、CategoryDescriber。没有Admission/Fusion/Reflector或额外原子性审核角色。Atomizer同时处理Critic和Updater草稿，直接输出原子列表；Updater keep不调用Atomizer。

Critic最多两轮，每轮一次草稿、一次原子化处理、一次独立Generator应用；每个角色允许有界格式/结构纠错，不增加业务轮次。Generator固定E，每轮替换完整C；Critic保留真实消息并追加派生原子列表及实际反馈。真实请求数应将纠错与网络重试分别记录，不把每条原子候选变成独立全链路。

## 2. 接口权限

| 对象/角色 | 目标契约 |
|---|---|
| Critic | analysis＋空或一份trigger/content草稿 |
| Atomizer | 只输入草稿及来源类型，单条保留草稿，多条输出各条trigger/content |
| Updater | 当前版本＋5案例，返回keep或revise草稿 |
| Application | candidate集合、逐条采用/P/N/eligible、最终选中轮集合 |
| Experience | 固定文本ID、active/retired、独立先验、信用继承及惩罚/usage/窗口、来源/退役事件 |
| EvolutionRecord | 父子ID、实际5案例、窗口信用量、λ、总惩罚、草稿/原子化结果、keep/replace/split及错误 |
| CategoryOrganizer | 单个目标＋Top10类别，assign/create/unclassified，只改目标归属 |
| CategoryDescriber | 旧name/description及增删成员，输出仅name/description |
| Category | 稳定ID和元数据，无信用，成员由活跃版本归属决定 |

所有对象ID经本次短数字映射，存储保留真实ID。不能用原子化结果覆盖真实Critic assistant消息，不能把CategoryDescriber返回值当成员操作。每条content≤150字符/trigger≤60字符仅提示词约束，不写长度纠错规则。

## 3. 信用、窗口和提交顺序

有效R0在成败分支前按实际版本写入P/N及同判计次。候选阶段E仅审计；正常收尾新候选只计最终选中轮的实际P/N，Beta从(1,1)开始。多来源均分、双通道累计、无折扣，不用净值替代P/N。事件须按版本/任务/阶段去重。

候选过程结束后收集本版本有区分R0案例，P+N>0即可，P=N>0也计一次。同判、来源、祖先案例不占窗口。每5个新任务归纳，输入当前版本最近5条；成功keep消费，失败不消费且同一最新案例不重复尝试，后续新案例到来时使用最近5条有限重试。历史案例/信用不随窗口丢弃，不足5条不在收尾强制归纳。

revise经过Atomizer后若单条完全相同则keep；实际替换/拆分一次Memory提交创建全部子版本、父退役、演化关系、分类队列和父成员移出记录。子版本各有(1,1)先验及空usage/窗口；修订继承全部父P/N和旧惩罚，拆分均分。本次总惩罚D=0.2×最近5案例累计(P+N)，均分加入子beta；keep/同文本/失败不惩罚。实际反馈、继承与惩罚分开记录，证据量排除惩罚，不额外验证。不能部分创建子经验或在本样本给子版本回填R0反馈。

## 4. 输入与故障预算

完整模型请求沿用可配置字节预算（现行默认100000 UTF-8字节），保存实际投影和预算计算。Updater保留完整task/两回答，只提供相关有区分标准、Boolean/reason及方向，不传权重/P/N/无关标准；Atomizer不接收完整案例。Generator不见类别和信用。Selector使用当前版本的confidence/evidence_amount，不使用区分率。

预算超限不静默截断回答或候选。原子化部分结构无效时整次有限纠错，不留下任意前几条。检索分类的相关成员上限是明确输入投影（初始每类3条完整文本），不是溢出后截断；任务Selector仍完整展开，超预算隔离。

候选格式/结构耗尽为无效轮；Judge、拒答、可隔离请求错误结束不做正常候选回退。Updater/Atomizer演化失败保留父及合法信用；分类失败保留该目标归属/队列；描述失败保留已提交成员和旧描述。超时/连接/408/429/5xx等有限重试及输入拒绝隔离沿用计划63；鉴权/配置、数据/存储、Calculator和程序故障fail-fast。

## 5. 混合检索和缓存

类别name/description与各活跃经验trigger/content分别建向量、BM25文档。文档级RRF等权融合，初始k=60；缺失路贡献0，BM25无命中不凭任意排序计分。成员命中映射到类别后取max，先聚合去重再TopK：任务20单位、归类10类别。归类排除目标自身成员命中。

分词、英文归一化、排名并列规则、参数和索引版本持久记录；当前规模可计算全缓存文档排名，不增加近似候选截断损失。退役版本和空类别不可检索，信用改变不重编码；文本不变只换归属时更新映射，类别元数据变更只重建类别文档。Embedding失败不静默换成纯BM25实验条件。

任务命中类别完整展开，Selector最多5个版本；类内成员可能使输入超预算，不能宣称分类局部化已经解决所有上下文增长。两路排名、单位映射、融合得分、候选集合及选择均留审计。

## 6. 局部分类与元数据演化

待分类队列按版本ID去重，默认5条在样本结束处理，训练停止/暂停处理余量。批内稳定顺序，逐项检索Top10后只提交目标归属；后项可见前项新类别和成员映射。创建类别的name/description为初始元数据，已有类别描述在批末更新。

成员加入/移出/退役形成dirty变化，每批每个受影响非空类别至多更新一次描述；信用变化不触发。描述角色只输出name/description，接口白名单禁止成员增删。空类别由程序删除；元数据刷新后供下一批使用，本批不循环归类。

归类失败按目标及候选索引版本去重；描述失败保留dirty变化，按dirty版本去重，有新变化或后续收尾机会再有限重试。同一失败状态不在每题空转。累积变化超预算仍报错，不额外摘要或丢弃。全局自动类别合并/拆分不在首版范围。

## 7. 协议、日志与恢复

Memory、Trajectory、Manifest、method/Prompt须随实现统一升级，当前Memory8、Manifest/Trajectory10。新代码拒绝旧schema和跨方法resume，不编写生产迁移/兼容层，历史输入转换仅用于独立复测并保留来源。

真实请求/回复、结构结果、短编号映射、使用快照、信用、演化、局部分类和描述事件都需持久记录；不记录鉴权头/API key，保留文件权限与样本上下文隔离。Memory读取返回独立副本，检索显式仅active，审计可读取retired。

Memory内演化一次提交不代表Memory与trajectory跨文件事务。resume验证完整有序前缀、配置/代码/提示词/数据一致、无越界状态；不一致须拒绝，不能从头重复记账或静默补造成功。

## 8. 冻结、界面与验收

held-out只检索/选择/R0/Judge，不写任何经验、usage、窗口或类别；只读缓存允许重建。stop_after_train暂停不启动测试，真实LLM基准Qwen3.5-Flash关闭思考。

Web只读、loopback，展示活跃/退役版本、父子关系、本版本信用、5条工作窗口及完整历史、归纳触发任务、类别成员与描述事件。保留类别专页、分类/未分类分区、排序与点击滚动；0证据显示未知，继承分数与本版本实际反馈分开展示。仅改JS/CSS刷新即可，启动/重启遵守实际权限环境并验证苹果翻译。

确定性测试覆盖资格/轮次选择、信用守恒、事件去重、keep/replace/split、窗口/失败、权限、索引与预算、冻结/resume及Web。每个改动模块至少20条真实历史来源独立复测，保留转换、请求、成本和语义检查，不改原产物、不链式应用。完整链路单独授权，局部通过不证明整体收益。本次信用变更以计划68为准；Selector仅同步字段说明，独立20条真实输入复测，不扩大到其他角色或完整训练。
