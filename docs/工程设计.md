# VERGE 工程设计

> **新机制已实现，230项离线测试通过。**分支 `feat/critic-experience-validation` 从 `7ab9bdc` 建立；本轮已获代码实现、旧日志清理与提交授权，未运行付费实验。方法见[总览](设计方案.md)，实施见[计划31](plans/31-Critic候选经验准入与新会话验证.md)。

## 1. 最小结构与范围

保持verge源码扁平、单进程、训练逐样本顺序处理。测试在冻结Memory下有界并发、轨迹按数据顺序提交。不增加服务、独立审核、插件框架或跨文件事务。

```text
Config / Registry → Dataset / Role Backends / Modules
→ Pipeline Runner → Calculator
                 → Experience Memory / Vector Index / Trajectory / Role IO
```

活跃LLM角色只有Selector、Generator、Judge、Critic、Admission、Fusion；同一个Generator角色提供初始生成和独立应用接口，不增设Refiner。新代码移除Reflector、同会话修订、操作/反思遗留协议、来源清空及旧版本展示。

## 2. 业务流程与预算

```text
检索/筛选固定E → R0生成/Judge → R0来源信用 → 回写Memory
R0成功：保存轨迹
R0失败：
  每轮Critic提出候选 → Admission
    首次FAIL：候选与拒绝原因回到Critic，重生成一次
    再次FAIL：结束任务，不应用
    PASS：固定候选 → 新Generator(task+E+C) → Judge
      成功且采用C：Fusion入池
      成功未采用C：任务成功，C未验证，不入池
      失败：有业务预算则更新实际证据进入下一轮
全部路径留档；最多2轮，最多4次Critic业务生成。
```

每轮最多2次Critic业务生成、1次应用生成机会，Admission拒绝重生成和格式/网络/结构纠错分别计数。正常业务通过首轮有效Judge失败进入下一轮；格式耗尽按既有无效轮隔离，可继续剩余业务机会，但不假装Judge失败、不增加额度。准入两次FAIL则立即结束，不能挪用下一轮继续准入。

R0按来源标准的P/N分别累计，在成败分支前立即更新；不再先净抵消，P+N>0即更新。R1/R2的E来源只审计，不重复R0信用。后续失败或角色错误不回滚已写入的R0信用。

## 3. 角色、消息与来源

- Critic看task、偏好对、实际失败rubric/Judge；第二轮附上条通过候选及采用记录，前后证据不重复，不以旧私有analysis代替事实。返回私有analysis与0–1条content/trigger候选。
- Admission只看task和当前候选；PASS仅允许试用。FAIL的被拒候选和具体reason只进入Critic，不能进入Generator。
- 每次应用创建新Generator会话，输入仅task、固定E、本轮已准入C。不输入R0/R1、旧analysis/assistant、偏好对、Judge、Critic私有诊断或普通修订建议。
- E和C自主采用，任务明确约束优先。C不伪造历史confidence，不强制引用；下一轮替换C，不累积旧候选，不重新检索/筛选E。
- 每条criterion保留E/C来源。ID只允许本次输入的局部编号，严格白名单反解、无重复，内部候选ID和经验ID可区分；R0仍仅允许E。
- 移除旧revision_number来源清空，不为历史修订保留分支，不加入全局未知ID绕过。至少一条criterion引用C作为声明采用标记；这是模型自报，不证明因果性。
- 保持analysis/完整criteria、2–8条标准、1–10整数重要性、正向Boolean语义。Judge独立两侧请求和评分机制不变，不支持部分分/否决/自动跳过。
- 角色职责与输出要求局部、简洁，不恢复共享经验定义或通用输出块。不新增采用/泄漏审核模型或语义过滤器。

HTTP数字ID与Fake内部ID都验证结构和引用；原始输出、解析结果及有效轨迹分开保存，不修改真实回复来伪装采用。

## 4. 数据与轨迹

新协议直接定义，不兼容旧字段/schema；最终命名在实施时落实，不要求历史迁移。至少保存：

| 数据 | 必须可核对 |
|---|---|
| 任务与固定E | 当前任务、原始选择投影、R0实际来源 |
| 候选生成 | 应用轮次、生成序号、候选ID及固定content/trigger |
| Critic与Admission | 实际输入输出、私有analysis、decision/reason及对应拒绝反馈 |
| 应用 | 独立会话、实际有效rubric、E/C来源和声明采用标记 |
| Judge/错误 | 真实有效结果，或明确的无效轮/sample_error/judge_error，不造分数 |
| 终止与入池 | 准入耗尽、应用失败、未采用成功、采用成功及Fusion资格 |
| Fusion/证据 | 实际候选、最终经验ID、前后文本版本、来源及新弱证据 |
| 计数 | 业务候选/应用机会与底层请求/结构纠错分别统计 |

E/C来源保存在criterion层；累计信用仍经验级。没有有效输出时采用状态未知，不能默认为未采用或已验证。重生成分配新候选ID，不能覆盖被拒记录。新Rubric无需为旧base_rubric_id兼容；失败上下文引用由轨迹记录，不作为Generator会话继承。

Experience保留content/trigger、alpha/beta、派生confidence、来源、证据与融合文本版本。已有经验R0与候选统一按来源标准计算正向P、负向N，alpha加P、beta加N，不先抵消；双通道全0才不更新。新记录存positive_credit/negative_credit，净方向仅派生展示，强度增P+N；不调用旧margin增益calculate_fusion_credit或保留lambda。

## 5. 有限纠错与错误隔离（沿用既有方式）

| 情况 | 行为 |
|---|---|
| Critic/应用Generator格式或结构纠错耗尽 | 保存无效轮；剩余业务机会内可继续，不全局中止、不造Judge失败 |
| R0生成、Selector、Admission、Fusion角色契约错误/拒答 | 保存sample_error及已完成阶段，继续下一样本 |
| Judge输出耗尽 | 保存judge_error，结束本样本后续步骤，继续下一样本；未知判定不算成功或普通失败 |
| 网络/鉴权/配额、数据/存储/Calculator/未知程序错误 | 按原有全局故障边界抛出，不用宽泛catch吞掉系统错误 |

后端格式重试耗尽不叠加额外格式重试；结构纠错有原有限定上限。技术错误不作为Admission业务FAIL，不能索要新的准入预算或形成虚假的验证证据。错误轨迹计入已处理前缀，R0信用或合法已完成写入保留，不做跨阶段回滚。

输出错误只在指定外部角色阶段隔离。无初始有效判断不更新已有经验信用；无有效应用判断不Fusion。错误计数单列，未知Judge不伪装准确率；沿用既有有效样本指标与未知判定处理原则。

## 6. Memory、索引与审计写盘

Admission PASS但未应用/未采用/未成功的候选仅留轨迹，不能检索。只有PASS+采用标记+有效成功+合法Fusion的同一候选可入池。成功未采用C结束任务，不为验证经验再生成。

ADD以Beta(1,1)为基础；MERGE保留原ID、旧Beta/证据及前后文本。继承证据不认证新扩展。本次候选P/N无折扣追加，R0也改为双通道、不先抵消；任务成功与证据方向分开，不能忽略候选负证据或强行只记正值。向量索引为派生缓存，ADD新增向量，MERGE文本变化使编码缓存失效，可由Memory重建。

Memory写入与完整trajectory不是跨文件原子事务。新机制自身的续跑仍需代码/配置/数据/版本一致、完整有序前缀、Memory只引用已提交任务、未完成任务没有不可撤销写入等既有严格审计，复制到新目录而不覆盖来源。不得把旧检查点迁移到新方法。

真实角色输入、消息、输出、请求元数据与错误写入0600日志，保留原始task/偏好对但不记录鉴权头或API key。样本/线程ContextVar隔离，JSONL写入加锁。Web仅loopback、只读、按需展示新方案，不兼容旧版本、不从结果补造未记录消息。

## 7. 配置、冻结与数据保护

删除无经验诊断及experience_enabled开关，不保留另一个旧修订策略。空池或Selector不选E时，完整新候选学习链仍可执行。旧配置/schema/方法版本直接拒绝，不自动忽略遗留字段或解释成新模式。

保留数据准备的固定版本、provenance、划分/有序前缀和SHA256核验，不覆盖准备好的数据。新实验manifest记录新方法/提示词、模块参数、模型和有效执行边界；新目录启动，不跨方法resume。

训练结束冻结Memory、文本及Beta；held-out只检索/选择、R0生成/Judge，不调用候选/准入/融合、不回写信用，关闭exploration。训练顺序、测试限流并行和轨迹有序提交保持。run.stop_after_train仍限制绝对已处理训练前缀（含错误），暂停不启动测试。

“不兼容旧方案”只表示新代码不为旧运行实现解析、迁移、展示或运行分支，不授权删除main、历史目录、数据、截图或报告。

无折扣正负分别累计及既有工程边界均已确认；字段名等新工程契约由实现落实，不做旧协议迁移。实施已完成离线验收，代码提交已获授权，付费实验另行授权。

## 9. 当前工程协议

- `modules.application`使用`critic_candidate_validation`，`max_rounds`为1–2；每轮一次拒绝重生成固定。结构纠错`invalid_output_retries`为0–3，Critic/应用Generator共用此参数；R0纠错独立记录`initial_output_retries`。
- `CriticProposal(analysis, candidate)`、`ProposalAttempt(round_number, generation_number, analysis, candidate, error)`与`ApplicationAttempt(round_number, candidate_id, rubric, judgment, adopted, adopted_criterion_ids, credit, error)`分别保存候选业务生成及实际应用。
- `Credit(positive_credit, negative_credit)`双通道；EvidenceRecord的`evidence_weight`固定1，类型为`downstream_credit`或`application_credit`。只在P+N>0追加数值记录；零证据Fusion仍保存文本版本。
- Trajectory显式`schema_version: 2`，Memory根对象`schema_version: 2`；manifest为`format_version: 2`及方法`critic_candidate_validation`。不读取旧字段或缺少新版本的检查点。
- 新机制续跑要求实际源码指纹、提示词、配置、数据和有效执行参数一致；仅输出目录与CLI暂停前缀可改变。Memory中的来源/证据不得越过已提交训练前缀，源目录只读。
- 终态区分`application_success`、`success_without_candidate`、`admission_exhausted`、`validation_exhausted`、`invalid_application_exhausted`、`no_candidate`和角色错误。未知采用或Judge不能默认为失败。
