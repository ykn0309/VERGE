# VERGE 工程设计

> 当前以[计划61](plans/61-延迟归纳与正负案例经验更新.md)为准，方法见[总览](设计方案.md)。Manifest/Trajectory7、Memory5；历史产物保留，拒绝跨协议resume。

## 1. 结构与预算

verge源码保持扁平，不新增服务或数据库。训练单进程顺序执行，测试冻结Memory后有界并发、按顺序提交。角色为Selector、Generator、Judge、Critic、ExperienceUpdater；不再有Admission/Fusion模型。

Critic每轮一次0–1条提案，最多两轮；每次应用为全新Generator。格式结构纠错单独有限计数，不增加业务机会。Generator固定E快照，每轮只替换C；Critic保留样本局部真实消息，第二轮追加应用反馈。

## 2. 资格、记账与收尾

R0有效Judge后、成败分支前按已有E来源累计P/N，反向按完整额度计N，同判按25%额度计N，无折扣、不先抵消，alpha+=P、beta+=N。R1/R2 E不重复记账。

候选采用且自身P>N为eligible，使用输入十进制权重的精确比例判断，不凭浮点净值或整体margin。合格先暂存；整体失败可继续第二轮，正常结束只选最新合格候选（C2优先，否则C1）。新候选直接保存原文，新ID、Beta(1,1)追加对应轮次P/N，未选候选留轨迹，不合并信用。

整体任务状态与入池记录独立，整体失败可入池，整体成功可无入池。空候选、无效轮耗尽可正常回退C1；Judge错误或角色拒答的错误结束不入池，有效R0信用保留。基础设施与程序错误fail-fast，不执行伪正常收尾。

## 3. 经验文本归纳

训练R0有实际信用的已有经验，在候选过程结束后收录不同sample_id的正负案例，包含原题最多10条。原题不计窗口，每3个不同下游任务归纳；成功（包括合法保持文本）重置窗口，失败不重置但同一新案例只尝试一次，第10个案例强制最后尝试，随后文本/案例冻结，继续信用。

输入signed_cases_v3：当前content/trigger及全部有限案例，完整task/两回答，只保留引用本经验的标准问题、Judge Boolean/reason及feedback=positive/negative/neutral；同判为较轻负反馈。不传P/N、权重、共享来源数、无关标准、整体分数或私有分析。实际使用文本不同才附applied_experience。不截断回答，不做额外摘要或审核。

Generator的已选经验输入仅保留experience_id/content/trigger，不提供confidence/evidence_amount；当前候选仍明确标注尚未验证。Selector保留可靠性信息用于筛选，Critic保留诊断所需权重、来源、逐项结果/理由及真实多轮历史，Judge仍只接收task/标准/单回答。领域对象、经验信用、轨迹和选中快照继续保留完整数值。

归纳案例标识见[计划51](plans/51-归纳案例短编号.md)：真实模型只见本次短数字案例编号，输出仅content/trigger，不抄案例ID或分组；实际消息预算按投影计算，存储保留真实ID。

所有角色的程序对象标识均经NumberedIDCodec映射为本次局部数字编号：Selector/Generator的经验与候选、Judge的标准、Critic的标准集/标准/来源/前轮候选，以及归纳员的案例。Critic继承已投影的真实消息历史，每条新增反馈使用本条局部编号；输出在领域校验与保存前还原真实ID。Embedding只接收task或经验正文/trigger，不带对象ID；不为隐藏程序标识改写任务和回答原文。

归纳员只返回非空content/trigger；150/60字符仅提示词，不校验长度。保持ID/Beta，文本变化才version+1，保存前后文本、版本、案例IDs及error；取消拆分、父子关系及继承信用分配。历史信用不自动认证新文本，当前样本固定E不变。

完整system/user UTF-8文本预算100,000字节，不静默截断。预算超限、格式/结构耗尽或归纳拒答保留旧文本、合法信用与已收录案例并记错误；网络/鉴权、存储、Calculator和程序错误fail-fast。预算控制不保证任意提供商上下文一定可用。

## 4. 协议与保存

| 对象 | 当前协议 |
|---|---|
| method/application | local_credit_bounded_experience |
| Prompt | local-credit-delayed-experience-signed-cases |
| Manifest/Trajectory | 7 |
| Memory | 5 |
| Candidate | candidate_id/content/trigger/experience_id，无Fusion字段 |
| Application | 增加eligible，credit对应本轮实际来源 |
| Trajectory | admitted_candidate_id/admitted_experience_id/experience_updates |
| Experience | cases/text_version/update_history，无父子及fusion字段 |
| Evidence | 对应实际使用text_version |

source_trajectories记录有限案例来源，全部实际信用保存在evidence_history。案例非零来源信用、版本、10条上限、3任务窗口及候选净正资格须可核验；未知Judge不伪造信用。真实请求/消息/原始回复、结构输出和错误留档，鉴权头/API key不落日志，0600权限，ContextVar样本隔离及JSONL锁保持。

Memory与trajectory不是跨文件事务。resume要求新方法、代码/Prompt/配置/数据相同、完整有序前缀且无越界Memory写入；复制到新目录，来源只读。直接拒绝旧schema、Fusion/旧配置，不迁移或跨协议resume，历史配置/报告保留；历史清理范围按对应阶段记录执行；本轮保留原运行、数据和源缓存。

## 5. 冻结、Web与验收

held-out冻结内容、案例和Beta，只检索/选择/R0/Judge，不生成候选/归纳/记账。stop_after_train限制绝对已处理前缀，暂停不启动测试。真实角色固定Flash非思考，新实验使用独立目录。

Web仅loopback只读，仅列新Prompt/Manifest运行。展示整体Judge状态、候选eligible和最终入池、经验案例数/版本/冻结、正负信用、下游任务数、待归纳反馈及文本演化错误；不把历史信用当作新文本验证。历史旧协议产物保留，由原运行服务继续只读查看；新源码仅处理新协议。本轮不启动或重启Web。

测试覆盖局部资格/精确平局、延迟C2/C1选择、错误边界、P/N与版本、10/11条、样本去重/固定E、输入预算、向量失效、冻结、resume、真实HTTP消息及Node前端转义。离线通过不证明语义泛化改善，效果需后续新实验。
