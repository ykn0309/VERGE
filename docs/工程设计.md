# VERGE 工程设计（V1）

本文只定义把 VERGE 流程跑通所需的最小工程方案。方法规则以 [VERGE 设计总览](./设计方案.md) 为准。

V1 目标：

> 单进程内训练样本顺序执行；测试样本在只读经验池下限流并发计算、按数据集原顺序写轨迹，使结果可复核、阶段结果可查看；同时允许通过配置替换 LLM、数据集和主要方法模块。V1 不保证任意阶段的中断恢复、重复运行去重或跨文件原子写入；对任意阶段尚未写入 Memory 或轨迹的失败样本，允许经严格检查后复制完整轨迹前缀到全新目录重做该样本。

暂不考虑面向运行与修改实验状态的 Web UI、微服务、分布式队列和多机并行；独立的本地只读运行日志诊断页可读取既有产物，不参与流水线执行。

---

## 1. 最小系统结构

```text
Experiment Config
        │
        ▼
Component Registry
├── Dataset Adapter Registry
├── LLM Backend Registry
└── Module Implementation Registry
        │
        ▼
Pipeline Runner
├── Dataset Adapter
├── Role → LLM Backend
├── Module Implementations
├── Calculator
└── Store
    ├── Experience Memory
    ├── Vector Index
    └── Trajectory Log
```

| 组件 | 职责 |
|---|---|
| Experiment Config | 选择数据集、LLM、模块实现及其参数 |
| Component Registry | 根据实现名称创建对应组件 |
| Pipeline Runner | 按固定流程编排组件，不依赖具体实现 |
| Dataset Adapter | 将任意数据集转换为统一 PreferenceSample |
| LLM Backend | 屏蔽不同模型服务的调用差异 |
| Module Implementation | 实现 Retrieval、Credit、Fusion 等可替换策略 |
| Calculator | 提供确定性计算和统一不变量检查 |
| Store | 保存 Experience Memory、Vector Index 和 Trajectory Log |

V1 只实现进程内 Registry，不实现外部插件发现或远程模块服务。所有确定性数值都由 Calculator 或确定性模块实现计算，LLM 不直接给出最终 credit。

## 2. 核心数据

V1 只定义以下顶层对象：

```text
PreferenceSample {
    sample_id
    task
    chosen
    rejected
    metadata
}

Experience {
    experience_id
    content
    trigger
    alpha
    beta
    confidence
    source_trajectories
    evidence_history
}

Rubric {
    rubric_id
    base_rubric_id
    criteria
}

Criterion {
    criterion_id
    question
    importance_score: integer 1..10
    source_experiences
}

RevisionOperation {
    operation_id
    operation_type: ADD | DELETE | MODIFY
    target_criterion_id
    new_or_updated_criterion
    before_criterion  # Generator 留空；Executor 对 DELETE/MODIFY 补全
}

CandidateExperience {
    candidate_id
    content
    trigger
    linked_operation_ids  # Reflector 阶段为空；Credit Assigner 填写
    credit                # Reflector 阶段为 null；Credit Assigner 写入暂定修订信用
    admission             # null | PASS | FAIL
    admission_reason      # null | 模型给出的非空准入理由；旧轨迹可为 null
    fusion                # null | ADD | MERGE
    experience_id         # null | Fusion 后的最终经验 ID
}
```

其他阶段结果统一保存在：

```text
TrajectoryRecord {
    sample_id
    state

    retrieval_and_selection
    initial_rubric_and_judgment
    revision_attempts  # 仅保存 Judge 过的有效修订：私有 analysis 和补全后的 operations
    invalid_revision_attempts  # Executor 结构校验失败：私有 analysis 和失败摘要，无 Rk/Judge
    reflected_candidates  # 直接保存绑定、信用、准入与融合结果
    operation_contributions
    judge_error  # Judge 输出重试后仍不合法时的原因；不伪造 judgment
}
```

## 3. Pipeline Runner

Runner 启动时读取 Experiment Config，通过 Registry 创建 Dataset Adapter、各角色 LLM Backend 和模块实现。配置组合不合法时应在处理样本前直接失败。

Runner 按以下顺序处理一个样本：

```text
Retrieval
→ Selection
→ Initial Rubric
→ Judge
→ Existing Experience Credit → 更新已有经验

如果 Initial Failure：
→ Revision Attempt 1（生成并执行 operations）
→ 必要时 Revision Attempt 2（仍以 R0 为 base）
→ Reflection
→ Operation Contribution
→ Candidate-Operation Binding
→ Provisional Revision Credit
→ Admission
→ Experience Fusion → 写入 MERGE / ADD

→ 保存 Trajectory
```

Runner 必须在代码层保证：

1. Retriever、Selector 和 Initial Generator 看不到 chosen/rejected；
2. $R_1$ 和 $R_2$ 的 `base_rubric_id` 都是 $R_0$；
3. Critic 同次输出私有 analysis 与 operations；Revision Executor 只接受引用合法、无冲突且执行后含 2–8 条 criteria 的 operations；操作校验（含 Critic 操作编号反解、领域结构、Executor 冲突与条数）用尽结构重试时记作修订失败，不交给 Judge，也不生成候选经验；Critic 后端格式纠错耗尽时记录无效修订，跳过本轮并允许下一轮/下一样本，不叠加操作重试；未取得合法分析时 analysis 为 null，不伪造 Rk/Judge。其它未分类契约错误或后端故障仍中止；不增加 operations 候选内容审查；
4. 无法绑定 operation 的 candidate 不进入 Admission；
5. Admission FAIL 的 candidate 及其 provisional credit 被丢弃，且 credit 不重新分配;
6. Final Failure 不生成经验。

LLM 输出失败分为：

- **格式失败**：无法解析或缺字段，可以有限次数重试；Critic 的 `LLMFormatError` 耗尽后仅结束当前修订轮，保存 validation_failures，analysis 无合法值时为空；其它角色沿用既有失败策略；
- **Judge 输出无效**：编号错漏、重复、Boolean 非法等有限纠错（每侧默认最多 3 次含首次）。仍不合法则保存 `judge_error_initial` / `judge_error_revision` 轨迹并继续下一样本，不生成虚假判定；初始失败不得更新经验信用，修订失败保留已完成的 R0 下游信用。若测试集中存在此类错误，汇总保留错误数和有效样本准确率，整体 `test_accuracy` 置为 `null`，不将未知判定当成错误。网络故障与其他角色的错误不在此容错范围内；
- **语义失败**：Binding 无结果或 Admission 返回 FAIL，直接结束该 candidate，不改写、不重试。

## 4. 统一接口与可替换实现

### 4.1 Dataset Adapter

系统内部只接受第 2 节定义的 `PreferenceSample`。每个数据集实现统一接口：

```text
load(split) → Iterator[PreferenceSample]
```

Adapter 负责字段映射、样本 ID、split 和非法样本过滤。数据集必须能够合理抽象为 `task + chosen + rejected`。

RewardBench Chat Hard 的数据准备只从实验 YAML 的 `dataset.config.prepare` 读取 `implementation: rewardbench_chat_hard`、`output_dir`、固定的上游 `revision`、`seed`，以及划分模式的 `per_subset`、`train_per_subset` 和可选 `preserve_splits_from`；`mode` 默认 `split`，新增 `full_train` 将六个子集全部记录按全局 seed 确定性打散，仅输出 train.jsonl 和 provenance，不接受划分采样参数，不按题面去重；`dataset.config.paths` 须精确指向该输出目录的 train/test JSONL；`full_train` 仅声明 train。不再提供单独的准备子命令。`run --config` 在准备目录完全不存在时先按配置下载并划分数据；完整目录已存在时只校验复用；目录存在但缺文件、配置与 provenance 不一致或哈希不匹配时拒绝，不自动修复或覆盖。恢复旧运行时要求原数据已存在，不自动重建。模型请求前核验源版本、模式参数、样本数及输入文件 SHA-256；split 模式检查子集平衡，full_train 模式检查 provenance 中实际子集数量。运行 manifest 保存核验过的 provenance；未声明准备方式的通用 JSONL 数据仍按旧接口运行。

### 4.2 LLM Backend

真实模型的每次调用（包括 Admission）只看到本次上下文内的数字编号（字符串 `"1"`、`"2"`……）：对标准、经验、rubric、修订操作和候选经验分别编号，所有嵌套引用及键一并转换，返回时仅在已知 ID 字段将 JSON 正整数 `1` 规范为字符串 `"1"`，再严格反解为内部 ID；不跨调用复用编号，也不根据位置猜测错误引用。Fake Backend 保留固定内部 ID 用于历史离线场景。

不同模型提供方实现统一接口：

```text
generate(request) → response
```

Backend 负责消息格式、鉴权、structured output、模型参数、错误和限流。配置可以给每个角色选择不同 Backend 和模型。所有角色面向人阅读的生成内容（criterion 问题、critic 反馈、revision 问题、经验 content/trigger）要求中文；JSON 字段、ID、枚举、布尔值、数值等机器协议字段保持原样。真实 OpenAI-compatible Backend 仅校验输出结构与类型，不根据汉字数量、中英比例等语言特征拒绝或重试；中文表达由提示词约束，不能保证模型始终遵循。Fake Backend 是离线测试桩，不充当语义或语言审计器。

支持角色：

```text
Selector
Initial Rubric Generator
Judge
Critic（私有 analysis + 原子 operations）
Reflector
Revision Credit Assigner
Admission Checker
Fusion Judge
```

每个角色使用独立 context builder。真实消息使用角色专属 system（职责、证据边界、判断步骤与返回格式）和自然语言 user 输入；user 按带含义说明的字段分节展示原始文本、标准、操作前后和历史，不直接串行化为整块 JSON。已有对象的数字 ID 引用规则保持不变；Initial Generator 返回 criteria 列表（question、importance_score、source_experiences），Reflector 返回 candidates 列表（content、trigger），系统按列表顺序分配内部标准/rubric/候选 ID；Critic 只返回操作类型、已有目标引用和新标准内容，由系统分配操作/新增标准 ID，MODIFY 保留目标 ID，Executor 补全 before_criterion；Judge 对两份回答各做一次独立并行调用，每次模型仅接收待判断标准及 response，返回 satisfied；两侧结果均有效后合并，单侧纠错保留另一侧结果，全部复用时零调用；Admission 模型只接收 task 与候选 ID/content/trigger，信任上一步操作绑定，不接收操作、修订轨迹或信用数值；日志保留内部投影和真实消息，二者不能混为一谈。提示词版本为 `v16-system-critic-independent-judge`，旧运行仍可读，但旧检查点不得跨提示词版本续跑；此变更未证明真实语义效果改善。

Critic 第一次看 task、偏好对、R0 与逐项初始 Judge；第二次额外看第一次的私有 analysis、已执行 operations/R1/Judge/校验记录（若第一次无效则仅有 analysis 与校验失败摘要），仍从 R0 生成一次性完整操作集。`analysis` 可引用候选内容，提示词要求 `operations` 的标准仅从 task 推导；不审查操作是否含候选内容，结构通过不保证内容隔离。不传召回、信用或经验池等无关轨迹；Selector 和 Initial Generator 仍不可见偏好对。Fusion Judge 只比较 `content + trigger`，不能看到 confidence、preference pair 或 source trajectory。

“支持任意 LLM”表示新增模型时只需增加 Backend Adapter，不表示完全不需要适配。

### 4.3 Module Implementation

每个方法模块使用统一输入输出接口，并允许注册多种实现：

```text
Retriever
Selector
RubricGenerator
RubricJudge
ExistingCreditAllocator
RevisionStrategy
RevisionExecutor
Reflector
RevisionCreditAllocator
AdmissionChecker
ExperienceFusion
ReliabilityUpdater
```

V1 不要求每个接口立即提供多种实现，但 Runner 从一开始只依赖接口，默认实现也必须通过 Registry 装配。

例如：

```text
Retriever
├── VectorRetriever
├── HybridRetriever
└── NoOpRetriever

RevisionCreditAllocator
├── OperationBoundCredit
├── EqualCredit
└── NoRevisionCredit
```

每个实现必须声明：

```text
implementation name
implementation version
config schema
required capabilities
standard input/output types
```

计算模块不直接修改 Experience Memory，只返回计算结果；Runner 在初始 rubric 信用计算后调用 Memory 更新已有经验，并在 Fusion 决策后调用 Memory 执行 ADD / MERGE。

### 4.4 Calculator

Calculator 提供共享的纯计算能力：

```text
weight normalization
response score and margin
operation contribution
revision evidence budget
credit bounds
Beta update
```

不同 CreditAllocator 可以使用不同 credit 公式，但必须返回统一 credit 结果，并满足其声明的不变量。

核心配置至少检查：

$$
\sum_e|I_t(e)|\le B_t
$$

Operation contribution 只衡量 operation 直接修改 criterion 的 contribution 变化；importance score 归一化造成的其他 criterion 间接变化不归因，因此不检查 operation delta 与整体 margin improvement 守恒。

## 5. Store 与样本结果写入

训练时，初始 rubric 判断完成并计算下游信用后，立即更新本地 Experience Memory 中的已有经验；通过 Admission 的候选在 Fusion 阶段直接 MERGE / ADD。Trajectory Log 保存各阶段结果，不再暂存 `pending_memory_changes`。写入不是跨阶段事务：若后续步骤失败，之前成功写入的下游信用仍保留。

Vector Index 是 Experience Memory 的派生索引：ADD 后新增向量，MERGE 通常只更新元数据；索引需要时可从 Experience Memory 重建。未进入 Memory 的候选不能被检索。

V1 默认提供 `run` 和 `inspect-sample`，不保证通用崩溃恢复、跨文件事务、重复运行去重。实验 11 的可审计例外：`run --resume-from <旧目录>` 只接受输入/config 未改变（除新输出目录）、轨迹是 train→test 的完整有序前缀、Memory 的全部来源/证据只引用已完成训练样本、训练阶段未完成样本的请求和角色日志仅涉及紧接轨迹前缀之后的一个样本（可包含 Judge/Critic/Revision）；并行测试阶段允许测试集中更靠后的已发出请求出现在日志，但轨迹仍为严格有序前缀、经验池只读，续跑可能重复这些未提交测试请求。续跑前复制 Memory、轨迹及脱敏请求元数据到**新目录**并核对 SHA-256；manifest 保存父目录、旧代码指纹、原始文件哈希及已完成计数，新代码指纹另行记录。`run --stop-after-train N` 在训练前缀的第 N 条完整提交后正常退出，不启动测试，也不截断数据文件；N 含续跑复制的前缀，写入 execution 元数据而非方法配置，继续时使用新输出目录和已有恢复校验。只跳过已完整记录的样本，失败样本从检索开始；已存在任何部分 Memory 更新的中断点必须拒绝，原目录只读保留。原进程内向量缓存会在新进程中从 Memory 重建并产生必要的 embedding 请求。此机制不承诺任意失败点可续跑。

## 6. 配置驱动与消融

所有组件通过一个 Experiment Config 选择：

```yaml
dataset:
  implementation: dataset_adapter_name
  config: {}

models:
  default:
    backend: backend_name
    model: model_name
  roles:
    judge:
      backend: another_backend
      model: another_model

modules:
  retrieval:
    implementation: vector
    config:
      top_l: 20

  revision_credit:
    implementation: operation_bound
    config:
      max_budget: 1.0

  reliability:
    implementation: beta
    config: {}
```

消融通过替换实现完成，不在 Runner 中堆叠 `if ablation`：

| 消融 | 实现 |
|---|---|
| 无经验检索 | `NoOpRetriever` |
| 无 LLM 筛选 | `TopKSelector` |
| Equal Credit | `EqualCredit` |
| 无 Revision Credit | `NoRevisionCredit` |
| Neutral Reliability | `ConstantReliability` |
| 单次 Revision | `SingleAttemptRevision` |

Runner 启动时检查实现依赖。例如 `OperationBoundCredit` 必须要求 executed operations、两侧 Judge 结果和 candidate-operation bindings 可用。

每次运行保存 Run Manifest：

```text
dataset adapter and version
LLM backends and models
prompt versions
module implementations and versions
module configs
random seed
code version
```

这样两次运行之间的差异可以被准确定位。

Judge 子线程分别复制样本 ContextVar，请求/角色日志由现有锁保护；日志用 response_side 标注 chosen/rejected，此标记不进入模型消息。两侧任一网络/鉴权故障仍中止，另一侧格式错误不会覆盖后端故障。每个待判断 rubric 至多同时发起两条请求，与测试样本级并发相乘，需关注 API 配额。

本地只读日志诊断页需要区分完整轨迹结果与角色真实输入/输出：新运行在 `artifacts/role_io.jsonl` 顺序追加各个 LLM 角色调用的输入投影、真实发送的 system/user 消息（真实 backend）、模型原始文本、解析后的结构化结果及格式/网络重试记录（Fake backend 仅记录真实调用的投影及返回，不伪造消息）。该文件包含原始 task、chosen、rejected，须设为仅属主可读写（0600），不记录鉴权头和 API key；浏览器仅通过 loopback 读取选中样本，旧日志未保存的原始消息不能由最终轨迹逆推出。恢复运行时若存在该文件，核对哈希并复制到新运行，否则继续只保存新的角色调用；不得为旧前缀补造输入输出。

### 在线演化概览

运行概览从已有完整训练轨迹、memory 的 evidence_history 和请求日志重建首次正确率、ADD/MERGE、使用前置信度及召回→选中→引用指标，不新增独立演化日志，不改变方法流程。使用前 Beta 只累积更早任务的证据；零信用从初始 rubric/Judge 复算。缺失任务、部分 memory 写入或证据不一致时隐藏不可可靠重建的置信度/池规模分桶并显示警告。池曲线仅累计已提交轨迹中的融合事件，当前磁盘池另行呈现。train-only 不展示虚假测试准确率；本轮不采集检索耗时或相似度。

### 单进程测试并行与进度

- `run.test_workers` 默认 4、可设 1–16；1 表示顺序测试。训练始终顺序处理，测试线程共享只读经验快照与线程安全的 HTTP 客户端；向量检索缓存从训练快照复制到各 worker，避免共享可变缓存和重复编码已有经验。
- 每条请求与角色日志用 worker 独立的样本上下文标注，并以互斥锁写入 JSONL；轨迹只由主线程按数据集顺序提交。请求日志按调用完成时间排列，不应依赖其跨样本顺序解释轨迹。任一测试失败时只保留已完成轨迹前缀；等待已启动任务结束，后续请求可能已发生且在续跑时重做。配置中的并发数会进入 manifest 和续跑一致性检查。
- 训练与测试进度写入 stderr，标准输出保留机器可读 JSON；终端原位更新、重定向时节流输出。进度包括已续跑跳过的样本，不代表 API 请求数。

## 7. 最小测试与实现顺序

每类扩展接口至少需要一个 contract test，验证实现能够接受标准输入并返回标准输出。

V1 还要求：

1. Initial Generator 输入中没有 chosen/rejected；
2. $R_1$ 和 $R_2$ 都直接基于 $R_0$；
3. Revision Executor 拒绝不存在的 target ID、重复新 ID 和冲突 operations；
4. Revision credit 不超过 evidence budget；
5. Admission FAIL 后不重新分配其他 candidates 的 credit；
6. 非法组件组合能在启动时被发现；
7. 使用 [完整示例](./设计方案/13-完整示例.md)作为端到端 golden test。

推荐实现顺序：

```text
领域数据结构
→ Dataset Adapter / LLM Backend / Module Interfaces
→ Component Registry 与 Config Loader
→ Calculator
→ Experience Memory 与 Trajectory Store
→ Pipeline Runner
```
