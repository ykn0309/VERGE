# VERGE 工程设计

> 当前实现：Critic候选直接进入独立Generator应用，Admission已删除。方法见[总览](设计方案.md)，当前权重与判断依据实施见[计划44](plans/44-相对权重与Judge依据反馈.md)。历史计划与实验产物不改写。

## 1. 结构与角色

verge源码保持扁平。单进程、训练顺序执行；测试冻结Memory后有界并发，轨迹按数据顺序提交。不新增服务、审核角色或跨文件事务。

活跃LLM角色为Selector、Generator、Judge、Critic、Fusion。同一Generator提供R0生成与独立应用接口。

```text
Config / Registry → Dataset / Role Backends / Modules
→ Pipeline Runner → Calculator
                 → Memory / Vector Index / Trajectory / Role IO
```

## 2. 业务流程与预算

```text
固定E → R0生成/Judge → R0来源信用写入
R0失败：
  Critic提出0–1条候选 → 全新Generator(task+固定E+C) → Judge
    成功且采用C：Fusion → Memory
    成功未采用C：结束，不入池
    失败：剩余轮次内重新提出并独立应用
最多两轮；每轮一次Critic业务提案和一次应用。
```

删除准入调用、decision/reason、拒绝反馈、同轮拒绝重生成及准入耗尽终态。技术格式/结构纠错单独有限计数，不增加业务机会。Critic或应用Generator输出耗尽记录无效轮，剩余轮次可继续；空候选正常结束。未执行Judge不伪造分数或失败。

R0在有效Judge后、成败分支前更新已有经验。R1/R2中的E来源只用于审计，不重复记账；后续失败不回滚R0证据。

## 3. 消息与来源

Critic接收task、偏好对、当前有效失败评分标准/Judge。第二轮附上条候选、实际采用记录及必要前后证据，不附旧私有analysis，不再接收拒绝候选或原因。返回analysis和0–1条content/trigger，系统分配新候选ID；ID必须新颖、无重复且候选未融合。

每轮Generator重新创建独立消息，只包含system和task+固定E+当前C。没有旧评分标准、analysis、assistant历史、偏好对、Judge判断/理由或Critic私有诊断。实际user使用统一“本次可用经验”列表：E保持原顺序，C附末尾；审计payload分别保存E/C。C标注“当前候选、尚未验证，无历史置信度”，自主采用，不强制引用。

R0来源仅允许E；应用来源只允许本次固定E和当前C。局部数字编号严格反解，未知或重复来源拒绝。至少一条criterion引用C即记录adopted=true；这是自报，不保证语义忠实或因果性。

Generator保持非空analysis、2–8条标准、有限正数相对权重和正向Boolean问题。Generator按总预算1分配weight，Calculator归一化并保留原值；以十进制数字的精确比例计算margin符号，避免浮点伪平局/伪成功。Judge每侧返回Boolean和非空reason，合并为chosen_reason/rejected_reason；独立两侧请求，并保留既有相同问题复用规则，理由随判断复用和留档。不支持部分分、否决或跳过。

Fusion仅看双方content/trigger，默认ADD；兼容同一设计问题才MERGE，不负责补充审核或候选清理。ADD保存实际应用原文，MERGE保留文本版本。数值由Calculator计算。

## 4. 数据与协议

| 对象 | 当前协议 |
|---|---|
| application实现 | `critic_candidate_weighted_application` |
| Prompt版本 | `critic-candidate-weighted-judge-reasons` |
| Manifest | `format_version: 4` |
| Trajectory | `schema_version: 4` |
| Experience Memory | `schema_version: 2`，字段未变 |
| CriticProposal | analysis、candidate |
| ProposalAttempt | round_number、analysis、candidate、error |
| ApplicationAttempt | round_number、candidate_id、rubric、judgment、adopted、adopted_criterion_ids、credit、error |

每个轮次最多一个ProposalAttempt和ApplicationAttempt，两者通过轮次及候选ID关联。候选无admission/admission_reason，提案无generation_number。旧字段和旧版本直接拒绝，不迁移或静默忽略。

保存真实输入、消息、原始输出、解析输出、有效评分标准、来源、错误、Fusion和双通道证据。原始task和偏好文本不改写；日志不记录鉴权头/API key，0600权限；线程/sample通过ContextVar隔离、JSONL写入加锁。

终态包括initial_success/initial_failure、application_success、success_without_candidate、no_candidate、validation_exhausted、invalid_application_exhausted、sample_error和Judge错误。未知采用/Judge不默认失败。

## 5. 信用与Memory

Credit保存positive_credit/negative_credit；R0与本轮候选按实际引用标准的归一化权重和Boolean差计算，多来源均分。alpha+=P、beta+=N，evidence_weight固定1，不先抵消、不折扣、不使用margin增益；P+N>0才追加数值证据，零信用仍可合法Fusion。

只有实际提供、声明采用且有效整体成功的同一候选才可入池。失败、未采用、未应用候选仅留轨迹。成功未采用C结束任务。

ADD从Beta(1,1)起步；MERGE继承原ID/Beta/证据并保存前后文本。继承证据不认证新扩展。索引是可重建派生缓存，ADD编码新文本，MERGE使变化的文本缓存失效。

Memory与trajectory不是跨文件原子事务。续跑要求源码/提示词/配置/数据/执行参数相同、完整有序前缀和没有越过提交前缀的Memory写入；复制到新目录，来源只读。不跨方法resume。

## 6. 错误边界

| 情况 | 行为 |
|---|---|
| Critic/应用Generator格式或结构耗尽 | 保存无效轮，剩余轮次可继续 |
| R0/Selector/Fusion契约错误或角色拒答 | 保存sample_error及已完成阶段，继续下一样本 |
| Judge输出耗尽 | 保存judge_error，结束本样本后续流程，继续下一样本 |
| 网络/鉴权/配额、数据/存储/Calculator、程序错误 | fail-fast，不吞系统错误 |

后端格式耗尽不叠加结构重试；未知结果不算有效判别，不伪造成功或失败。错误轨迹计入已处理前缀，不回滚合法R0写入。

## 7. 配置、冻结与保护

`max_rounds`为1–2，每轮提案固定1次；`invalid_output_retries`为0–3，Critic/应用Generator共用，R0的`initial_output_retries`独立。没有Admission开关、旧对话模式或experience_enabled兼容分支。

当前真实实验固定所有LLM角色Qwen3.5-Flash、enable_thinking=false、timeout_seconds=30、max_retries=2，roles为空继承默认。历史Plus/thinking配置只留档。

准备数据保持revision/provenance/有序前缀/SHA256核验。新目录启动；已有实验配置及原始产物不覆盖。Web仅loopback、只读、支持当前协议，不补造历史消息。

训练结束冻结Memory、文本与Beta；held-out仅检索/选择/R0生成/Judge，关闭exploration，不提出、应用或融合候选，不回写信用。stop_after_train限制绝对已处理前缀，暂停不启动测试。

## 8. 验收与效果边界

离线验证覆盖两轮提案直接应用、真实HTTP消息与数字ID、固定E/替换C、未采用成功、严格来源、P/N、负/零信用Fusion、错误隔离/全局故障、冻结、续跑以及Web展示。删除仅服务旧Admission角色的测试，不用skip掩盖错误。

Mock/Fake检验工程契约，不证明真实语义效果。删除Admission没有自动授权新实验、提交或push。
