# VERGE 工程设计（V1）

本文只定义把 VERGE 流程跑通所需的最小工程方案。方法规则以 [VERGE 设计总览](./设计方案.md) 为准。

V1 目标：

> 单进程内训练样本顺序执行；测试样本在只读经验池下限流并发计算、按数据集原顺序写轨迹，使结果可复核、阶段结果可查看；同时允许通过配置替换 LLM、数据集和主要方法模块。V1 不保证任意阶段的中断恢复、重复运行去重或跨文件原子写入；对任意阶段尚未写入 Memory 或轨迹的失败样本，允许经严格检查后复制完整轨迹前缀到全新目录重做该样本。

暂不考虑面向运行与修改实验状态的 Web UI、微服务、分布式队列和多机并行；独立的本地只读运行日志诊断页可读取既有产物，不参与流水线执行。

---

## 1. 最小系统结构

```text
Experiment Config
        │
        ▼
Component Registry
├── Dataset Adapter Registry
├── LLM Backend Registry
└── Module Implementation Registry
        │
        ▼
Pipeline Runner
├── Dataset Adapter
├── Role → LLM Backend
├── Module Implementations
├── Calculator
└── Store
    ├── Experience Memory
    ├── Vector Index
    └── Trajectory Log
```

| 组件 | 职责 |
|---|---|
| Experiment Config | 选择数据集、LLM、模块实现及其参数 |
| Component Registry | 根据实现名称创建对应组件 |
| Pipeline Runner | 按固定流程编排组件，不依赖具体实现 |
| Dataset Adapter | 将任意数据集转换为统一 PreferenceSample |
| LLM Backend | 屏蔽不同模型服务的调用差异 |
| Module Implementation | 实现 Retrieval、Credit、Fusion 等可替换策略 |
| Calculator | 提供确定性计算和统一不变量检查 |
| Store | 保存 Experience Memory、Vector Index 和 Trajectory Log |

V1 只实现进程内 Registry，不实现外部插件发现或远程模块服务。所有确定性数值都由 Calculator 或确定性模块实现计算，LLM 不直接给出最终 credit。

## 2. 核心数据

V1 只定义以下顶层对象：

```text
PreferenceSample {
    sample_id
    task
    chosen
    rejected
    metadata
}

Experience {
    experience_id
    content
    trigger
    alpha
    beta
    confidence
    source_trajectories
    evidence_history
    fusion_history  # 融合样本/候选、修改前后文本和弱修订证据
}

Rubric {
    rubric_id
    base_rubric_id
    criteria
}

Criterion {
    criterion_id
    question
    importance_score: integer 1..10
    source_experiences
}

RevisionOperation {
    operation_id
    operation_type: ADD | DELETE | MODIFY
    target_criterion_id
    new_or_updated_criterion
    before_criterion  # 历史字段；当前方法不生成 operation
}

CandidateExperience {
    candidate_id
    content
    trigger
    linked_operation_ids  # 历史字段；当前固定空数组
    credit                # 历史字段；当前方法固定 null
    admission             # null | PASS | FAIL
    admission_reason      # null | 模型给出的非空准入理由；旧轨迹可为 null
    fusion                # null | ADD | MERGE
    experience_id         # null | Fusion 后的最终经验 ID
    fusion_record         # null | 同次融合的前后文本和信用记录
}
```

其他阶段结果统一保存在：

```text
TrajectoryRecord {
    sample_id
    state

    retrieval_and_selection
    initial_rubric_and_judgment
    revision_attempts  # 仅保存 Judge 过的有效修订：私有 analysis、公开 feedback、完整 rubric 与修改前基线
    invalid_revision_attempts  # 完整修订输出校验失败：私有 analysis 和失败摘要，无 Rk/Judge
    reflected_candidates  # 保存候选、准入与融合结果；无操作信用，合法融合记录弱修订证据
    operation_contributions
    judge_error  # Judge 输出重试后仍不合法时的原因；不伪造 judgment
}
```

## 3. Pipeline Runner

Runner 启动时读取 Experiment Config，通过 Registry 创建 Dataset Adapter、各角色 LLM Backend 和模块实现。配置组合不合法时应在处理样本前直接失败。

Runner 按以下顺序处理一个样本：

```text
Retrieval
→ Selection
→ Initial Rubric
→ Judge
→ Existing Experience Credit → 更新已有经验

如果 Initial Failure：
→ Revision Attempt 1（Critic 反馈 → 原 Generator 完整修订）
→ 必要时 Revision Attempt 2（接续最近有效 rubric）
→ Reflection
→ Admission
→ Experience Fusion → 写入 MERGE / ADD

→ 保存 Trajectory
```

Runner 必须在代码层保证：

1. Retriever、Selector 和 Initial Generator 看不到 chosen/rejected；
2. $R_1$ 的 base 为 $R_0$，$R_2$ 的 base 为最近有效 rubric；R1 无效时仍为 R0；
3. Critic 返回 analysis + improvement_advice；私有分析不进入 Generator，仅公开建议追加到同一 Generator 的单样本会话。第二轮修订最近有效 rubric；无 Executor。完整输出校验耗尽记录无效尝试，下一轮继续；网络/存储等全局错误仍中止。
4. Reflector 仅生成 0–1 条候选，直接 Admission，无操作绑定；
5. Admission FAIL 不入池；ADD 以 Beta(1,1) 为基础，MERGE 更新融合文本并继承历史 Beta/证据；二者追加来源、文本版本与 0.25 折扣的成功轮 margin 增益证据;
6. Final Failure 不生成经验。

LLM 输出失败分为：

- **角色输出/样本契约失败**：有限纠错后仍有无效结构、引用、条数等时，保存 `sample_error` 的 stage/type/message 与此前真实完成的阶段，继续下一样本。Generator 默认 2 次额外语义纠错，后端格式重试耗尽不叠加此重试。Critic 既有格式耗尽仍仅结束修订轮；模型明确拒答按样本错误处理；
- **Judge 输出无效**：编号错漏、重复、Boolean 非法等有限纠错（每侧默认最多 3 次含首次）。仍不合法则保存 `judge_error_initial` / `judge_error_revision` 轨迹并继续下一样本，不生成虚假判定；初始失败不得更新经验信用，修订失败保留已完成的 R0 下游信用。若测试集中存在此类错误，汇总保留错误数和有效样本准确率，整体 `test_accuracy` 置为 `null`，不将未知判定当成错误。鉴权、配额/网络服务故障、存储/数据集错误与程序异常仍中止运行；
- **语义失败**：Admission 返回 FAIL，直接结束该 candidate，不改写、不重试。

## 4. 统一接口与可替换实现

### 4.1 Dataset Adapter

系统内部只接受第 2 节定义的 `PreferenceSample`。每个数据集实现统一接口：

```text
load(split) → Iterator[PreferenceSample]
```

Adapter 负责字段映射、样本 ID、split 和非法样本过滤。数据集必须能够合理抽象为 `task + chosen + rejected`。

RewardBench Chat Hard 的数据准备只从实验 YAML 的 `dataset.config.prepare` 读取 `implementation: rewardbench_chat_hard`、`output_dir`、固定的上游 `revision`、`seed`，以及划分模式的 `per_subset`、`train_per_subset` 和可选 `preserve_splits_from`；`mode` 默认 `split`，新增 `full_train` 将六个子集全部记录按全局 seed 确定性打散，仅输出 train.jsonl 和 provenance，不接受划分采样参数，不按题面去重；`dataset.config.paths` 须精确指向该输出目录的 train/test JSONL；`full_train` 仅声明 train。不再提供单独的准备子命令。`run --config` 在准备目录完全不存在时先按配置下载并划分数据；完整目录已存在时只校验复用；目录存在但缺文件、配置与 provenance 不一致或哈希不匹配时拒绝，不自动修复或覆盖。恢复旧运行时要求原数据已存在，不自动重建。模型请求前核验源版本、模式参数、样本数及输入文件 SHA-256；split 模式检查子集平衡，full_train 模式检查 provenance 中实际子集数量。运行 manifest 保存核验过的 provenance；未声明准备方式的通用 JSONL 数据仍按旧接口运行。

### 4.2 LLM Backend

真实模型的每次调用（包括 Admission）只看到本次上下文内的数字编号（字符串 `"1"`、`"2"`……）：对标准、经验、rubric、修订操作和候选经验分别编号，所有嵌套引用及键一并转换，返回时仅在已知 ID 字段将 JSON 正整数 `1` 规范为字符串 `"1"`，再严格反解为内部 ID；不跨调用复用编号，也不根据位置猜测错误引用。Fake Backend 保留固定内部 ID 用于历史离线场景。

不同模型提供方实现统一接口：

```text
generate(request) → response
```

Backend 负责消息格式、鉴权、structured output、模型参数、错误和限流。配置可以给每个角色选择不同 Backend 和模型。所有角色面向人阅读的生成内容（criterion 问题、critic 反馈、revision 问题、经验 content/trigger）要求中文；JSON 字段、ID、枚举、布尔值、数值等机器协议字段保持原样。真实 OpenAI-compatible Backend 仅校验输出结构与类型，不根据汉字数量、中英比例等语言特征拒绝或重试；中文表达由提示词约束，不能保证模型始终遵循。Fake Backend 是离线测试桩，不充当语义或语言审计器。

支持角色：

```text
Selector
Initial Rubric Generator
Judge
Critic（私有 analysis + 公开 improvement_advice）
Reflector
Admission Checker
Fusion Judge
```

每个角色使用独立 context builder。真实消息使用角色专属 system（职责、证据边界、判断步骤与返回格式）和自然语言 user 输入；user 使用简单标签、原始文本和紧凑列表展示任务、回答、标准、操作前后和历史，必要技术量集中说明一次，不直接串行化为整块 JSON。已有对象的数字 ID 引用规则保持不变；Initial Generator 返回非空 analysis（先分析任务要求和输入完整性）及 criteria 列表（question、importance_score、source_experiences），Reflector 接收原始 task、chosen/rejected、成功修订与判断，再返回 0–1 条 candidates（content、trigger），系统按列表顺序分配内部标准/rubric/候选 ID；Critic 返回 analysis 与 improvement_advice；后者作为 user 追加到同一 Generator 会话，Generator 返回完整 rubric，系统分配所有新标准 ID；Judge 对两份回答各做一次独立并行调用，每次模型接收原始 task、待判断标准及单份 response，返回 satisfied；两侧结果均有效后合并，单侧纠错保留另一侧结果，全部复用时零调用；取消操作绑定及修订信用分配；Admission 模型只接收 task 与候选 ID/content/trigger，不接收操作、修订轨迹或信用数值；日志保留内部投影和真实消息，二者不能混为一谈。提示词版本为 `generator-dialogue-inline-experience-definition`，历史运行产物保持原样，Web 只读兼容当前版本与既有 Generator 对话/融合版本，但旧检查点不得跨提示词版本续跑；此变更未证明真实语义效果改善。

Critic 每轮看 task、偏好对、当前有效 rubric/Judge，第二轮额外看此前反馈和失败摘要；公开建议仅由任务及独立领域知识支撑。Generator 保留实际 assistant 回复并仅追加公开建议，ContextVar 隔离样本/并发线程。Reflector 读取初始、成功前后标准及 Critic 分析/建议，提炼 0–1 条经验。反馈内容隔离依赖提示词，不增加内容审核。

“支持任意 LLM”表示新增模型时只需增加 Backend Adapter，不表示完全不需要适配。

### 4.3 Module Implementation

每个方法模块使用统一输入输出接口，并允许注册多种实现：

```text
Retriever
Selector
RubricGenerator
RubricJudge
ExistingCreditAllocator
RevisionStrategy
CriticFeedback (analysis + improvement_advice)
Reflector
AdmissionChecker
ExperienceFusion
ReliabilityUpdater
```

V1 不要求每个接口立即提供多种实现，但 Runner 从一开始只依赖接口，默认实现也必须通过 Registry 装配。

例如：

```text
Retriever
├── VectorRetriever
├── HybridRetriever
└── NoOpRetriever

```

每个实现必须声明：

```text
implementation name
implementation version
config schema
required capabilities
standard input/output types
```

计算模块不直接修改 Experience Memory，只返回计算结果；Runner 在初始 rubric 信用计算后调用 Memory 更新已有经验，并在 Fusion 决策后调用 Memory 执行 ADD / MERGE。

### 4.4 Calculator

Calculator 提供共享的纯计算能力：

```text
weight normalization
response score and margin
operation contribution
revision evidence budget
credit bounds
Beta update
```

不同 CreditAllocator 可以使用不同 credit 公式，但必须返回统一 credit 结果，并满足其声明的不变量。

核心配置至少检查：

$$
\sum_e|I_t(e)|\le B_t
$$

Operation contribution 只衡量 operation 直接修改 criterion 的 contribution 变化；importance score 归一化造成的其他 criterion 间接变化不归因，因此不检查 operation delta 与整体 margin improvement 守恒。

## 5. Store 与样本结果写入

训练时，初始 rubric 判断完成并计算下游信用后，立即更新本地 Experience Memory 中的已有经验；通过 Admission 的候选在 Fusion 阶段直接 MERGE / ADD。Trajectory Log 保存各阶段结果，不再暂存 `pending_memory_changes`。写入不是跨阶段事务：若后续步骤失败，之前成功写入的下游信用仍保留。

Vector Index 是 Experience Memory 的派生索引：ADD 后新增向量，MERGE 改写 content/trigger 后使文本缓存失效，下次召回重新编码；索引需要时可从 Experience Memory 重建。未进入 Memory 的候选不能被检索。

V1 默认提供 `run` 和 `inspect-sample`，不保证通用崩溃恢复、跨文件事务、重复运行去重。实验 11 的可审计例外：`run --resume-from <旧目录>` 只接受输入/config 未改变（除新输出目录）、轨迹是 train→test 的完整有序前缀、Memory 的全部来源/证据只引用已完成训练样本、训练阶段未完成样本的请求和角色日志仅涉及紧接轨迹前缀之后的一个样本（可包含 Judge/Critic/Revision）；并行测试阶段允许测试集中更靠后的已发出请求出现在日志，但轨迹仍为严格有序前缀、经验池只读，续跑可能重复这些未提交测试请求。续跑前复制 Memory、轨迹及脱敏请求元数据到**新目录**并核对 SHA-256；manifest 保存父目录、旧代码指纹、原始文件哈希及已完成计数，新代码指纹另行记录。`run --stop-after-train N` 在训练前缀的第 N 条完整提交后正常退出，不启动测试，也不截断数据文件；N 含续跑复制的前缀，写入 execution 元数据而非方法配置，继续时使用新输出目录和已有恢复校验。只跳过已完整记录的样本，失败样本从检索开始；已存在任何部分 Memory 更新的中断点必须拒绝，原目录只读保留。原进程内向量缓存会在新进程中从 Memory 重建并产生必要的 embedding 请求。此机制不承诺任意失败点可续跑。

## 6. 配置驱动与消融

所有组件通过一个 Experiment Config 选择：

```yaml
dataset:
  implementation: dataset_adapter_name
  config: {}

models:
  default:
    backend: backend_name
    model: model_name
  roles:
    judge:
      backend: another_backend
      model: another_model

modules:
  retrieval:
    implementation: vector
    config:
      top_l: 20

  reliability:
    implementation: beta
    config: {}
```

消融通过替换实现完成，不在 Runner 中堆叠 `if ablation`：

| 消融 | 实现 |
|---|---|
| 无经验检索 | `NoOpRetriever` |
| 无 LLM 筛选 | `TopKSelector` |
| Equal Credit | `EqualCredit` |
| 当前信用基线 | 下游反馈 + 折扣弱修订证据；不分配操作信用 |
| Neutral Reliability | `ConstantReliability` |
| 单次 Revision | `SingleAttemptRevision` |

Runner 启动时验证 critic_generator_dialogue 配置、模块角色与完整 rubric 契约，不装配操作执行器或修订信用模块。

每次运行保存 Run Manifest：

```text
dataset adapter and version
LLM backends and models
prompt versions
module implementations and versions
module configs
random seed
code version
```

这样两次运行之间的差异可以被准确定位。

Judge 子线程分别复制样本 ContextVar，请求/角色日志由现有锁保护；日志用 response_side 标注 chosen/rejected，此标记不进入模型消息。两侧任一网络/鉴权故障仍中止，另一侧格式错误不会覆盖后端故障。每个待判断 rubric 至多同时发起两条请求，与测试样本级并发相乘，需关注 API 配额。

本地只读日志诊断页需要区分完整轨迹结果与角色真实输入/输出：新运行在 `artifacts/role_io.jsonl` 顺序追加各个 LLM 角色调用的输入投影、真实发送的 system/user 消息（真实 backend）、模型原始文本、解析后的结构化结果及格式/网络重试记录（Fake backend 仅记录真实调用的投影及返回，不伪造消息）。该文件包含原始 task、chosen、rejected，须设为仅属主可读写（0600），不记录鉴权头和 API key；浏览器仅通过 loopback 读取选中样本，旧日志未保存的原始消息不能由最终轨迹逆推出。恢复运行时若存在该文件，核对哈希并复制到新运行，否则继续只保存新的角色调用；不得为旧前缀补造输入输出。

### 在线演化概览

运行概览从已有完整训练轨迹、memory 的 evidence_history 和请求日志重建首次正确率、ADD/MERGE、使用前置信度及召回→选中→引用指标，不新增独立演化日志，不改变方法流程。使用前 Beta 只累积更早任务的证据；零信用从初始 rubric/Judge 复算。缺失任务、部分 memory 写入或证据不一致时隐藏不可可靠重建的置信度/池规模分桶并显示警告。池曲线仅累计已提交轨迹中的融合事件，当前磁盘池另行呈现。train-only 不展示虚假测试准确率；本轮不采集检索耗时或相似度。

### 单进程测试并行与进度

- `run.test_workers` 默认 4、可设 1–16；1 表示顺序测试。训练始终顺序处理，测试线程共享只读经验快照与线程安全的 HTTP 客户端；向量检索缓存从训练快照复制到各 worker，避免共享可变缓存和重复编码已有经验。
- 每条请求与角色日志用 worker 独立的样本上下文标注，并以互斥锁写入 JSONL；轨迹只由主线程按数据集顺序提交。请求日志按调用完成时间排列，不应依赖其跨样本顺序解释轨迹。任一测试失败时只保留已完成轨迹前缀；等待已启动任务结束，后续请求可能已发生且在续跑时重做。配置中的并发数会进入 manifest 和续跑一致性检查。
- 训练与测试进度写入 stderr，标准输出保留机器可读 JSON；终端原位更新、重定向时节流输出。进度包括已续跑跳过的样本，不代表 API 请求数。

## 7. 最小测试与实现顺序

每类扩展接口至少需要一个 contract test，验证实现能够接受标准输入并返回标准输出。

V1 还要求：

1. Initial Generator 输入中没有 chosen/rejected；
2. 第二轮基于最近有效 rubric；第一轮无效时仍基于 R0；
3. Generator 实际会话保留 assistant 回复并追加公开反馈；私有分析/候选不直接进入 Generator，无效完整输出不交给 Judge；
4. 生成经验最多一条；ADD 的基础 Beta 为 (1,1)，ADD/MERGE 追加弱修订证据；MERGE 保存前后文本且保留已有证据；
5. Admission FAIL 不写入经验池；生成数量不得超过一条；
6. 非法组件组合能在启动时被发现；
7. 使用 [完整示例](./设计方案/13-完整示例.md)作为端到端 golden test。

```text
领域数据结构

→ Component Registry 与 Config Loader
→ Calculator
→ Experience Memory 与 Trajectory Store
→ Pipeline Runner
→ 默认模块实现

```

> 任意一个 sample 都能从 Trajectory Log 中还原其完整流程和 Experience Memory 更新来源；替换符合接口的数据集、LLM 或模块实现时，不需要修改 Pipeline Runner。

### v17 只读诊断视图

Web 从既有 role_io 中流式提取 Generator 初始生成的最后一次结构化分析和 Reflector 原始候选数量，按 sample_id 与轨迹关联；完整调用仍按需加载，Rubric/Trajectory schema 不变。样本列表区分生成候选、ADD/MERGE 入池、Selector 选中和 R0 实际来源引用；引用不等于有效贡献。Web 只读支持当前融合版本和上一版 Generator 对话版本的运行，移除原子操作展示；展示 Critic analysis/公开 feedback、完整修订结果和 Generator 全部实际消息，不为历史日志伪造新字段；运行中尚未写入的分析/候选仍显示未确认，不把缺记录当作零生成。无运行目录时展示空状态，允许后台服务持续运行。

### 单样本错误隔离

`TrajectoryRecord.sample_error` 为可空 `{stage, type, message}`，错误状态为 `sample_error`。Generator 失败时 R0 和 initial_judgment 为 null；后续阶段失败则保留实际已有判断、有效/无效修订、候选和已落盘的下游信用及 ADD/MERGE，既不回滚真实更新也不补造后续结果。错误记录作为已处理轨迹前缀，续跑跳过它，不自动重做已记账样本；异常写盘中断仍需严格检查点审计，不保证跨文件事务。

Web 显示错误阶段/原因、样本错误计数和有效初始判别分母；修复数依据真实成功修订，不依赖最终状态是否已进入反思。无初始判断的错误不算正常失败；已有初始判断仍计入首次指标。测试/baseline 有未知判断时整体准确率为 null，同时提供有效样本准确率及单独错误数。默认最多 100 条暂停按已处理并落盘任务计数，包含显式错误轨迹。

保护边界：仅在指定外部角色阶段隔离 ValueError/模型拒答；Calculator、Memory/索引/轨迹写盘、数据集/配置、鉴权/网络请求及未知程序异常保持 fail-fast，防止掩盖系统故障或大量无效请求。

### v18 自然输入表达

system 只声明一次角色身份。user 使用自然标题、原始任务/回答文本和标准、经验、操作列表；删除角色标识、资料原值前缀及逐字段括号释义。置信度、证据量、分数与信用等必要技术量集中说明一次。输入投影、ID 映射和输出 JSON 协议不变。v17 前100条完成后才修改提示词，旧运行产物不改写；跨提示词版本检查点仍拒绝续跑。

### v19 紧凑自然输入

输入渲染器对八个角色统一使用普通标签与紧凑列表；每条标准、经验、操作和逐项判断作为列表项展示，保留编号、来源、修改前后以及零值/缺失状态，不为对象或嵌套字段生成 Markdown 标题。任务与回答原文中的 Markdown、换行和缩进保持原样。输入投影、输出 JSON、编号映射及方法规则不变。完整离线测试 320 项通过；未发起 v19 真实实验，v18 前10条日志不改写，跨版本续跑仍拒绝。

## 下游验证方法边界

候选模型输出只有 content、trigger，不再有 linked_operation_ids。为只读解析旧轨迹，领域模型的历史 linked_operation_ids/credit 和 operation_contributions 暂保留，新运行的旧操作字段固定为空/null；流水线、模块装配与实验配置不再含旧 operation_bound revision_credit。旧操作收益工具仅作历史诊断；新 calculate_fusion_credit 基于成功轮最近有效基线的 margin 增益计算 0.25 折扣弱证据。旧暂停进程与检查点不得混用本版本方法；应另起新目录重跑。

### 经验时间线与样本预览交互

经验时间线将初始先验与同一来源样本的首次 ADD（包括融合弱证据）合为一个展示事件，不改变磁盘证据、Beta 或后续 MERGE/信用事件；折线图使用同一展示序列。去掉时间线说明小字和重复来源列表，缺完整轨迹的事件仍逐项标记。

样本引用普通点击打开模态悬浮窗，仅展示 task、chosen、rejected；各字段复用现有按需翻译与原文切换，未点击翻译时不调用翻译服务。Cmd+点击（兼容 Ctrl+点击）进入样本流水线并选中流水线页签；样本列表保持直接导航。悬浮窗支持关闭按钮、Escape、点击遮罩及焦点返回，运行/页面刷新时关闭。

### 可扩展文本融合与弱修订证据

Fusion 仅见 content/trigger，返回匹配位置及完整融合文本，无匹配时三字段均为 null。兼容机制可扩展；程序校验位置、非空文本和契约，内容边界依赖提示词，不新增审核门禁。

合法 ADD/MERGE 写入 `fusion_credit = 0.25 * min(1, 成功轮 margin - 最近有效基线 margin)`、weight=1、candidate_id；alpha 增加该量，beta 继承，confidence 派生。Calculator 先校验两个完整判断，第二轮不能使用初始 R0 替代 R1。

Experience.fusion_history 与 CandidateExperience.fusion_record 保存修改前后 content/trigger 和样本/候选 ID；候选旧 credit 字段仍为 null。旧日志缺字段按空历史解码，不补造证据。Web 区分融合弱证据、下游证据、历史未计信用融合，显示每个文本版本；继承旧证据不认证新扩展。旧运行不得跨方法续跑，新增配置指向全新目录。

### 可用经验表达与任务目标优先

Reflector、Admission、Fusion 的实际 system 消息各自直接定义用于首次生成的具体经验；content 说明如何设计评价标准，trigger 说明适用于哪些任务或输入条件，避免角色间迁移标准漂移。Admission 仅审核表达、task-only 条件及任务目标/明确约束兼容性；理由引用实际候选并定位缺陷，PASS 不宣称有效。Fusion 的扩展保持同一定义和条件强度边界，不追加审核阶段。

Selector/Generator 区分任务指令的操作与材料主题，前者决定机制是否适用，后者按 task 决定标准和重要性；材料主题相似及经验信用不覆盖任务目标。变化仅在提示词，角色输入投影、7角色、0–1候选、输出协议、信用公式与存储路径逻辑不变。

新版提示词阻止旧检查点跨版本续跑；Web 只读允许已知的 `generator-dialogue-critic-feedback`、`generator-dialogue-fusion-revision-evidence` 、`generator-dialogue-task-grounded-experience` 、`generator-dialogue-task-grounded-experience-compact`、`generator-dialogue-initial-design-experience` 和 `generator-dialogue-initial-design-experience-v2` 版本，不重写或补造旧消息。语义效果仍需后续验证，离线契约测试不作为模型误拒率证据。
