# VERGE V2 工程设计

方法规则统一见[设计方案](设计方案.md)。当前实现对应[计划71](plans/71-V2审查修复.md)，基础实现与局部验证见计划70，源码保持扁平；不保留V1生产兼容层。独立参数估计与冻结终测尚未开展，General30题在线采集预试验结果见报告73。

## 1. 领域对象与协议

- `Method`：trigger/principle必填，template可空，parameters每项仅定义description。仅支持简单命名占位符，参数集合必须与占位符一致；不做字数硬限制或语义原子性校验。
- `Criterion`：至多一个source_experiences，允许空来源与零权重，整套rubric必须有正权重。只保留bindings参数填充值，删除binding_evidence。Generator应用阶段不硬校验参数键覆盖或question逐字渲染；模板遵循及参数合理性由Generator Checker结合上下文判断。JSON类型、非空文本、引用ID等结构校验保留；Method定义中的占位符与参数定义一致性检查保留。
- `Experience`：不可变方法、独立版本ID、父版本、状态、来源案例、质量后验及参数版本、实际应用记录、检查游标。无alpha/beta/P/N、类别或继承惩罚。
- `ApplicationRecord`：保存完整样本、实际方法版本、rubric/Judge原始结果、四类计数、W正/W反、反馈、三个报告、O、更新原因及前后Q。逐任务聚合；纯同判与正反抵消均记tie，保留原始权重及四类计数供审计。
- `RevisionRecord`：触发案例、原因、抽样来源、Keep/Revise、候选版本、两臂实际回放和采用判据；拒绝与失败也留档。

Memory=13，Trajectory/Manifest=15，method=`semistructured_bayesian_v2`。旧协议训练/恢复一律拒绝，不做迁移或自动字段映射；Web对格式13/14历史实验只读展示原始记录，不转换为当前训练对象。历史输入转换仅出现在独立复测脚本中，逐项记录差异。

## 2. 可见性与角色

首轮task+E；候选新Generator只接收task+当前C。Critic最多两轮，真实消息在单一样本中接续，短编号映射在该会话内稳定。Critic每轮直接输出0或1条候选，不再调用Atomizer；Experience Checker以approved/reason核对，明确拒绝才向Critic反馈；通过立即入池，终止提案循环，再仅task+C应用。Generator/Judge结果不反馈Critic，不撤销入池。

Judge在两个独立并行调用中分别看到task、同一组问题和一份回答，不看到来源、权重、另一个回答或偏好。程序依据原始偏好计算结果。

每个被实际引用版本的三个Checker并行：Selector核对任务与Trigger，Generator核对方法与引用标准，Judge核对标准及两份匿名回答的原始Boolean/理由。Checker不读偏好、F或彼此报告；输出正确/错误/未知，耗尽重试记为调用失败。任一有效错误报告优先，即使另有失败仍可形成O=错误；三者全正确才为O=正确；其余不更新Q。准入前调用独立Experience Checker，来源验证实际引用后照常调用三个执行Checker。

所有模型输入的系统编号压缩为局部数字；自然语言中的原文不改写。原始请求、回复、编号表保留，密钥与鉴权头不进日志。完整上下文预算默认100000 UTF-8字节，含Critic历史，不静默截断。

## 3. 反馈与质量计算

相对权重用十进制Fraction归一化，保留精确平分与小分差。整体chosen分数严格高于rejected才正确。逐经验比较引用标准W正/W反；正反权重相等统一为tie（含纯同判及正反抵消），未引用或仅零权重为unused。

一任务一版本只作一次独立质量观察；来源验证(source_validation)满足F/O门槛时更新Q，仅计一次，重估保留这条证据；来源不计下游任务。先验来自经验核对通过的新准入流程，metadata须含admission_protocol=experience_checker_v1，拒绝旧准入参数表。重复回放不重新记账；重估参数必须从基础先验及去重账本重建。

贝叶斯网络为Q→F、C→F、C→O。参数文件严格校验四组反馈概率、两组报告概率和先验；报告表包含correct/error/unknown三列。元数据必须明确available_reports估计范围和来源，防止只截未知列却混用分母。实验表不自动用于决策，只有显式`usable`状态才启用；项目不附带虚构可用表。

逐次更新使用对数似然并保存对数赔率，避免展示概率舍入为0/1后无法恢复。账本记录等比例缩放后的两侧似然及前后概率，缩放不改变后验比。参数缺失/实验状态、未知O、综合结果缺失、未引用或仅零权重都显式记录跳过原因。零似然矛盾属于参数错误，不能当负反馈。

## 4. 经验检索与选择

只为活跃版本的完整四字段建立向量与BM25文档。两路通过RRF融合，k=60、Top20；关键词无命中时不贡献任意排名分。排序并列按稳定ID处理，退役版本不可召回。向量失败不静默切成关键词实验。

Selector最多5条，可读取Q、独立后续任务与回放更新次数；Generator不读质量私有统计。质量变化不改变方法文本，不触发重复编码。回放检索器复制只读向量缓存，在隔离索引中替换目标版本，不污染实时池。

## 5. 修订与回放

每3个不同下游有效F任务消费一次检查机会，包括同判与O未知/失败的任务；来源、回放、unused和重复任务不计，正反抵消作为tie参与计数。程序只检查有本轮新增Q证据时的Q<0.5，或最近6任务同环节至少3次未消费错误报告；按stage/task_id持久化消费记录，未消费错误可跨批次积累。没有理由则不调用模型，也不会在同一批证据上重复检查。

抽样最多6个任务，按3问题+1来源+1正向+1适用性争议优先级去重，不足用近期记录补足；来源可沿父链追溯。输入版本明确，祖先记录不视为新版实测。Updater仅Keep/Revise；文字完全相同视为Keep。

两臂在固定池快照中使用同一案例、角色配置、检索/Selector与Judge。旧臂也实际回放，避免旧记录的环境差异。正向+1、反向-1、其余正常结果0；未选择仍有效，技术失败缺失。仅比较两臂共同有效任务，至少3个且新版总分严格更高才替换。此指标不是长期P/N，也不是独立泛化证据。

通过后父退役、唯一子版本激活、血缘和事件在同一Memory提交。子版本从基础先验及自身有效回放重建Q，不复制父Q；未通过则父不变，候选及失败结果只留事件记录。首版无Split。

## 6. 持久化、故障与冻结

Memory状态先在独立副本修改/校验，再以临时文件、fsync和replace提交；读取返回副本。Trajectory追加实际完整样本，Web无需依赖旧数据路径推测原文。Memory与Trajectory不是跨文件事务。

CLI创建新目录，快照代码、配置、参数和原始请求。完成/暂停后保存Memory与Trajectory哈希。续跑只接受同V2协议、代码/提示词/数据/参数/配置一致、哈希完好且轨迹是有序训练前缀的已认证检查点；运行中崩溃未认证的状态拒绝续跑，不补造成功。

格式纠错默认最多2次，网络重试独立受backend配置约束。样本级耗尽记录错误继续；Checker失败不安排后台补跑；Updater或回放失败保留父版本。鉴权、配置、存储、数据与程序错误fail-fast。

冻结评价顺序执行（`test_workers=1`），只检索/选择/生成/Judge，不运行Critic/Checker、不写池、Q或修订。终测标签不回写训练。

## 7. 配置、界面与验收

入口配置仅保留V2的default/openai.example/qwen3.5-flash/helpsteer3-v2-qwen-flash；数据准备单独使用`scripts/prepare_helpsteer3.py`。参数文件可空，不能因此恢复旧信用。

Web仅识别V2运行；经验分活跃/退役，展示四字段、Q与参数来源、后续/回放证据、完整应用、触发归纳案例、版本与配对回放。排序、搜索和点击滚动位置保留，删除全部类别控件。只监听127.0.0.1，翻译桥接保持原有本地苹果实现；本次不自动启动服务。

离线测试与角色独立复测结果见计划70及报告。模块局部通过不证明贝叶斯诊断正确、原子性已解决或完整链路收益。旧运行产物已按用户授权清理；保留数据及缓存，复测所需历史输入隔离保存于artifacts。


## 7. 审查修复约定

Python最低3.10，推荐本机3.12；旧解释器在包入口明确报错。任务身份由空白归一化文本计算，来源与重复任务在线和重估采用同一排除规则，重估清理旧似然/概率派生字段。

Memory保存完整参数快照及重估事件；线上加载拒绝参数内容或状态变化，显式`reestimate`输出到新目录，不覆盖原运行。生命周期校验覆盖环、单活跃版本及创建/退役双向事件；事件候选保留激活时的出生快照，而不是未来实时Q。重估后的当前Q以Memory为准，历史轨迹中的Q保留原参数时期含义。

训练模式由是否配置test明确区分；无test的完成状态为training_completed，不伪装成冻结评价完成。CLI正数限制在创建目录前检查；配置了test且训练结束必须评价。held-out数据准备仍需单独任务授权。

应用记录补齐recalled/selected/cited、retrieval_rank/trace、round_number/no_evidence_reason；修订case_refs保存实际版本、phase、轮次与用途。Selector的effective_tasks仅统计独立下游任务，replay_tasks另列。Updater读取程序聚合O、原始结果和入账原因。细项Checker结构化且总状态必须一致，零权重引用保留检查能力。Embedding保存原始输入、向量/失败、模型及usage；费用未配置单价时明确null，不虚构费用。

F使用十进制Fraction精确比较；1e-12仅用于已有展示分数一致性校验。Rubric明确2至8条，不增模糊容差配置。数据准备只保留HelpSteer3与通用JSONL，无RewardBench下载接口或生产兼容。

参数metadata必须声明`feedback_protocol=net_direction_tie_v1`，拒绝旧tie仅含同判的表；Checker调用粒度保持每个实际引用版本三个独立报告。此次为确定性聚合修正，不修改角色提示词，不追加真实LLM复测。

采集模式`run.mode=collection`在配置加载时拒绝parameter_file、revision_enabled=true和test路径；Selector的include_quality=false剔除全部私有质量与历史使用统计，其他角色不变，Memory无参数因此Q保持未估计。正常learning模式保持原接口。

Web展示按[计划74](plans/74-WebUI阅读体验.md)使用短编号、中文状态与结构化详情页签；标准/Judge/Checker/候选均直接展示正文，JSON仅用于元数据与调试。列表和详情独立滚动，搜索保持焦点并同步选中结果，原始调用按需加载与角色筛选。Markdown展示只生成文本节点和固定标签，不执行实验文本中的HTML。

Critic/Updater方法示例按计划75展示完整嵌套参数与无模板取舍；明确JSON null不得写成字符串，回答内容、待判结果和推测约束不作绑定参数。Critic每轮0或1条候选，Updater仍Keep/Revise一条，不改变Generator/Checker协议。

Generator原始weight目标总和1，提示词用多条预算示意并明确不可照搬；Calculator继续Fraction归一化且保存原始权重，不因总和偏差追加格式纠错。没有强制不等权，具体相对重要性仍由Generator判断，见计划76。

角色提示词按计划77将字段取值规则与JSON示例分开：明确布尔true/false、枚举合法集合、编号来源、数量及null/空集合分支。Judge的reason为简短判断理由，不要求逐字摘录；示例不替代完整取值说明。

调用日志采用call_id关联模型请求与独立contract_validation事件；格式校验结果含valid/invalid及字段路径，不能将HTTP200等同于结构通过。Web合并展示这些事件；历史缺少校验事件时仅依据已有纠错反馈及轮次终结错误标注，不猜测未记录状态。

计划82新增ExperienceReview(approved,reason)，ProposalAttempt保存核对报告，Experience保存source_sample与admission_review。核对器技术失败只记录并终止当前候选分支，不伪造拒绝原因；入池后应用技术失败保留经验。collection无参数时仍记录来源反馈/执行Checker但不更新Q。
