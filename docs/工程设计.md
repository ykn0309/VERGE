# VERGE v3.1工程设计

2026-11-13。本文是[方法设计](设计方案.md)的目标工程约束，**尚未实现**。当前`verge/*.py`仍执行v3，原实现说明见[v3工程归档](历史设计/2026-11-13-v3/工程设计.md)。不在文档任务中修改代码、提示词或原实验状态。

## 1. 模块职责

源码继续保持扁平结构，配置、测试、文档分别放`configs/`、`tests/`、`docs/`。

| 模块 | v3.1目标职责／相对当前实现的变化 |
|---|---|
| `models.py` | 表达共享初稿、最多三个独立单经验路、无经验修订路、逐轮单候选验证及不确定状态；不再以唯一实际训练路径代表全部试用 |
| `retrieval.py` / `ranking.py` | 程序先召回排序，保留10候选与6历史＋4全池语义；按任务组内单条收益均值作相似度加权，不设正收益使用门槛 |
| `modules.py` / `prompts.py` | Selector训练最多3条、推理最多1条；Generator分初稿与修订；Critic接收人工理由、分析三类问题并允许不提案，每轮最多1条 |
| `pipeline.py` | 共享初稿后各路一次修订，训练最多四路且无组合；所有路径明确失败才触发Critic；推理单路冻结 |
| `feedback.py` | 每条经验独立计算有／无经验差值，按不同任务去重；部分未知不抹掉其他有效配对，来源验证不入账 |
| `clustering.py` | 具体提供边按对侧类别汇总成归一化分布，两侧交替更新并刷新分数；不再仅比较具体对象ID交集 |
| `memory.py` | 原子发布经验、关联、收益和完整轨迹；新候选无来源信用及关联，不继承旧经验收益 |
| `llm.py` / `scheduling.py` | 统一请求限流、有限重试、样本并发；网络和格式失败局部记录，继续其余样本 |
| `web.py` / `web_assets/` | 区分版本；显示初稿与修订、三条平等试用、无经验对照、单候选分轮验证，保留原始请求回复 |

## 2. 数据与可见性

保留三字段经验及独立ID、来源、可选parent追溯。记录召回分数、证据量、选择理由、共享初稿、各路输入与输出、Judge原判、Critic诊断与候选、技术错误及实际设置。

人工偏好理由来自样本metadata，仅传入训练Critic。Response 1／2映射需与chosen／rejected一致；执行Generator和Judge不得读取标签、人工理由或Critic诊断。Judge双侧独立匿名评价。

无经验对照使用修订稿；训练记录每路结果，不定义首选路径或事后最佳输出。统计最多三条的覆盖和推理准确率时使用不同口径，不将共享基线当多个独立任务。

## 3. 并发、失败与保存

沿用样本开始时读取历史快照、完成后原子提交的原则；所有初始路径和候选验证完成后才冻结。初稿生成先于依赖它的修订，各独立修订和Judge可在统一限流下并发。

网络、格式、虚构ID等问题有限次重试，保持输入与协议不变；耗尽记录当前路径未知，继续其余任务。技术未知不计算为0收益、不作为Critic内容失败。共享初稿失败、存在未知但无成功时的流程及候选初稿复用，尚待明确，实施前不自行补齐。

v3检查点语义包含组合四路和唯一实际路径，不能直接当成v3.1训练状态。新状态格式和迁移／拒绝策略需另行设计；旧数据只读展示，复现使用对应Git提交，不重写原日志。

## 4. 实现与验收边界

当前尚未创建v3.1运行配置或启动实验。下一阶段先明确方法中的剩余参数和失败规则，再制定执行计划，实现及检查范围以该计划为准。

验证应覆盖：三条逐一对照、无经验同等修订、每条信用与未知独立处理、来源排除、Critic全部失败门槛、人工理由映射、交替更新及冻结只读。结构合同通过不代表经验泛化、Selector正确选择或Judge可靠。

新实验完整保留输入、版本摘要、原始请求回复和失败；旧日志归档忽略，最新日志以文本上传并提供可读索引。WebUI继续仅监听127.0.0.1，不在本任务增加服务或复测。
