# 105 — 任务归类与经验适用性共同学习

2026-11-05。状态：用户提出并要求据此重设计的研究方向；以下机制为候选，未实施、未实验、未选定最终模型。不修改现行运行时设计与参数。

## 1. 转向依据

此前对话候选按预先固定的任务条件k，对每条经验e独立估计使用收益，并预留所谓“校准集”。用户指出，相关任务难以预先取得，任务分类本身应是学习过程的一部分：经验通过下游任务验证，任务也通过经验的效果来归类；混合检索和LLM归类仍参与，但不能将它们的初始判断固定为真值。

因此撤回“已有可靠固定类别＋为各类预备足够任务”的前提。此前HTML两版仅表达旧候选，不应视为当前方向或已采用方案。用户没有要求启动实验，本轮不训练、不调用生产模型、不改经验池。

## 2. 建议的学习对象

保存任务与经验版本构成的稀疏关系表。每个已运行关系保存task、经验版本、实际Rubric、Judge判断、偏好标签的核对结果，以及有无对照、调用失败与不确定性。语义相似度、LLM的适用性判断、模型预测效果、实际运行观测分别保存，不能混称“有效”。

任务之间的关系不必是唯一、互斥的类别。A和B可能在“需要核对原著依据”方面相近，同时在格式、交付数量等方面不同。同一经验对A、B有效，只是这条方法所涉及维度上的正向支持；通用经验对几乎所有任务有效时，区分任务的能力较弱。不同经验的效果差异可以修正初始分组，允许重叠、拆分和未知。

## 3. 候选训练过程

1. 新任务进入时，混合检索召回旧任务及经验；LLM根据task及可见经验给出初始适用性、相似点与区别，不读取当前真实偏好标签。这是待验证的起点，不是类别真值。
2. 结合先前效果记录预测哪些经验可能有帮助，并保留受预算约束的探索。不要只试当前最看好的经验，也不要要求每题遍历全部经验。
3. 使用经验实际生成Rubric并完成评分。记录原始流程结果。需要判断“提供该经验是否带来净改善”时，在预定子集上补充单条有无对照或明确背景下的移除对照；选择不同背景会改变估计对象，不能互相混用。
4. 用同一批新观测共同更新经验的任务适用范围、任务表示/相似关系以及对未测试任务—经验关系的预测。一次Judge判对、经验被引用、或现行F正向均不能直接当作净收益标签。
5. 根据实际失败轨迹提出经验修订或新候选，准入仍需审查提炼忠实性。来源案例和反复修订回放不充当独立迁移验证；版本改变后明确证据归属，不默认转移所有旧证据。
6. 新任务继续到来后重复；用下一批未见任务检验预测。最终独立评价冻结学习状态，或另行预先规定逐任务先预测后更新的在线评价，不能边看答案边改后再报事前效果。

不再要求先按同类任务填满校准数据。训练任务逐次进入、逐渐积累关系；独立评价仍应保留。没有对照时只能评价绝对表现或弱相关线索，不能声称已经识别经验的净收益。

## 4. 模型如何承载相互反馈

第一候选是带文本信息的任务—经验关系模型。为任务学习可重叠的需求表示，为经验学习作用表示，二者共同预测某次使用的效果分布。混合检索、LLM提供新任务和新经验缺证据时的初始信息；实际效果观测更新两侧表示。任务类可以由表示中的共同结构归纳，类别不再是建模的已知输入。

若采用贝叶斯版本，其基本依赖是“任务潜在需求 → 观测效果 ← 经验潜在作用”，文本影响两侧先验。通过观测效果共同推断任务和经验的潜在状态。这种更新不能继续假装是固定(e,k)四格计数独立加一；具体似然、表示维度、共享方式与推断计算尚未确定。训练中的双向更新不意味着在贝叶斯有向无环图中添加有向循环。

关系数据联合发现类别可以参考Kemp等人的Infinite Relational Model；任务—经验两侧表示可参考概率矩阵分解。它们仅支持“可从关系共同学习结构”的技术思路，不证明适合VERGE。IRM原模型采用单一类别归属，不应直接冒称支持本候选的重叠任务需求；BPMF面向评分数据的高斯模型，也不能不加改造直接作为四类效果模型。

## 5. 必须分开的证据与下一步

“根据A预测B”可以指导下一次试验，不能当成B已经验证。只有B自身新的实际观测才能给B增加直接证据。同一份反馈可在一个共同模型中更新多个相关未知量，但不能作为两份独立证据重复入账。

现有ApplicationRecord保留了sample、版本、Rubric、judgment、F/O、检索/选择/引用和理由，可以作为原始轨迹基础；当前F是引用标准的方向汇总，不是有无经验的净收益，不能直接改名使用。部分轨迹同时使用多条经验，也不能将整题收益分给每条经验。

下一步仅细化：观测效果的定义与预算；从文本预测新任务表示的方式；如何联合更新、避免通用经验把全部任务连成一类；未知关系、选择偏差与版本的处理；比较语义检索、固定分组和共同学习三种方案的最小反证设计。未选定模型、数据规模、成本或成功阈值前，不启动实验。

## 6. 用户进一步提出：学习整条评分流程

2026-11-05补充方向。训练和推理的主体均为：任务选择经验 → 应用经验生成Rubric → 按Rubric评价回答。优化目标是新任务上整个流程更好，而不只提高经验池质量；经验作用必须结合任务、应用和评判来考察。用户的图作为执行关系示意，不据此宣称已经定义了概率图或因果关系。

该方向扩展了上文任务—经验关系学习，尚未选定具体算法，不修改现行运行协议。旧方法通过改写经验也可能间接改变选择和应用，不能说完全没有影响；不足是没有明确学习并验证每一环节的行为。

下一版需分别定义训练后留下什么：选择环节的任务条件与经验集合决策；应用环节的可执行使用方式与边界；评判环节对标准及证据的执行方式。仅学任务—经验权重、将其作为提示参考，不足以宣称后两环节也已得到训练。是否采用策略学习、规则记忆或参数训练，仍待讨论。

训练可探索多条候选流程，但最终推理执行相同三步、使用相同可见信息。任务始终直接约束Rubric和判断，Judge还需候选回答；经验不是唯一任务依据。真实偏好与纠错反馈只在训练端使用。只有整体偏好标签时，无法直接判定三个环节谁错，需通过有计划地固定部分环节、改变其他环节的执行来获取可解释的反馈；不把额外Checker意见当真值。

经验文本的内在缺陷与在某类任务上的收益应分开：后者随任务、应用方式与评判变化；前者如矛盾、量词偷换仍应检查。下一步先形成整流程的输入、决策、可更新状态与反馈接口，再确定是否以及如何用贝叶斯网络表示，不先堆叠更多潜在节点。
