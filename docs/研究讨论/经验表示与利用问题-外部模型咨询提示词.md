你是一位擅长LLM评测、经验学习和实验设计的研究者。我在研究VERGE（Verified Experience-guided Rubric Generation），目前遇到经验表示、经验选择和经验应用的问题。请阅读下面完整上下文，独立分析并提出可落地的改进方案。可以推翻现有设计，不必替它辩护；也不要预设问题只需优化提示词即可解决。

一、研究目标与任务

我的目标是从历史偏好任务中积累可复用的“评分标准设计经验”，帮助后续任务生成更好的rubric。经验是设计方法，不是标准答案，也不应记住具体题目的专名、数字、情节或示例。

每个数据样本包含task、chosen回答和rejected回答。Generator只看task和可用经验，生成2至8条Boolean标准及权重，权重总和为1。Judge对两个回答分别独立调用，只看到task、同一套标准和当前一个匿名回答，不看到另一个回答、偏好标签或权重。程序加权求分，chosen得分严格高于rejected才记为判断正确，平分也算未成功。

因此“首次准确率”指评分结果与数据集偏好一致的比例，不是生成回答的正确率。我没有训练大模型权重；所谓训练是按任务积累、应用和修订经验。

二、当前已实现流程

1. 经验对象仅有trigger（适用条件）和principle（核验方法），另存ID、版本、质量后验和历史应用记录。目标是一个经验对应一个可独立采用的核验动作，但实际仍可能混入多个要求、具体场景或过强限制。
2. 直接向量＋关键词混合检索，最多召回20条活跃经验。Selector根据task、经验及质量证据最多选5条，也可不选。
3. Generator接收task＋选中的E，可以使用部分经验或全部忽略；每条标准最多引用一条经验，一条经验可以对应多条标准，也允许无经验来源标准。
4. 首轮失败时，Critic阅读失败轨迹，每轮提出0或1条候选，最多两轮。独立Experience Checker检查候选是否合理、原子、可泛化及是否泄露原题内容；明确拒绝才把核对意见反馈给Critic重写。
5. 候选通过核对就入池，然后新的Generator会话只使用task＋新候选C，不带原E或上一轮标准，再运行Judge。应用失败不撤销准入，也不再把Judge结果反馈给Critic；这次实际应用可提供Q更新证据。
6. 训练中，每条实际引用的经验分别运行Selector、Generator、Judge三个Checker。它们也都是可能出错的LLM，分别检查适用性、方法应用与判断依据。不能把报告当真值。
7. Updater可以Keep或Revise，暂不Split。每3个不同下游任务检查触发条件，结合低Q风险或最近窗口同环节至少3次错误报告决定是否调用。归纳与回放共用最多6个不同任务，新旧版本比较净区分表现（正向+1、反向-1、其余有效情形0），新版本严格更好且有最低有效回放数才替换。该回放是局部验收，不是独立泛化证明。

暂时不建经验间依赖。旧版的类别、Atomizer、严格模板与参数绑定均已取消；长期P/N信用也已取消。这些不是不可推翻的决定，但不要简单地恢复它们而不说明作用和代价。

三、当前贝叶斯机制及局限

每个经验版本有未知质量Q（内容合理/有缺陷）；每次应用有未知执行状态C（选择、生成、Judge全正确/至少一环有错）。观察量为该经验本次反馈F和三个Checker的综合报告O。

F按同一任务中实际引用该经验的标准聚合：正向权重和大于反向权重和为positive，反之为reverse，相等为tie（含纯同判与正反抵消）。没有正权重引用为unused，不更新Q。同一经验每个不同任务至多记一次证据，不把多个标准当作独立任务。

O规则：任一有效Checker报告错误则O=error，即使另一个Checker未知或失败；三者都正确才O=correct；其余unknown/unavailable，本次不更新Q。

网络为Q→F←C→O。逐次更新：
L(q)=对c求和 P(C=c) × P(F|Q=q,C=c) × P(O|C=c)。
新Q后验=旧Q后验×L(1) / [旧Q后验×L(1)+(1−旧Q后验)×L(0)]。

正式概率表尚未估计。最近预实验经我明确授权使用人工假设：Q先验0.60，C正确先验0.80；F按positive/reverse/tie排列：
Q合理、C正确：(0.65,0.10,0.25)。
Q有缺陷、C正确：(0.20,0.40,0.40)。
C出错时，不论Q：(0.25,0.35,0.40)。
O按correct/error/unknown排列：C正确为(0.80,0.10,0.10)，C错误为(0.10,0.80,0.10)。

这些数字不是数据估计结果，不能据此声称Q已校准、能够准确归因或区分好坏经验。新准入经验以先验开始，后续应用更新；修订新版本以自己的回放证据建立Q，不能直接等同旧版本已验证。

四、最近完整对照的实际结果

模型统一为Qwen3.5-Flash，默认关闭思考。HelpSteer3的General、英文、单轮、强偏好一致性筛选数据。训练从空池开始，每批3题读同一批前快照，批内经验不互通，批末合并证据和串行修订。

原计划300题，因耗时提前停止：213题有完整轨迹，另3题已提交经验反馈但批末未完整结束。冻结时86条活跃经验，不能宣称完成300题训练。

测试固定200个不同任务，与实际训练任务不重叠。测试题按任务文本与原计划300道训练题的TF-IDF相似度选择，排除近重复，每个最近训练邻居最多3题；未用回答、偏好标签或测试结果选题。它是刻意选出的相近任务留出集，不是官方测试集，也不代表总体分布。提前停止后没有重选。

两组同题配对，仅比较首次生成与Judge：
无经验：101/200=50.5%。
有经验：92/200=46.0%，下降4.5个百分点。
25题由错变对，34题由对变错。
两组各2次技术失败，都计错。测试期间冻结经验池/Q，不运行Critic、Checker或Updater，未回写测试反馈。

因此，这次负结果既不能证明所有经验无用，也不能把全部失败归因于经验。两组生成和Judge有随机波动，有些退化甚至没有引用经验。没有重复基线来估计波动，也没有独立消融来识别贝叶斯模块的贡献。

五、具体观察到的问题

1. 经验的条件被当成当前事实。
经验大意：名称可能不存在或拼写模糊时，应澄清、防止臆造。
任务：解释“low nefa”的意思。
有经验版本却把大量权重用于检查“回答是否先指出nefa可能拼错或不是既定实体”，替代了直接解释术语。这涉及经验自身过强、Selector未确认前提、Generator照搬策略，尚无完整因果比例。

2. 把合理方法和额外回答义务混在一起。
经验：“任务要求概念定义时，内容只能描述属性，不得包含操作步骤或建议。”
任务：“What is an IOU?”
标准把“不包含任何使用建议”设为高权重项。即使定义准确，补充合理建议也可能被扣分。这项禁止并不是用户要求，经验本身就不够合理。

3. 风格经验挤占任务核心。
经验要求续写保留Name:标签、括号动作，不转旁白。某些角色反应题没有明确要求固定格式，但标准高权重检查标签，忽略角色范围、具体事件和反应是否符合设定。
一条类似经验在测试中引用50次、冻结Q约0.96，也仍出现错误应用；高Q不能证明本题适用。这是应用关联，不是经验的因果贡献统计。

4. 背景属性被升级成额外交付要求。
商品描述任务说“有3种图像变体”，只要求说明这一属性，经验却促使标准要求“必须写出3条具有实质差异的变体描述”；原有关键词、商业权利、结尾应用等要求权重被压缩或遗漏。

5. 背景与待完成动作混淆。
续写材料中前面已经发生的事件，被标准要求在新回答中重新复述；尚未发生的后续情节则被模型当成事实。也有普通任务理解错误、Boolean标准方向反转等，未必由经验造成。

6. 质量信息、反馈与版本问题尚未解决。
假设参数得到的Q可能偏向错误方法；选择正确、使用正确、Judge正确都不能仅由正向反馈保证。经验内容变化后如何处理旧证据仍是设计问题，不能把改写后的经验当作继承了原来的有效性。

六、已经做过的独立优化实验

审查了34个退化案例，并选取改善/正常对照。每模块固定30个不同任务开发（18退化+6改善+6双方结果正确），另外25个不同任务不参与开发调用，冻结方案后确认。历史“正常/改善”只是模型结果标签，不代表内容已正确。

Selector固定实际召回候选及排序；Generator固定历史选中经验，绝不把新Selector输出接到Generator。只复测单模块，不重跑全流水线，不修改原经验池和旧日志。语义复核由Terra子代理分工完成，不是人工真值，也不是三模型独立投票。

累计10轮开发对照和一次确认，970个角色最终输出，不是970个任务。尝试包括：
- 添加前提核实/任务优先提醒，重写主指令，原创few-shot；仍反复误用。
- 把适用前提与历史方法建议分开呈现；改善不稳定。
- 用历史task-only rubric作为锚点；会复制草稿错误，有时只是减少经验使用；部署还需额外一次生成。
- 去掉Selector的Q/历史展示，把task放最后，区分背景与输出动作；有局部改善，但多项同时变化，不能单归因去Q。
- 固定上述输入提示词开启思考；未显示稳定内容优势，日志Token约11.2万增至39.6万（含重试），不支持默认开启。
- 草稿→独立核对→最多修一次；核对器误放/误拒，正确指出问题也不保证修复成功，部分案例反而退化。
- 离线规范化经验文字：86条中72条由Terra调整，保留核验动作、去掉过强回答义务。比如“禁止建议”改为“不能只给建议而不解释”，“必须角色标签”改为“保持语义衔接”，“无法证实”等于“不存在”的关系拆开。这是实质内容修订，不是单纯换字段名称，也不是已验证的自动规范化器。
- 最有希望的是“规范化文字＋任务优先输入”，固定后重复开发对照，再用25题确认。原经验与规范化经验的ID/候选列表/排序固定；两臂Selector均不展示旧Q，Generator本来就不接收Q。旧Q没有写给改写后的生产经验。

25题确认中的Terra复核标记：
Selector：明确利用缺陷17→6，归因待判4→6；候选另有1次契约失败。
Generator：明确利用缺陷21→2，但归因待判2→14，不能把待判算通过；两臂各16题有基础错误，候选在5个正常对照新增实质问题，如错认回应者、遗漏原创要求、Boolean方向反转。

这些不是经人工校准的误用率，也不是整体偏好准确率。25题虽未参与前轮模块调用，其历史案例曾被最初审计看过，因此不是严格未见盲测。审查代理在此前工作中接触过案例，不能宣称规范化过程完全盲于开发材料。当前没有修改生产提示词/原经验池，也没有重新验证全链路准确率提升。

七、我的目标和约束

- 希望经验是原子的、有条件的、可泛化的核验方法，能通过后续使用与演化变好。
- 接受单条经验和Judge有噪声，不追求先把所有模型误判清零；但不能只假定“次数多了自然抵消”或“再加一个Checker就可靠”。
- 需要兼顾经验内容、适用性、实际应用与信用含义，不希望用一个分数掩盖所有问题。
- 我怀疑“每条经验内部的组织/表达形式”需要改进，但还不能断定增加字段、类别或层级就能解决。请独立判断，不必附和。
- 希望复杂度可控，不想不断堆角色、分析字段、审核轮次、复杂信用分配和无限提示词试验。也不要求为了保留贝叶斯网络而强行设计。
- 如果建议升级模型、更严格的程序限制、额外调用或外部知识，要明确它解决哪个已观察问题、成本及失败方式；不能把语义正确性冒充成结构校验。
- 不希望通过刻意少选/不用经验、丢掉失败题或复用调优数据来制造提升。对独立复测需同时看问题样本、正常样本、边界样本与真实内容。
