# VERGE — 设计总览

VERGE（Verified Experience-guided Rubric Generation）研究：如何从preference trajectory提出供首次rubric生成使用的经验，先审核其表达与边界，再观察实际应用结果，并通过后续任务维护可信度。

> **版本状态**：计划31已按用户“开始实现”授权落实到代码，230项离线测试通过。分支 `feat/critic-experience-validation` 从 `7ab9bdc` 建立，历史main与分析报告保持；旧实验日志随后按用户指示清理。新版只使用候选先准入、新会话自主应用及正负分别累计。实施记录见[计划31](plans/31-Critic候选经验准入与新会话验证.md)。本次代码与日志清理按授权提交，未push或开展付费验证，离线结果不证明语义效果。

## 1. 总体流程

```text
task → Retrieval / Selector → 固定所选经验 E
→ Generator(task + E) 生成R0 → Judge
→ 按R0实际来源标注计算已有经验下游信用 → 回写置信度与证据
→ R0成功：保存轨迹，下一任务
→ R0失败：进入统一的候选经验应用流程（最多2轮）

每轮：
Critic提出0–1条候选C → Admission
  FAIL：被拒候选及拒绝原因反馈同一个Critic，每轮可重生成一次
        再FAIL则结束本任务，不进入Generator
  PASS：候选原文固定 → 全新Generator(task + 固定E + C)
        → Judge
          成功且声明采用C：Fusion → 入池及应用验证弱证据
          成功但未采用C：任务成功，C未验证，不入池，结束
          失败：反馈实际rubric、Judge及采用记录，若还有机会则下一轮
最多2轮；第二轮失败后结束。全部路径留档。
```

成功后不调用Reflector，不重写一条解释成功的经验；Admission放在应用之前，Fusion后不再追加Admission或其他审核角色。训练结束冻结经验池，再进行held-out初始生成评价。

## 3. 已确认原则

1. Generator始终不接收偏好对、身份、Judge结果、Critic私有分析或普通修订建议；只接收task与本次可用经验。候选泄漏风险仍存在，提示词与Admission不是安全性保证。
2. 每次应用采用全新会话；不得把旧rubric、旧analysis、旧assistant或前轮候选隐式带入。固定原始E，不重新检索/筛选，不再新增Selector调用。
3. E与C同为可选指导，Generator自主采用、组合或不采用；任务目标和明确约束优先。E有历史可信度，C仅已准入，不伪造历史证据，也不因来自Critic获得优先权。
4. 单次Critic最多一条候选，允许没有可信指导时不生成。每轮最多2次业务候选生成，最多2轮应用；Critic业务生成最多4次，应用生成/Judge最多2轮。底层有限纠错另计；格式/结构耗尽按既有样本/无效轮隔离继续，不引发全局终止，不增加业务预算或伪造Judge失败。
5. Admission FAIL不进入Generator。第一次FAIL反馈被拒候选与原因；第二次FAIL结束样本，不能挪用下一轮来继续准入。
6. 下一轮Critic依据实际失败生成结果、Judge和上条通过的候选/采用记录；旧私有叙事不代替证据。准入重生成仍处理本轮相同失败基线，不能伪造应用结果。
7. 经验描述首次生成rubric的指导，trigger在生成前可识别；允许task、上下文、领域知识推理及协同动作，不要求单一动作或跨所有领域通用。
8. criterion采用正向Boolean语义：“是”表示满足要求；1–10重要性由task支撑。评分不支持部分分、否决或自动去除不适用项，不新增自动语义门禁。
9. “提供C”“声明采用C”“Judge成功”“Fusion入池”分别记录。来源标注仅是采用的可审计自报，不证明因果贡献。未采用不视为有效，也不直接视为无效。
10. R0成功/失败之前都计算已有经验P/N；实际引用且P+N>0才更新，净方向为0也可能有双通道证据。整体成败不等于所有经验涨/降信度；后续失败不撤销R0更新。
11. 只有准入PASS、采用标记成立且Judge成功的同一候选能Fusion。成功但未采用C则结束任务，不为验证C强行继续。
12. 已有经验R0与应用候选统一按来源标准的正向P、负向N分别累计：alpha+=P、beta+=N，不先抵消、不使用lambda或margin增益。P=N=0才不更新；净方向只展示。整体成功仍可有负证据，不改变入池资格；累计强度增P+N，不是独立任务数或质量认证。
13. Fusion默认ADD；只有同一设计问题的等价指导或必要细化、条件兼容才MERGE。保留旧ID/Beta/证据和文本版本，继承证据不认证新文本。
14. Held-out冻结池、Beta与文本，不提出/准入/验证新候选，不回写信用。删除无经验诊断模式及experience_enabled开关，空池仍正常执行新经验学习。面向人阅读的模型文本使用中文，机器协议字段保持原样。
15. 不兼容旧方案协议、字段、配置、提示词或Web展示；历史main与产物保留，不要求新代码读取。鉴权/网络、数据/存储与程序异常仍沿现有全局故障策略，格式等角色输出错误不全局终止。

## 4. 生命周期与实施边界

空池时E为空，R0失败后仍可提出候选；第一条符合入池条件的候选成为经验池起点。仅Admission PASS不入池，也不被向量检索。已有经验R1/R2采用标记仅用于应用审计，仍不重复追加R0下游信用。

历史基线及其证据公式保留在main、旧计划和既有产物。新实现使用新方法/提示词标识及全新输出目录，不跨方法resume、不迁移旧字段、不保留旧诊断或展示分支、不重写历史消息。技术错误隔离与无折扣、正负分别累计规则均已确认；最终新字段在实施时直接定义，不做旧协议兼容。代码已实现并获提交授权；真实实验仍需另行授权。
