## 1. 目标流程

```text
task → 向量＋BM25/RRF → Top20类别/未分类单位 → 展开 → Selector → 固定E
→ Generator(task＋E)生成R0 → Judge → 训练R0按版本写入P/N和同判计次
R0失败：最多两轮Critic草稿 → Atomizer原子候选集合C
  → 新Generator(task＋固定E＋当前C) → Judge → 各候选独立资格
  正常收尾：最新合格轮的合格集合入池，不跨轮拼接
样本收尾：当前版本每5条新下游有区分反馈 → 最近5条 → Updater
  keep：保持版本，消费窗口
  revise：Atomizer → 相同文本则keep，否则新ID替换/拆分
  新版本各有独立先验，修订继承/拆分均分历史信用，并分配0.2×窗口累计信用的惩罚；子窗口重新开始
新活跃版本 → 待分类队列 → Top10类别混合检索 → 局部归类
  → 批末受影响类别更新name/description → 刷新索引
```

新候选必须实际引用且自身P>N；演化新版本直接以继承信用及演化惩罚激活，不额外进行入池验证。两种出生路径不能混淆，详见[候选生命周期](设计方案/09-修订信用分配与准入.md)。

## 3. 关键约束

1. Generator只见task及本次可用经验ID/content/trigger，不见偏好对、Judge、私有分析、类别或信用。E在本题ID/文本/顺序固定，第二轮只替换整个C。
2. Critic保留样本内真实消息，第二轮另附Atomizer结果和应用反馈，不把派生产物改写为Critic原始回复。只有Judge疑点而无可信方法可空候选。
3. Atomizer独立调用，输出每条trigger/content；已有原子方法原样返回，拆分保留必要条件，不新增方法、analysis或额外审核器。150/60字符仍仅提示词约束。
4. 正向Boolean问题、有限正数相对权重和程序归一化保持；不引入部分分、总分否决或自动跳过。Judge理由是模型解释，不是事实认证。
5. 每条候选被引用且P>N才具资格，不要求整体成功；正常结束入池最新合格轮的全部合格项，不跨轮累积。Judge/拒答/请求错误结束不正常回退入池。
6. P/N按引用标准归一化额度、多来源均分，alpha+=P、beta+=N，不折扣、不先抵消。已有版本仅R0计分，合法R0证据不因后续错误撤销。同判只分别计次，不计信用、不进归纳。
7. 每5个新的本版本下游有区分任务使用最近5条归纳，正负均可，P=N>0也计任务。来源/祖先案例不计窗口，完整历史不丢弃。正常keep消费本批，失败新案例驱动有限重试，不在同题循环，不再10条永久冻结。
8. 已有正文和trigger固定；修订/拆分产生新ID及空窗口，父退役保留账本。修订继承历史P/N与旧惩罚，拆分均分；本次总惩罚为最近5例累计(P+N)的20%，子版本均分，各有(1,1)先验。keep、同文本及失败不惩罚。无家族或类别信用；继承不是本版本验证。
9. 类别与成员分别索引，文档级向量＋BM25/RRF后映射单位取max，聚合后Top20任务单位/Top10归类类别；类别命中完整展开供Selector最多选5条。全部成员参与检索，不把全类别拼成一个向量。
10. 归类器只改目标归属；批末描述更新器只改name/description，无成员字段。默认5条待分类队列触发与5案例归纳是两个计数器。描述失败不回滚成员，不在同批反复归类。
11. held-out冻结信用、usage、案例、演化和类别，只运行检索/选择/R0/Judge及只读缓存。真实LLM默认Qwen3.5-Flash关闭思考。
12. RRF k=60、归类展示最多3条相关成员、多候选按轮选择和失败窗口规则属于已写明的工程初始约定，须按计划67检验，不声称最优。

## 4. 实施与证据边界

代码已实现，局部验证不代表整体效果。新协议已分配Memory8、Manifest/Trajectory10，不兼容旧schema、不跨方法resume，不因同步文档修改原池或日志。当前实验和结果保留其原协议解释。

先做确定性账本/状态/权限测试，再每模块至少20条有代表性真实历史来源的独立复测，记录转换、预算、原始请求和语义退化；结果不反馈给后续案例。局部通过不证明整体准确率、泛化或因果收益，不自动扩大为完整训练。

不新增外部Judge核验、Admission/Fusion、探索名额或自动信用回滚。错误原子化、更新退化、继承信用影响新版本选择、描述漂移和大类别展开预算等风险须报告，不能以状态机执行成功替代方法效果。
