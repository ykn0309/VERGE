# VERGE — 设计总览

VERGE（Verified Experience-guided Rubric Generation）从 preference trajectory 提出供未来首次生成评分标准使用的经验，直接观察独立应用结果，再用后续任务表现维护可信度。

> 当前协议已按用户要求删除 Admission。实施见[计划42](plans/42-删除Admission直接应用候选经验.md)。计划31–41保留当时的流程与实验结果，不代表当前执行规则。最新已完成实验见[计划43](plans/43-无Admission固定Flash30样本实验.md)。当前已按[计划44](plans/44-相对权重与Judge依据反馈.md)实现相对权重与Judge依据反馈，尚未运行该版本真实实验。

## 1. 总体流程

```text
task → Retrieval / Selector → 固定所选经验 E
→ Generator(task + E)生成R0 → Judge
→ 按R0实际来源的P/N更新已有经验 → 回写Memory
→ R0成功：保存轨迹，下一任务
→ R0失败：最多2轮候选应用

每轮：
Critic提出0–1条候选C
  空候选：结束，记录no_candidate
  有候选：固定原文 → 全新Generator(task + 固定E + C) → Judge
    成功且声明采用C：Fusion → Memory
    成功未采用C：任务成功，C未验证，不入池，结束
    失败：有剩余轮次则依据实际失败结果提出下一条候选
最多2次业务提案、2次应用；技术纠错单独计数。全部路径留档。
```

Critic候选直接进入Generator，没有准入审核或拒绝反馈重生成。成功后不调用Reflector重新解释成功，也不增加审核角色。训练结束冻结经验池，再做held-out初始生成评价。

## 3. 已确认原则

1. Generator只接收task与本次可用经验，不接收偏好对、Judge、Critic私有分析、旧评分标准或会话历史。
2. E为R0之前固定的列表和文本；每轮仅替换当前C，不重新筛选E、不积累旧候选。
3. E/C均可自主采用、组合或忽略，任务目标和明确约束优先。C标注“当前候选、尚未验证”，不伪造历史confidence。
4. 每轮Critic提出一次，候选0–1条，最多两轮。格式/结构耗尽消耗当前轮，在剩余轮次内可继续；不伪造Judge失败、不增加业务机会。
5. Critic区分任务要求、标准文本、回答事实与Judge结果；只有Judge疑点而无可信设计动作时可空候选。下一轮依据实际应用及采用记录，不以旧私有叙事代替证据。
6. 经验用于未来首次设计评分标准。content描述方法，trigger从生成前的task、输入、上下文或领域知识识别。实例转为语义角色或任务参数；允许必要领域限定、通用说明和同一目的的协同动作，不用举例词作自动门禁。
7. 评分采用正向Boolean问题和task支撑的相对权重预算，不增加部分分、总分否决或自动跳过机制。
8. 提供C、声明采用C、Judge成功、Fusion入池分别记录。来源是模型自报，不证明忠实实施或因果贡献。
9. R0有效Judge后，成败分支前写入已有经验P/N；应用里的E引用仅审计，不重复记账。后续失败不撤销R0更新。
10. 候选只有实际提供、声明采用且Judge有效成功才可Fusion。成功未采用C则结束，不为验证经验强行继续；候选信用方向不另设门槛。
11. R0与应用信用按引用标准的正向P/负向N分别累计，alpha+=P、beta+=N，多来源均分，无折扣、不先抵消、不用margin增益。双通道均0才不增加数值证据；净方向仅展示。
12. ADD保存实际应用的候选原文并以Beta(1,1)开始；MERGE只合并同一设计问题的兼容指导，保留ID、旧证据及文本版本。继承证据不认证新文本。
13. Held-out冻结池、文本及Beta，只执行检索、选择和R0生成/Judge。当前真实实验的所有LLM角色固定Qwen3.5-Flash、关闭思考。
14. Judge每项返回Boolean与简短依据，Critic核对两侧理由及原回答；理由不是事实认证，不进入Generator。
15. 轨迹/manifest为版本4，Memory仍为版本2。不兼容旧流程运行、展示或跨方法resume；当前及后续产物保留；此前历史清理以计划43记录为准。
16. 鉴权/网络、数据/存储、Calculator及程序错误仍fail-fast。角色输出错误保持有限纠错与样本/无效轮隔离。

## 4. 实施边界

空池也能直接提出和应用候选。删除Admission使候选能够更频繁地得到实际应用，但不证明经验质量、Judge正确性或任务效果提升。真实效果需新目录实验；本次只完成代码、离线验证和文档同步，不自动启动付费请求。历史结果保留在各阶段计划及原始产物中。
