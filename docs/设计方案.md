# VERGE — 设计总览

> 当前以[计划61](plans/61-延迟归纳与正负案例经验更新.md)为准：保留正负累计，同判轻负信用，正负案例延迟归纳，取消拆分。Manifest/Trajectory7、Memory5，不迁移旧协议。

VERGE（Verified Experience-guided Rubric Generation）从 preference trajectory 提出供未来首次生成评分标准使用的经验，直接观察独立应用结果，再用后续任务表现维护可信度。

> 当前实施为[计划61](plans/61-延迟归纳与正负案例经验更新.md)；候选生命周期及Critic样本内多轮保持。历史实验和计划保留，不代表新机制效果。

## 1. 总体流程

```text
task → Retrieval / Selector → 固定E
→ Generator(task+E)生成R0 → Judge → 训练R0来源P/N写入
R0失败：最多两轮Critic提案 → 独立Generator(task+固定E+当前C) → Judge
  候选被引用且自身P>N：暂存合格候选，与整体成功独立
  整体失败且有预算：Critic接续反馈，Generator第二轮仅替换C
  正常结束：合格C2优先，否则回退合格C1；每题最多新增一条
样本收尾：R0有信用的已有经验 → 收录正负案例 → 每3个不同下游任务归纳
归纳只更新同一ID的content/trigger，不拆分
第10个案例强制最后归纳；之后案例/文本冻结、继续信用累计
```

没有Admission/Fusion模型，未选候选不记入池信用。归纳员读取一条经验的全部有限案例卡片（完整回答、相关标准/Judge），逐标准提供反馈方向，不提供P/N、权重或共享来源数；Generator不见已选经验的历史可靠性数值。程序和审计仍保留数值，见[计划53](plans/53-角色输入精简与定向示例.md)。不合并两条池经验。held-out冻结文本与Beta，只评价R0。

## 3. 已确认原则

1. Generator只接收task与本次可用经验，不接收偏好对、Judge、Critic私有分析、旧评分标准或会话历史。
2. E为R0之前固定的列表和文本；每轮仅替换当前C，不重新筛选E、不积累旧候选。已有E文本归纳在本样本候选过程结束后执行。
3. E/C均可自主采用、组合或忽略，任务目标和明确约束优先。C标注“当前候选、尚未验证”，不伪造历史confidence。
4. 每轮Critic提出一次，候选0–1条，最多两轮。格式/结构耗尽消耗当前轮，在剩余轮次内可继续；不伪造Judge失败、不增加业务机会。
5. Critic区分任务要求、标准文本、回答事实与Judge结果；只有Judge疑点而无可信设计动作时可空候选。同一样本内第二轮接续首轮请求和真实assistant回复，追加实际应用及采用反馈，重新分析并提出经验；历史analysis不代替事实。消息不跨样本，Generator仍为独立新会话。实施见[计划47](plans/47-Critic多轮消息会话.md)。
6. 经验用于未来首次设计评分标准。content描述方法，trigger从生成前的task、输入、上下文或领域知识识别。实例转为语义角色或任务参数；允许必要领域限定、通用说明和同一目的的协同动作，不用举例词作自动门禁。
7. 评分采用正向Boolean问题和task支撑的相对权重预算，不增加部分分、总分否决或自动跳过机制。
8. 提供C、声明采用C、局部净正向资格、整体Judge成功、最终选择入池分别记录。来源是模型自报，不证明忠实实施或因果贡献。
9. R0有效Judge后，成败分支前写入已有经验P/N；应用里的E引用仅审计，不重复记账。后续失败不撤销R0更新。
10. 候选实际提供、声明采用、Judge有效且自身P>N才具资格，不要求整体成功。正常结束时合格C2优先，否则回退合格C1，每题最多新增一条；Judge错误不做正常回退入池。
11. R0与被选候选信用按引用标准的P/N分别累计，多来源均分；alpha+=P、beta+=N，不折扣、不先抵消。同判按标准额度25%计N；P>N只控制候选入池，不替代双通道记账。
12. 新候选直接保存原文及原题，Beta(1,1)加实际信用。已有经验收录正向、反向及同判案例，包含来源最多10条；原题不计窗口，每3个不同下游任务归纳一次。成功（含保留文本）重置窗口，失败保留窗口、同题不重复尝试。第10条强制最后尝试，之后冻结案例/文本、继续信用。取消MERGE和拆分，只改同一ID的content/trigger；150/60字符仅提示词约束。保存版本，历史证据不自动认证新文本。
13. Held-out冻结池、文本及Beta，只执行检索、选择和R0生成/Judge。当前真实实验的所有LLM角色固定Qwen3.5-Flash、关闭思考。
14. Judge每项返回Boolean与简短依据，Critic核对两侧理由及原回答；理由不是事实认证，不进入Generator。
15. 轨迹/manifest为版本7，Memory为版本5，method为local_credit_bounded_experience，Prompt为local-credit-delayed-experience-signed-cases，Critic逐标准分块展示见[计划56](plans/56-Critic可读输入与Judge理由复测.md)。不兼容旧流程运行、展示或跨方法resume；当前及后续产物保留；此前历史清理以计划43记录为准。
16. 鉴权/网络、数据/存储、Calculator及程序错误仍fail-fast。角色输出错误保持有限纠错与样本/无效轮隔离。

## 4. 实施边界

离线契约通过不证明经验通用性或Judge事实正确。本轮包含代码、测试及文档和独立历史归纳输入复测；完整Flash非思考链路需新配置/目录另行启动；保留历史，禁止跨协议resume。角色输出有限纠错，基础设施/存储/程序故障fail-fast，不静默截断案例或伪造验证。
