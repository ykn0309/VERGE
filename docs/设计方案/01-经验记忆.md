# 经验记忆（Experience Memory）

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 新方案的Memory职责见本文；代码/schema已迁移到版本2，实施见[计划31](../plans/31-Critic候选经验准入与新会话验证.md)。

## 1. 模块职责

Experience Memory 只负责保存可复用经验及其累计证据，不负责经验生成、信用分配或融合决策。

经验是“如何生成好 rubric”的方法原则，而不是具体 criterion。

## 2. Experience 结构

```text
Experience {
    experience_id
    content
    trigger
    alpha
    beta
    confidence
    source_trajectories
    evidence_history
    fusion_history
}
```

示例：

```json
{
  "experience_id": "exp_001",
  "content": "当任务包含多个可独立验证的要求时，应将它们拆成独立的 Boolean criteria。",

  "alpha": 2.20,
  "beta": 1.25,
  "confidence": 0.6376811594202899,
  "source_trajectories": ["sample_103", "sample_287"],
  "evidence_history": [
    {
      "sample_id": "sample_103",
      "evidence_type": "downstream_credit",
      "positive_credit": 0.45,
      "negative_credit": 0,
      "evidence_weight": 1.0
    },
    {
      "sample_id": "sample_287",
      "evidence_type": "downstream_credit",

    },
    {

```

## 3. 字段含义

- `content`：可迁移的 rubric-generation principle；
- `trigger`：经验适用的任务条件和边界；
- `alpha`、`beta`：累计正负 evidence；
- `confidence`：$\alpha/(\alpha+\beta)$；
- `source_trajectories`：产生或再次发现该经验的 sample IDs；
- `evidence_history`：样本级累计证据；downstream_credit与application_credit均记录sample_id、positive_credit、negative_credit和权重1。R0与候选按实际来源标准的正负双通道无折扣更新，按新协议记录，不兼容旧revision_credit/fusion_credit解码。候选来源和文本版本需可关联，采用的criterion引用保存在应用轨迹。

`source_trajectories` 和 `evidence_history` 不提供给 rubric generator。

## 4. Selector View

Retrieval selector 只允许看到：

```text
id
content
trigger
confidence
evidence amount
```

它不能看到：

```text
source trajectories
operation logs
experience-operation bindings
具体 preference pair
```

## 5. Reliability 字段归属

Experience Memory 只存储 `alpha`、`beta` 和派生的 `confidence`，不定义其更新规则。

- initial rubric 的 downstream credit：见[已有经验信用分配](./05-已有经验信用分配.md)；
- 候选应用后入池资格：见[候选生命周期](./09-修订信用分配与准入.md)和[新会话应用](./07-Generator对话修订.md)；
- Beta 更新和 evidence weighting：见[可靠性更新](./11-可靠性更新与噪声证据.md)。

## 6. 模块边界

本模块不决定：

- 候选经验是否合格；
- 候选经验是否被当前应用声明采用；
- 候选经验执行 MERGE 还是 ADD；
- 哪条经验应被当前 task 使用。

## 新经验先验

新方案仍以Beta(1,1)为ADD基础；仅被声明采用且应用Judge有效成功的候选才有入池资格；未应用或未入池候选不是Memory经验，不能被检索。ADD/MERGE保存成功应用及P/N证据，alpha加P、beta加N，不先抵消、无折扣；两通道均0才不更新，净方向为0仍可增加证据量。成功也可有负证据，不把入池等同于涨信度，不使用旧0.25 margin增益。MERGE保留原ID、继承旧Beta/证据、改写文本，confidence仍派生计算。

fusion_history保存每次融合的样本/候选、ADD或MERGE、修改前后content/trigger及本次正向P/负向N证据；净方向仅作派生展示；ADD修改前文本为null。新字段按新协议保存，不为旧缺字段记录补造或兼容解码。候选轨迹关联同次变更，文本历史不提供给Selector/Generator，继承旧版本证据不认证新扩展。
