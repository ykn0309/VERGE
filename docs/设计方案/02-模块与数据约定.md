# 模块与数据约定

本文件补充[v3.1方法设计](../设计方案.md)，定义逻辑输入输出，不等同于已经实现的JSON协议。确切字段、检查点版本和存储布局在实现计划中确定。

## 1. 共享数据

| 对象 | 必须表达的信息 |
|---|---|
| 任务样本 | 稳定任务／样本ID、task、回答A／B；训练另有偏好映射、标签和可用的人工理由 |
| 经验 | 独立ID、trigger、principle、application_guide、来源任务及可选parent |
| 候选列表 | 经验ID及正文、历史／语义来源、历史分数或未知、不同有效任务数、语义分数及相近任务组依据 |
| Rubric | ID、设计分析、标准ID、question、weight |
| 执行路径 | 所提供零条／一条经验、共享初稿标识、修订稿、双侧原判与理由、得分、预测、错误及执行设置 |
| 信用记录 | 任务ID、经验ID、协议标识、无经验与该经验结果、差值或未知原因 |
| 聚类状态 | 固定向量、唯一归属、原始去重提供边、最低阈值、模块度、成员平均低限检查、修复记录、半轮矩阵版本及稳定／循环／预算状态 |
| Critic轮次 | 失败依据、候选或不提案理由、参考原文、来源验证路径和准入结果 |

任务、经验、路径、调用等ID职责不同；重试保留同一任务及路径身份，不重复计证据。提供关系不依赖模型声明引用。运行协议和模型设置必须随轨迹保存，以免不兼容效果被直接混合。

## 2. 组件约定

| 组件 | 输入边界 | 输出及约束 |
|---|---|---|
| Retriever／Ranker | 任务向量和本题开始时的历史 | 去重候选；未知保留，不补成0；经验池不足返回实际数量 |
| Selector | task及候选列表 | 训练0～3个、推理0～1个候选编号，编号不重复且来自输入；每条有task依据 |
| Generator初稿 | 仅task | 非空设计分析与可逐项判断的标准；权重非负有限，总和1 |
| Generator修订 | task、共享初稿、本路经验或空 | 同一Rubric内容结构；允许原内容保留；不输出引用、Judge结果或候选回答分析 |
| Judge | task、该路最终Rubric、一份匿名回答 | 每个标准恰好一次布尔判断与具体理由；不遗漏、重复或虚构标准编号 |
| Critic | 原始轨迹、标签映射及人工理由 | 一次分析，零条／一条候选；仅有Judge错误或依据不足可拒绝提案；不直接输出已修复结论 |
| 状态提交 | 完整本题结果及新增对象 | 经验准入、关联、反馈和轨迹一致发布；失败不能静默只写一部分 |

Critic新候选ID由程序分配，parent仅能来自可追溯经验，不赋予收益继承含义。触发与验证依据由程序结果记录，不能用Critic自评替代。

## 3. 错误和结果

区分三种状态：判对、未判对（平局／反向排序）、技术未知。每条经验只有与无经验路同时有效才生成信用，其他经验路未知不使该条证据丢失。

来源验证与下游应用使用不同证据用途；候选准入不写来源信用或提供边。所有输入、原始回复、合同错误与重试均保存，不能只保存最终解析成功内容。

网络和格式错误实行有限重试，耗尽只记录局部失败。共享初稿失败、Critic验证初稿复用、无成功但含未知时的后续执行仍待确定；在这些分支上不推断不存在的结果。
