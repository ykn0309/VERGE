# 混合检索与经验筛选

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

## 1. 索引文档与召回单位

只使用公开文本，不读偏好对、Judge、案例或信用来生成检索文档。

| 文档 | 索引文本 | 任务检索映射 | 归类检索映射 |
|---|---|---|---|
| 类别 | name＋description | 类别 | 类别 |
| 已分类活跃经验 | trigger＋content | 所属类别 | 所属类别 |
| 未分类活跃经验 | trigger＋content | 自身 | 不作为类别候选 |

所有活跃成员分别参与检索，不再把整类成员拼成一段向量。退役版本不索引；信用变化不重新嵌入。成员文本不变而归属变化时只更新映射；类别名称/描述变更才刷新其文档。空类别退出索引。

## 2. 向量＋BM25＋RRF

向量按余弦相似度，BM25按固定中文分词/英文归一化策略排名；参数、分词版本、并列顺序写入配置及manifest。工程初始约定为等权RRF、k=60，排名从1开始：

```text
score(d) = 1/(k + rank_vector(d)) + 1/(k + rank_bm25(d))
score(unit) = max(score(d) for d mapped to unit)
```

某一路无有效命中时贡献0，BM25没有词项命中不能获得任意排名分。按成员最相关命中取max，不累加全部成员分数；这减少直接的数量奖励，不保证完全消除大类别优势。

先将文档映射为单位、去重，再取TopK。当前规模可对全部缓存文档计算两路排名，不能先截少量成员文档再宣称得到足量类别。记录两路排名、融合分、映射和最终结果；Embedding失败不静默切成纯词法条件。

## 3. 两种查询

### 任务查经验

query=task，取Top20类别/未分类单位。命中类别完整展开全部活跃成员，不把20误认为叶子经验数。空池不调用Embedding；未分类经验与类别同级参与。

### 经验查类别

query=待分类经验的trigger/content，只取Top10类别，不足时全部提供。排除待分类经验自身的成员文档，避免自命中强化旧归属；类别描述可能残留其信息，属于已知限制。

给归类器每类name/description及最相关成员的完整trigger/content。工程初始上限3条展示成员，并记录真实成员数及投影，全部成员仍参与检索。这是预定输入契约，不是超预算时静默截断。归类结果见[类别整理](10-经验融合.md)。

## 4. Selector

同一次调用接收按类别组织的完整任务召回结果。每条活跃版本有局部短ID、content/trigger、本版本confidence/evidence_amount；类别有name/description。新演化版本50%且0证据应解释为未知，不是祖先已经验证，也不是质量一般。

Selector只输出0～5条小经验版本ID，可选同类任意子集，不输出类别ID。先看trigger与任务是否匹配，再看方法是否帮助设计标准；适用性相近时才参考本版本证据。不设探索名额、置信度门槛，不提供区分率。

完整system/user输入沿用可配置预算（当前默认100000 UTF-8字节），超预算隔离样本，不静默截断类别或增加模型分层筛选。局部分类输入有界不代表任务Selector展开后一定有界，需记录此限制。

## 5. 固定快照和冻结评价

输出E固定本样本的ID、文本和顺序；R0/R1/R2不重新检索、不混入本样本新版本。Generator只接收ID/content/trigger，不见类别或信用。演化和分类在候选过程结束后执行。

held-out冻结业务对象，仅构建只读缓存。纯向量与混合检索的局部对照必须使用相同快照、TopK、人工相关集合；池小于TopK时不能以全召回证明收益。
