# v3已有设置与v3.1新增决策

2026-11-13只读核对。下表记录v3实际代码及500题配置，供讨论沿用，不表示用户已批准所有数值直接成为v3.1配置。当前方法主体的“待确定”应理解为是否沿用或如何适配，而非此前没有规则。

| 项目 | v3实际设置 | v3.1需要确定的差异 |
|---|---|---|
| 关联权重与证据量 | `w=0.5*m/(m+1)`，m为两对象原始关联集合大小的较小值；任一无关联直接用文本 | 类别分布改变后可讨论沿用，但应明确m仍为原始对象数，不能随意改成类别数；任务最多3条边也限制实际w |
| 两侧门槛 | 任务0.75、经验0.75；任务查询也用任务门槛 | 是否保留为初值，非没有默认数值；新相似度下效果需验证 |
| 新对象入组 | 按`(kind, ID)`排序，选同类型成员平均分最高且达标组，否则新建；先加边再放置，新对象有边时也用混合相似度 | 已讨论的文本初始化不能直接冒称沿用v3；新增类别对象需先有对侧归属 |
| 更新移动 | 按固定ID逐个检查所有对象，移动立即生效；其他组达标且严格高于当前组才移动 | 可用于各半轮；对侧类别需在半轮固定并在切侧时重汇总 |
| 退出当前组 | 当前多成员组得分不达标且没有更好达标组时独立新建；单成员留组分按门槛 | 可讨论沿用 |
| 平分 | 最佳候选组同分按稳定组ID；当前组同分不迁移；1e−12内视为浮点相等 | 可讨论沿用 |
| 轮数 | 最多5轮，无移动提前停止，触顶有移动标记未稳定 | 轮的内部改为任务、经验两个半轮，次数上限已暂定沿用 |
| 候选验证 | 复用本题无经验路径及Judge结果，候选另生成Rubric；技术失败未知，候选纯技术失败不消耗第二轮语义提案 | v3没有共享初稿，故无法规定R0复用或初稿失败处理；保留基线复用可作为建议 |
| 检查点 | JSON原子写入，schema为`verge-subset-learning-v2`，保存经验、聚类、账本、轨迹及协议ID | 原子保存等基础机制可复用，v3.1共享初稿和独立三路需要新字段及校验；旧schema不可直接认作新协议 |
| 续跑 | 校验代码、数据、协议及检查点摘要，跳过已提交任务，任务开始读取只读快照 | 保留基础原则；没有保证恢复每个尚未提交的中间调用或已失败分支 |

## 实际执行配置

500题配置使用Qwen3.5-Flash，关闭思考；text-embedding-v4，1024维。训练／测试样本并发各5，全局请求最多16；模型和嵌入请求超时120秒，backend最多重试2次；角色合同层另最多纠错重试2次，两层不能简单合称总共3次调用。请求消息预算100000 UTF-8字节，超限报错、不静默截断。

模型请求未显式设置temperature或max_tokens，因此不能将其说成temperature＝0或某个固定输出上限；依供应商默认行为。以上为真实运行配置，不与fake离线默认混用。
