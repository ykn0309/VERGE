# 已有经验版本的信用分配

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

## 1. 记账时机与范围

已有活跃版本仅从训练R0记账。两侧Judge有效后、整体成败分支前立即更新，整体失败也计入；后续候选/演化/分类失败不撤销合法R0信用。R1/R2中固定E的引用只审计，不重复累计或收集案例。

每个来源ID指向实际使用的固定trigger/content版本；类别ID不能作为标准来源。后续退役不会改变这笔记录所属版本，新版本只通过独立继承记录接收父信用，不把父原始反馈伪装成本版本事件。

## 2. P/N公式

对标准i，d_i=J(chosen,c_i)−J(rejected,c_i)，来源集合S_i，归一化权重w_i：

- d_i=+1：每个来源e得到P_e+=w_i/|S_i|。
- d_i=−1：每个来源e得到N_e+=w_i/|S_i|。
- d_i=0：P/N不变，分别记录双方满足或双方不满足的标准次数。

没有来源的标准仍参与整体评分，不分配经验信用。多来源均分，P/N不先抵消、不折扣、实际反馈不使用lambda或margin增益；λ=0.2仅用于成功演化的程序惩罚。跨来源的信用总量等于有来源且有区分的标准权重之和，不因一个草稿拆成多条而复制标准权重。候选资格用精确十进制比例判断P>N。

alpha+=P、beta+=N；P+N=0不追加数值证据，引用同判仍记录UsageRecord。数值证据、引用标准计数、不同任务数分别保存，不当作同一指标。来源自报不等于忠实落实或因果贡献。

## 3. 五案例归纳

本版本实际R0反馈P+N>0时，可将该任务作为下游案例；P=N>0也算一个有区分混合案例。一个任务不论引用多少标准均只占一个案例，重复提交不能重复计分或触发。

每5个新的不同下游任务，以最近5条归纳。来源应用、祖先案例和同判不进窗口。混合案例输入仅投影引用本版本且有区分的标准，完整rubric/Judge仍留档；归纳失败重试规则见[经验演化](10-经验融合.md)。

演化子版本保留各自Beta(1,1)先验与空窗口，修订继承历史P/N及旧惩罚，拆分均分，再加本次稳定性惩罚。父信用原样保存在退役版本。详见[可靠性](11-可靠性更新与噪声证据.md)。held-out不写信用、usage或案例。
