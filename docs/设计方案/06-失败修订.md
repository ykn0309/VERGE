# Critic候选经验生成与应用验证控制

> 上位文档：[设计总览](../设计方案.md) ｜ 应用：[新会话Generator](07-Generator对话修订.md) ｜ 准入：[Admission](09-修订信用分配与准入.md)
>
> 新机制已实现，离线契约验收通过；旧对话修订见[历史计划20](../plans/20-Generator多轮对话修订.md)。本路径沿用。

## 1. 触发与职责

仅在训练且R0获得有效Judge失败结果后启动。Critic从真实失败证据提出供首次生成使用的候选经验，不直接修订rubric，不提供给Generator普通improvement_advice。不新增Refiner或Executor。

Critic返回私有analysis和0–1条候选content/trigger；系统分配候选ID。没有可信可复用指导时可为空，不伪造候选或成功。模型返回`analysis/candidates`，系统生成`CriticProposal`和独立候选ID；空候选终态为`no_candidate`。

## 2. 两层预算

| 层次 | 最大机会 | 触发 |
|---|---:|---|
| 候选应用验证 | 2轮 | 首轮由R0失败触发；下一轮由实际应用后的Judge失败触发 |
| 本轮候选生成 | 2次 | 首次提出；仅第一次Admission FAIL允许重新提出一次 |
| Critic业务生成总量 | 4次 | 两轮各最多2次；准入耗尽立即结束，不能继续下一轮 |
| 新Generator/Judge应用 | 2轮 | 仅通过Admission的候选才可进入 |

后端格式和模块结构纠错单独有限计数，不以技术错误伪造业务PASS/FAIL。沿用既有样本/无效轮隔离：Critic或应用Generator格式耗尽记录无效轮，在剩余业务预算内可继续；其他指定角色契约耗尽记录样本错误并继续下一样本，Judge耗尽记录明确Judge错误并结束该样本后续流程。格式/类型/引用错误不全局中止。鉴权/网络服务、数据/存储或程序异常仍按既有全局故障边界处理。

## 3. 统一流程

```text
Critic提出C → Admission
  首次FAIL：C及具体拒绝原因 → 同一个Critic重生成新候选ID
  再次FAIL：保存两个候选及准入记录，结束本任务
  PASS：冻结该候选原文 → 新Generator(task + 固定E + C) → Judge
    成功且采用C：融合该候选，结束
    成功且未采用C：任务成功，C未验证，不入池，结束
    失败：若仅进行了首轮应用则更新证据、重置准入重试额度并再执行一次；
          第二轮仍失败则结束，不入池
```

每轮最多一条通过的候选交给Generator，不把被拒候选或前轮候选叠加进去。应用失败的候选也仅留在轨迹，不提前写Memory。

## 4. Critic输入与证据组织

- 原始task、chosen/rejected；
- 当前有效失败rubric及真实逐项Boolean、分数和margin；
- 当前业务轮次、准入重生成状态；
- 准入重生成：本轮被拒候选与拒绝原因，仍基于同一份失败证据；
- 第二轮：上一条通过候选、实际生成结果、Judge及采用来源记录；必要前后版本各一次，不传旧私有analysis作为叙事。

首轮基于R0；下一轮基于实际失败应用结果。它们是Critic的诊断证据，不是Generator继承的会话或rubric基线。

## 5. 输出边界

analysis可讨论私有回答证据；候选content/trigger不得携带候选特有细节、偏好身份、私有评分或比较结论。以task和独立领域知识表达可迁移设计指导，允许协同动作，不要求只含一个机制动作。

判别失败不证明标准有错：先核对实际标准、回答、Judge与约束，允许指出Judge疑点或缺少可信调整依据。不得把错误判定包装成一般方法，不建议部分分、否决、修改已有Judge状态或无依据的任务降权。

隔离主要依赖角色输入边界、提示词和已有Admission；本方案不另加泄漏审查角色或自动语义门禁。全部原始输出和反馈保留，不从后续成功倒推Critic本意。
