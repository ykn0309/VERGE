# 失败修订

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 输入：[Rubric Judge](./04-Rubric-Judge.md) ｜ Operation 定义：[原子操作修订](./07-原子操作修订.md)

## 1. 模块职责

当 initial rubric $R_0$ 失败时，最多执行两次 revision attempts。每次 Revision Generator 都针对 $R_0$ 输出原子 operations，由 Revision Executor 应用 operations 生成 revised rubric。

## 2. 触发条件

```text
M(R0) > 0  → initial success，不 revision
M(R0) ≤ 0  → revision attempt 1
```

## 3. Revision Attempt 1

Critic 1 查看：

```text
task
chosen/rejected
R0
R0 criterion judgments
```

Revision Generator 输出：

$$
O_1=GenerateOperations(R_0,feedback_1)
$$

Revision Executor 生成：

$$
R_1=Apply(R_0,O_1)
$$

如果 $M(R_1)>0$，attempt 1 success。

## 4. Revision Attempt 2

如果 $M(R_1)\le0$，Critic 2 可以查看 $R_1$ 的失败信息；如果 attempt 1 的修订操作经有限重试仍无法通过 Executor 校验（包括条数、冲突或非法引用），则不存在有效的 $R_1$，Critic 2 只看 $R_0$ 及其初始判断失败信息，不接收无效操作或校验日志。

**Revision Generator 2 不能只依赖 Critic 2 的摘要**：其输入为 task、chosen/rejected、$R_0$ 与逐项初始判断、Critic 2 反馈，加上第一次完整的**修订相关轨迹**：Critic 1 反馈、已执行 operations、$R_1$、逐项 Judge 结果与校验重试记录。若第一次只有无效修订，没有 $R_1$ 或 Judge 结果，则只附第一次原始反馈和校验失败摘要，不伪造执行结果或泄露未保存的无效 operations。召回、信用、经验池及未来阶段不属于修订轨迹，不发送。训练中的 chosen/rejected 只在 Critic 与修订环节可见，初始生成/筛选仍仅看 task。

两种情况下新的 operations 都以 $R_0$ 为 base：

$$
O_2=GenerateOperations(R_0,feedback_2)
$$

$$
R_2=Apply(R_0,O_2)
$$

禁止从 $R_1$ 继续修改：

$$
R_2\ne Apply(R_1,O_2)
$$

如果 attempt 2 复用了 attempt 1 中的修改，该修改必须重新出现在 $O_2$ 中。第二次提示词要明确说明：第一次操作**不会自动继承**，先对照失败轨迹确定哪些修改值得保留、哪些应该舍弃，再输出对 $R_0$ **一次性执行的完整操作集**。不得把当前 chosen/rejected 的专有事实写入通用 rubric。

## 5. Revised Rubric 约束

- 使用与 $R_0$ 相同的 Boolean criterion schema；
- 完整 rubric 包含 2–8 条标准；无效条数不交给 Judge；
- importance score 为 1–10 整数；
- 未修改 criterion 保留原 ID 和 importance score；
- score 变化必须通过 MODIFY 显式表达；
- 不得包含当前 response 特有事实或引用 chosen/rejected。

## 6. 结果分支

```text
M(R0) > 0
→ initial success

M(R0) ≤ 0 且 M(R1) > 0
→ attempt 1 success

M(R0) ≤ 0、M(R1) ≤ 0、M(R2) > 0
→ attempt 2 success

M(R0) ≤ 0、M(R1) ≤ 0、M(R2) ≤ 0
→ final failure
```

只有成功 attempt 的 operations 进入 Reflection 和 Revision Credit Assignment。有效但失败的 $R_1$ 只用于 Critic 2 和离线诊断；经重试仍不能通过 Executor 校验的修订只记录失败诊断，没有 $R_k$、Judge 或 credit。两次修订均不成功（包括操作无效）时结果为 final failure。

已有经验始终只根据 $R_0$ 的 downstream credit 更新。
