# 失败修订

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 输入：[Rubric Judge](./04-Rubric-Judge.md) ｜ Operation 定义：[原子操作修订](./07-原子操作修订.md)

## 1. 模块职责

当 initial rubric $R_0$ 失败时，最多执行两次 revision attempts。每次 Critic 同次输出私有 `analysis` 和针对 $R_0$ 的原子 `operations`，由 Revision Executor 应用 operations 生成 revised rubric。不再调用独立 Revision Generator。

## 2. 触发条件

```text
M(R0) > 0  → initial success，不 revision
M(R0) ≤ 0  → revision attempt 1
```

## 3. Revision Attempt 1

Critic 1 查看：

```text
task
chosen/rejected
R0
R0 criterion judgments
```

Critic 在给定 chosen 优于 rejected 的偏好目标下，结合逐项 Judge 与 margin 分析 R0 为何未能区分；`analysis` 可以引用候选回答内容，`operations` 中的通用标准则提示仅从 task 推导。**不增加对 operations 是否含候选回答内容的审查**；这项隔离依赖提示词，可能失败。

$$
(analysis_1,O_1)=Critic(task,chosen,rejected,R_0,Judge(R_0))
$$

Revision Executor 生成：

$$
R_1=Apply(R_0,O_1)
$$

如果 $M(R_1)>0$，attempt 1 success。

## 4. Revision Attempt 2

如果 $M(R_1)\le0$，Critic 2 可以查看第一次 `analysis`、已执行 operations、$R_1$ 逐项 Judge 与校验重试记录，解释第一次为何未奏效。若第一次的操作因编号反解、领域结构或 Executor 校验错误经有限结构重试仍无效，则不存在有效 $R_1$；Critic 2 只额外看到第一次 `analysis` 和结构校验失败摘要，不接收虚构的 Judge 结果或未保存的无效操作。召回、信用和经验池不进入 Critic；Selector 与初始生成仍只看 task。

两种情况下新的 operations 都以 $R_0$ 为 base：

$$
(analysis_2,O_2)=Critic(task,chosen,rejected,R_0,Judge(R_0),history_1)
$$

$$
R_2=Apply(R_0,O_2)
$$

禁止从 $R_1$ 继续修改：

$$
R_2\ne Apply(R_1,O_2)
$$

如果 attempt 2 复用了 attempt 1 中的修改，该修改必须重新出现在 $O_2$ 中。提示词要求先对照失败轨迹确定有效和无效修改，再输出对 $R_0$ **一次性执行的完整操作集**；操作标准不得引用当前 chosen/rejected 的专有事实。`analysis` 仅作私有诊断，不自动构成可迁移经验。

## 5. Revised Rubric 约束

- 使用与 $R_0$ 相同的 Boolean criterion schema；
- 完整 rubric 包含 2–8 条标准；无效条数不交给 Judge；
- importance score 为 1–10 整数；
- 未修改 criterion 保留原 ID 和 importance score；
- score 变化必须通过 MODIFY 显式表达；
- 提示词要求不得包含当前 response 特有事实或引用 chosen/rejected；不添加针对该性质的内容校验或门禁。

## 6. 结果分支

```text
M(R0) > 0
→ initial success

M(R0) ≤ 0 且 M(R1) > 0
→ attempt 1 success

M(R0) ≤ 0、M(R1) ≤ 0、M(R2) > 0
→ attempt 2 success

M(R0) ≤ 0、M(R1) ≤ 0、M(R2) ≤ 0
→ final failure
```

只有成功 attempt 的 operations 进入 Reflection 和 Revision Credit Assignment。有效但失败的 $R_1$ 只用于 Critic 2 和离线诊断；经重试仍不能通过 Executor 校验的修订只记录失败诊断，没有 $R_k$、Judge 或 credit。Critic 的后端格式重试耗尽也作为本轮无效修订记录，允许后续轮次及下一样本继续；未取得合法 analysis 时保留 null 和格式错误摘要，不虚构模型分析、Rk 或 Judge。网络、鉴权等后端故障不在此容错范围。两次修订均不成功（包括操作无效和格式失败）时结果为 final failure。

已有经验始终只根据 $R_0$ 的 downstream credit 更新。
