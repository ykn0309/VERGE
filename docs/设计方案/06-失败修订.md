# 失败修订

> 上位文档：[VERGE 设计总览](../设计方案.md) ｜ 执行：[Generator 对话修订](./07-Generator对话修订.md)

## 职责与流程

仅训练中 R0 判别失败才进行最多两轮修订。使用原有 Generator，不引入 Refiner 或 Revision Generator 角色：

```text
Generator 初始回复 → Judge
→ Critic {analysis, improvement_advice}
→ 将公开建议作为 user 消息追加到 Generator 会话
→ 同一个 Generator 返回完整 rubric → Judge
→ 若失败，针对当前有效 rubric 重复一轮
```

第一轮基线 R0，第二轮接续第一轮有效 R1，R2.base_rubric_id=R1.rubric_id。第一轮未取得有效 rubric 时，第二轮仍基于最近有效 R0，保留失败摘要。不是两次从 R0 独立重做。

## 输入边界

Critic 看原始 task、两份回答、即将执行的修订轮次和当前有效基线的标准/逐项判断/得分。第二轮有有效R1时再看上一轮修改前标准/判断/得分与公开建议；修改前后各展示一次，不重复R1、不传上一轮私有诊断。上一轮无效时仍基于R0，只附轮次、校验失败摘要及“无Judge结果”，不附无效分析/建议或伪造判断。完整历史仍存轨迹和role_io；Reflector投影不变。返回非空 `analysis` 与非空 `improvement_advice`，不生成操作。

`analysis` 先核对实际标准、回答、Judge判断及前后变化，区分设计缺陷、Judge疑点与证据不足；判别失败不证明标准有错，旧公开建议是意图而非执行事实。公开建议说明哪个评价要求有问题、如何调整及任务依据；允许task本身的信息和独立领域知识，禁止候选特有内容、偏好身份、评分或比较评价。没有可靠修改依据时可以建议保留合理标准，但不新增跳过修订分支。不能为了偏好目标放宽任务约束或无依据地提高要求；重要性表示任务重要程度。评价为重要性归一化加权Boolean，不支持部分分、一票否决或不适用项自动排除，也不要求每条都区分两侧。只有 improvement_advice 进入 Generator；私有分析及回答不直接传入。

提示词隔离不是内容审核；反馈仍可能发生语义泄露，本方法不新增内容门禁。

## 错误和后续

Critic 后端格式纠错耗尽记录无效轮次，不叠加语义重试。Generator 完整输出须满足 2–8 条标准、整数重要性 1–10、非空问题及原有字段/基本类型；修订来源字符串数组由程序在编号反解前统一清空，不要求模型清空，不因复制旧来源编号重试。R0来源仍严格核验；其他结构错误可有限纠错，耗尽记录无效轮次，继续下一轮/样本；后端格式纠错耗尽不再叠加。无有效修订不进入 Judge。

Judge 针对最近有效基线复用相同问题的判断，其他标准重新独立评价。Judge 输出重试耗尽仍保存显式错误；网络/鉴权等全局错误仍中止。R0 的已有经验下游信用已完成时不回滚。只有成功修订进入 Reflector，生成 0–1 条经验；无操作信用。
