# 原子操作修订

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 调用方：[失败修订](./06-失败修订.md) ｜ 成功后：[经验反思](./08-经验反思.md)

## 1. 模块职责

Revision Generator 直接输出原子 operations，Revision Executor 将这些 operations 应用到 $R_0$，生成 revised rubric。系统不再先生成完整 rubric、再反推差异。

## 2. Operation 类型

V1 只支持：

```text
ADD
DELETE
MODIFY
```

统一使用一个 `RevisionOperation`：

```text
RevisionOperation {
    operation_id
    operation_type: ADD | DELETE | MODIFY
    target_criterion_id
    new_or_updated_criterion
    before_criterion
}
```

- ADD：`target_criterion_id` 与 `before_criterion` 为空；`new_or_updated_criterion` 是新标准，包含新 ID、question 和 1–10 importance score；
- DELETE：`target_criterion_id` 是待删除标准的 ID；`new_or_updated_criterion` 为空；
- MODIFY：`target_criterion_id` 是待修改标准的 ID；`new_or_updated_criterion` 是修改后的标准，必须保留原 ID，可改变 question、importance score 或两者。

Generator 只输出操作意图，`before_criterion` 设为 `null`；Executor 从 $R_0$ 读取 DELETE/MODIFY 的原标准，填入同一个操作对象。ADD 的 `before_criterion` 始终为空。

## 3. 复合修改

- 拆分：一个 DELETE + 多个 ADD；
- 合并：多个 DELETE + 一个 ADD；
- 替换：一个 DELETE + 一个 ADD；
- 只调整 importance score：一个 MODIFY；
- 完全未变化：不产生 operation。

修订只关注 criterion 的 `criterion_id`、`question` 和 `importance_score`；`source_experiences` 不属于修订语义。单独改变来源不生成 MODIFY，Executor 不用该字段判断 operation 是否有效。修订后的来源字段即使与 $R_0$ 不同，也不参与 operation 收益归因。$R_0$ 的来源仍用于初始 rubric 的已有经验信用。

## 4. Revision Executor

$$
R_k=Apply(R_0,O_k)
$$

Executor 按 operation list 构造完整 rubric，并从 $R_0$ 自动取得修改前 criterion，返回补全 `before_criterion` 的操作列表。Generator 不计算 `before_criterion`、normalized weight 或 operation credit。

Executor 只做执行合法性检查（比较标准时忽略 `source_experiences`）：

1. DELETE/MODIFY 引用的 criterion ID 存在于 $R_0$；
2. ADD 使用新且唯一的 criterion ID；
3. 同一 criterion 不被冲突修改；
4. 所有 importance scores 是 1–10 整数；
5. operation base 是 $R_0$；
6. 执行结果包含 4–8 条 criteria。

执行失败属于 revision output 无效，可以按格式/结构错误策略有限重试。

## 5. Operation Record

每次修订只保存一份 Executor 返回的 `RevisionOperation` 列表；ADD 仍无 `before_criterion`，DELETE/MODIFY 含修改前的 criterion。`new_or_updated_criterion` 表示 ADD/MODIFY 的修改后标准，DELETE 时为空。未单独保存 `ExecutedRevisionOperation`。

Normalized weights、Judge 结果和 operation contribution 在 [Revision Credit Assignment](./09-修订信用分配与准入.md) 中派生。

## 6. 边界

本模块只负责“用 operations 构造 rubric”，不负责：

- 判断 revised rubric 是否成功；
- 生成经验；
- 绑定经验与 operations；
- 计算 operation 收益或 revision credit；
- Admission。
