# 原子操作修订

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 调用方：[失败修订](./06-失败修订.md) ｜ 成功后：[经验反思](./08-经验反思.md)

## 1. 模块职责

Revision Generator 直接输出原子 operations，Revision Executor 将这些 operations 应用到 $R_0$，生成 revised rubric。系统不再先生成完整 rubric、再反推差异。

## 2. Operation 类型

V1 只支持：

```text
ADD
DELETE
MODIFY
```

### ADD

```text
ADD {
    operation_id
    new_criterion
}
```

`new_criterion` 包含新 ID、question 和 1–10 importance score。

### DELETE

```text
DELETE {
    operation_id
    target_criterion_id
}
```

### MODIFY

```text
MODIFY {
    operation_id
    target_criterion_id
    updated_criterion
}
```

MODIFY 可以改变 question、importance score，或同时改变两者。`updated_criterion` 保留原 criterion ID。

## 3. 复合修改

- 拆分：一个 DELETE + 多个 ADD；
- 合并：多个 DELETE + 一个 ADD；
- 替换：一个 DELETE + 一个 ADD；
- 只调整 importance score：一个 MODIFY；
- 完全未变化：不产生 operation。

## 4. Revision Executor

$$
R_k=Apply(R_0,O_k)
$$

Executor 按 operation list 构造完整 rubric，并从 $R_0$ 自动取得修改前 criterion。Generator 不输出 `before_criterion`、normalized weight 或 operation credit。

Executor 只做执行合法性检查：

1. DELETE/MODIFY 引用的 criterion ID 存在于 $R_0$；
2. ADD 使用新且唯一的 criterion ID；
3. 同一 criterion 不被冲突修改；
4. 所有 importance scores 是 1–10 整数；
5. operation base 是 $R_0$；
6. 执行结果包含 4–8 条 criteria。

执行失败属于 revision output 无效，可以按格式/结构错误策略有限重试。

## 5. Operation Record

成功执行后保存：

```text
ExecutedRevisionOperation {
    operation_id
    operation_type
    before_criterion
    after_criterion
}
```

- ADD 的 `before_criterion` 为空；
- DELETE 的 `after_criterion` 为空；
- MODIFY 同时包含 before 和 after。

Normalized weights、Judge 结果和 operation contribution 在 [Revision Credit Assignment](./09-修订信用分配与准入.md) 中派生。

## 6. 边界

本模块只负责“用 operations 构造 rubric”，不负责：

- 判断 revised rubric 是否成功；
- 生成经验；
- 绑定经验与 operations；
- 计算 operation 收益或 revision credit；
- Admission。
