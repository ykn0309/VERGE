# 经验反思

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 输入：[成功的对话修订](./07-Generator对话修订.md) ｜ 输出：[修订信用分配与准入](./09-修订信用分配与准入.md)

## 1. 模块职责

从 revision success trajectory 中提炼供 Generator 未来首次生成标准使用的经验。修订轨迹是提炼证据，不将经验写成对既有 rubric 的修订指南。Reflector 返回 0–1 条候选，只包含 content、trigger；本模块不执行 Admission 或数值信用计算。

## 2. 触发条件

只有以下情况进入 Reflection：

```text
revision attempt 1 或 2 success
```

Initial success 和 final failure 都不生成候选经验。

## 3. 输入

Reflector 可以查看：

```text
task
chosen / rejected 原始回答
R0 及判断结果
successful Rk 及判断结果
成功修订的 Critic 私有分析及公开 improvement_advice
成功修订前后标准及两侧判断
```

## 4. 输出

Reflector 输出 0–1 条：

```text
CandidateExperience {
    candidate_id
    content
    trigger
    admission             # 初始为 null，后续为 PASS / FAIL
    fusion                # 初始为 null，通过准入后可为 ADD / MERGE
    experience_id         # 初始为 null，Fusion 后为最终经验 ID
}
```

要求：

- `content` 是任务类型、要求关系、输入条件或评价维度层面的 rubric-generation principle，保留可执行的标准设计机制；用语义类别替代样本特定对象、场景、名称、数字和候选措辞，不复述当前题目的解决方案，也不退化为泛泛质量口号；适用范围可限定任务类型，不要求跨所有领域通用；
- `trigger` 描述经验的触发条件或使用场景，只包含未来筛选阶段**仅凭当前 task** 可判断的适用条件，例如题型、任务显式要求或提供的上下文；不得以候选回答的实际内容、初始/修订 rubric、Judge 判断、critic 反馈或偏好结果为前提；
- 反思时可利用成功修订与反馈提炼 `content` 中的生成原则，但不能将这些事后诊断条件直接放进 `trigger`；若无法形成清晰、非空泛、事前可检验的条件，可以不输出该候选；
- 一条 candidate 表达一个设计机制，允许设计评价维度、安排标准重要性、排除不当要求等具体方法；同一机制可有协同动作，只有可独立使用且触发条件不同的原则应拆开；
- trigger 的范围足以支持 content 的指导强度，应用仍尊重任务目标和明确约束；区分任务操作与材料主题，提炼标准设计而非完整 rubric 或回答生成指南；
- 不包含当前 response 特有内容。

Reflector 仅返回 content、trigger。系统自动分配 candidate ID，直接执行 Admission，不绑定操作、不赋操作信用；后续合法融合的弱修订证据由 Calculator 计算。无值得迁移的单一机制时返回空数组。

## 5. 模型输入展示

Reflector 直接接收原始 task、chosen 和 rejected，用回答事实理解修订解决的问题，提炼内容仍表达可迁移方法，trigger 仍仅由未来 task 核验。展示最近有效修改前标准、成功修订后的标准、重要性和两侧 Boolean 判断；与初始 R0/判断分别保留。原始和修订后的整体得分与得分差仍保留，最多展示四位小数；完整 rubric 不再重复列出。user 消息省略归一化权重、整份 rubric 的内部编号与 base 编号，以及末尾补充说明。内部日志和数值计算不变，标准使用纯数字引用，当前输入和候选输出均无操作引用。

Generator 对话修订下，successful_attempt 还记录最近有效 previous_rubric / previous_judgment，以及 Critic 公开反馈；第二轮不能把 R0 当作刚刚修改的基线。Reflector 不接收操作。
