# 经验反思

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 输入：[成功的原子操作修订](./07-原子操作修订.md) ｜ 输出：[修订信用分配与准入](./09-修订信用分配与准入.md)

## 1. 模块职责

从 revision success trajectory 中生成少量候选经验。Reflector 同次返回候选及其支撑操作编号；本模块不执行 Admission 或数值信用计算。

## 2. 触发条件

只有以下情况进入 Reflection：

```text
revision attempt 1 或 2 success
```

Initial success 和 final failure 都不生成候选经验。

## 3. 输入

Reflector 可以查看：

```text
task
chosen / rejected 原始回答
R0 及判断结果
successful Rk 及判断结果
Critic 私有分析
successful operation list
```

## 4. 输出

Reflector 输出 0–3 条：

```text
CandidateExperience {
    candidate_id
    content
    trigger
    linked_operation_ids  # Reflector 返回支撑该原则的成功操作编号
    credit                # 初始为 null，后续写入暂定修订信用
    admission             # 初始为 null，后续为 PASS / FAIL
    fusion                # 初始为 null，通过准入后可为 ADD / MERGE
    experience_id         # 初始为 null，Fusion 后为最终经验 ID
}
```

要求：

- `content` 是 rubric-generation principle；
- `trigger` 只描述未来筛选阶段**仅凭当前 task** 可判断的适用条件，例如题型、任务显式要求或提供的上下文；不得以候选回答的实际内容、初始/修订 rubric、Judge 判断、critic 反馈或偏好结果为前提；
- 反思时可利用成功修订与反馈提炼 `content` 中的生成原则，但不能将这些事后诊断条件直接放进 `trigger`；若无法形成清晰、非空泛、事前可检验的条件，可以不输出该候选；
- 一条 candidate 只表达一个原则；
- 不包含当前 response 特有内容。

Reflector 输出 `content`、`trigger` 和 `linked_operation_ids`。系统按列表顺序自动分配 candidate ID，并校验操作引用来自本次成功尝试且无重复；信用、准入和融合字段初始化为 `null`；后续模块在同一候选对象上补全绑定、信用、准入与融合结果。候选经验随后进入 Revision Credit Assignment；空关联候选在信用分配阶段保持 credit 为 null，不进入 Admission；不再发起独立绑定模型调用。

## 5. 模型输入展示

Reflector 直接接收原始 task、chosen 和 rejected，用回答事实理解修订解决的问题，提炼内容仍表达可迁移方法，trigger 仍仅由未来 task 核验。原始与成功修订的标准分别按 ID 合并两侧 Boolean 判断，连同原始重要性、整体得分差和成功操作供反思使用。user 消息省略归一化权重、整份 rubric 的内部编号与 base 编号，以及末尾补充说明。内部日志和数值计算不变，标准与操作的纯数字引用保留。
