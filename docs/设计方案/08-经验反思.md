# 经验反思（历史机制存档）

> **历史存档，不是计划67有效契约。**现行代码及计划67都不调用Reflector。计划67目标是Critic草稿经Atomizer形成原子候选集合后应用，正常收尾选择最新合格轮集合；已有版本由Updater与Atomizer演化。见[方案14](14-原子经验版本演化与局部混合检索.md)及[候选生命周期](09-修订信用分配与准入.md)。以下保留旧Reflector规则，只供历史阅读，不能用于新协议实现或兼容。

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 输入：[成功的对话修订](./07-Generator对话修订.md) ｜ 输出：[修订信用分配与准入](./09-修订信用分配与准入.md)

## 1. 模块职责

从 revision success trajectory 中提炼供 Generator 未来首次生成标准使用的经验。修订轨迹是提炼证据，不将经验写成对既有 rubric 的修订指南。Reflector 返回 0–1 条候选，只包含 content、trigger；本模块不执行 Admission 或数值信用计算。

## 2. 触发条件

只有以下情况进入 Reflection：

```text
revision attempt 1 或 2 success
```

Initial success 和 final failure 都不生成候选经验。

## 3. 输入

Reflector 可以查看：

```text
task
chosen / rejected 原始回答
R0 及判断结果
successful Rk 及判断结果
成功修订的 Critic 私有分析及公开 improvement_advice
成功修订前后标准及两侧判断
```

## 4. 输出

Reflector 输出 0–1 条：

```text
CandidateExperience {
    candidate_id
    content
    trigger
    admission             # 初始为 null，后续为 PASS / FAIL
    fusion                # 初始为 null，通过准入后可为 ADD / MERGE
    experience_id         # 初始为 null，Fusion 后为最终经验 ID
}
```

要求：

- 先对照修订前后标准与两侧判断，辨认实际产生区分的维度及设计变化；Critic分析只作参考，不将所有改动归结为有效方法，也不将判别成功解释为因果贡献；
- content表达未来首次生成时的具体、可复用设计指导，将修订诊断转为事前方法，不复述样本答案细节或偏好身份；
- trigger表达生成标准前可识别的任务/输入场景，允许任务语义、实际输入、上下文与领域知识推理；不依赖已有rubric、Judge结果或已观察到的候选特征。content可以指导核验未来回答，但trigger不能要求这些回答特征已被观察到；
- 一条经验可含服务于同一设计目的的协同动作，不要求只有一个操作，不把这次修订的所有收获塞入一条经验；指导尊重任务目标、明确约束和实际输入条件；
- 无清晰可复用指导时返回空数组。每次仍最多一条候选，只返回content/trigger，系统分配ID，直接Admission，不绑定操作、不赋操作信用。合法融合后追加Calculator计算的弱修订证据。

## 5. 模型输入展示

Reflector 直接接收原始 task、chosen 和 rejected，用回答事实理解修订解决的问题，提炼内容仍表达可迁移方法，trigger 仍应在首次生成前通过任务与上下文分析确定适用。展示最近有效修改前标准、成功修订后的标准、重要性和两侧 Boolean 判断；与初始 R0/判断分别保留。原始和修订后的整体得分与得分差仍保留，最多展示四位小数；完整 rubric 不再重复列出。user 消息省略归一化权重、整份 rubric 的内部编号与 base 编号，以及末尾补充说明。内部日志和数值计算不变，标准使用纯数字引用，当前输入和候选输出均无操作引用。

Generator 对话修订下，successful_attempt 还记录最近有效 previous_rubric / previous_judgment，以及 Critic 公开反馈；第二轮不能把 R0 当作刚刚修改的基线。Reflector 不接收操作。
