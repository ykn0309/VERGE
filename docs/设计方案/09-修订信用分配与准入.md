# 候选经验准入（无操作绑定）

> 上位文档：[设计总览](../设计方案.md) ｜ 输入：[经验反思](./08-经验反思.md) ｜ 输出：[经验融合](./10-经验融合.md)

## 当前方法

成功修订后 Reflector 生成 0–1 条候选，仅包含 content、trigger。取消操作绑定、operation contribution 和暂定操作信用分配；合法融合时追加折扣弱修订证据，但修订成功不证明经验具有因果贡献。

## 审核对象与条件迁移

候选直接进入 Admission。模型只看 task 和候选 ID/content/trigger，不看回答、修订判断或信用；它审核供 rubric generator 首次生成标准时使用的可用经验表达，而非完整 rubric、回答生成指南或实际效果证明。

核心标准：候选是否提供具体可复用的单一 rubric 设计机制；trigger 是否清楚描述触发条件或使用场景，且仅凭未来 task 可判断，范围是否足以支持机制及指导强度；应用机制是否尊重任务目标与明确约束。当前 task 用于理解候选的条件边界，迁移范围以 trigger 为准。

允许设计评价维度、安排标准重要性、排除不当要求等具体指导。可迁移意味着满足 trigger 的同类任务间复用，无须适用所有领域；任务类别有限、需要语义理解或方法具体均不单独构成拒绝理由。单一机制可包含协同动作，只有可独立使用且触发条件不同的多条原则应拆开。定性指导无须统一固定数值阈值，审核其任务语义支撑。

## 理由与效果边界

理由引用具体 content/trigger 文本并解释符合或违反的条件。拒绝须定位明确缺陷：依赖未来回答/既有标准/Judge、保留样本答案或专有细节、改变任务目标、条件不足以支撑强制指导、混入独立原则或要求程序不支持的机制。仅写“太具体”“非通用原则”“属于制定评估标准的方法论”不足以拒绝。

PASS 表示表达合格，不代表经验有效。Admission 仍审查明显逻辑/边界缺陷，但不提前证明泛化增益；实际效果由后续下游验证，修订成功和信用分数不替代此验证。

返回 decision（PASS/FAIL）和具体 reason。FAIL 候选不入池；PASS 交给 Fusion。准入不产生信用，不自动改写候选。

新增经验以 Beta(1,1) 为基础；ADD/MERGE 都在合法融合后追加弱修订证据。MERGE 改写融合文本、保留历史 Beta 和证据，并记录文本版本，见[经验融合](./10-经验融合.md)。后续任务 R0 的 downstream credit 独立更新，见[已有经验信用](./05-已有经验信用分配.md)。
