# 原子候选集合的验证与入池

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

路径保留。没有Admission模型、Fusion/MERGE；本文件描述确定性资格和延迟入池，不新增判断经验正确性的模型门禁。

## 1. 每轮候选集合

Critic最多两轮，每轮0～1份草稿，Atomizer整理为非空原子候选集合C_r。新Generator只接收task＋固定E＋当前C_r；第二轮不叠加C_1。每个原子候选具有独立ID、trigger/content及实际来源记录。

Judge有效后，逐候选按引用标准计算P/N。实际提供、被引用且自身P>N为eligible，不要求整体成功。P=N、P<N或未采用均不合格；混合正负信用分别保存，不能用P−N替代双通道。

## 2. 正常结束选择哪一轮

工程初始约定：令A_r为第r轮合格原子候选集合。

```text
A_2非空 → 入池A_2全部成员
否则A_1非空 → 入池A_1全部成员
否则 → 无新增
```

不跨轮拼接，不按margin挑选，不再限制每题最多一条。整体成功结束轮次；失败有预算继续。第二轮空草稿或格式/结构耗尽可正常回退第一轮集合，但请求耗尽、拒答或Judge错误结束不做正常回退。

每条被选候选以新ID保存其实际应用文本和来源案例，初始alpha=1+P、beta=1+N；仅计该轮本候选P/N。来源案例不占5条下游窗口。未选择轮、未采用或不合格候选保留轨迹但不写入池信用。

## 3. 与演化新版本的区别

| 对象 | 是否需要本题应用资格 | 初始信用 |
|---|---|---|
| Critic产生的原子候选 | 需要被引用且自身P>N，并被最终轮次选择 | Beta(1,1)＋该候选实际应用P/N |
| Updater演化子版本 | 不额外做入池验证，合法演化提交后直接激活 | 独立Beta(1,1)先验＋继承信用＋演化惩罚；父账本原样留档 |

两者都进入待分类队列，后续只累计自己的实际R0反馈。演化不能借候选入池路径复制父信用，候选也不能借演化路径绕过应用资格。

## 4. 边界

多来源标准按引用数均分，拆分候选不能获得整份重复权重。整体成功与入池结果分别保存，整体失败可有多个合格候选，整体成功也可无入池。

有限纠错与样本错误隔离见[训练流程](12-训练流程.md)，已有合法R0信用不回滚。结构或来源有效不证明方法通用、Judge正确、独立因果作用或原子性。新协议拒绝旧单候选产物跨方法resume。
