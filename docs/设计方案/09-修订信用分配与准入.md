## 1. 直接提供与自主采用

Critic提出0–1条候选，程序校验结构、唯一ID和未融合状态。非空候选以原文直接进入独立Generator，标注“当前候选、尚未验证，无历史置信度”。这些结构校验不审查语义质量。

Generator只看task、固定E和本轮C，自主采用、组合或忽略。下一轮替换C，不积累前轮候选。候选被提出或提供不构成应用成功，不产生数值信用，也不能被Memory检索。

## 2. 应用与入池

| 阶段结果 | 处理 |
|---|---|
| 空候选 | 正常结束，无应用 |
| 未形成有效评分标准或Judge | 保存错误，不伪造采用或成功 |
| Judge失败 | 保存真实应用证据，剩余轮次可重新提出 |
| Judge成功但未引用C | 任务成功，C未采用，不Fusion，结束 |
| Judge成功且引用C | 同一候选可Fusion，无额外信用方向门槛 |

每轮一次提案，最多两轮。Fusion默认ADD原文，只有兼容的同一设计问题才MERGE并保留文本版本。不存在成功后的二次审核或Reflector改写。

## 3. 证据边界

来源引用是采用自报，不证明真实实施或因果贡献。应用P/N按本轮引用标准计算，分别累计alpha/beta，无折扣、不先抵消；零信用不阻止合法Fusion。失败、未应用、未采用候选只保留轨迹。

候选抽象和任务忠实性仍由Critic/Generator职责约束。删除Admission不证明候选通用、无泄漏或有效；同任务成功也不证明迁移。
