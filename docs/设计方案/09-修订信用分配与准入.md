# 候选经验准入（先于Generator应用）

> 上位文档：[设计总览](../设计方案.md) ｜ 输入：[Critic候选](06-失败修订.md) ｜ PASS后：[新会话应用](07-Generator对话修订.md)
>
> 新机制已实现，离线契约验收通过；沿用路径，不恢复操作绑定或修订操作信用。

## 1. 顺序与输入

Admission放在Critic之后、Generator之前，每次审核本次候选。模型只看原始task和候选ID/content/trigger，不看偏好对、rubric、Judge结果、Critic私有analysis、信用或经验池。PASS仅表示允许试用；不直接Fusion、入池或涨信度。

## 2. 审核要求

经验应提供具体、连贯、可复用的rubric设计指导，trigger表达首次生成前可识别的任务/输入场景，尊重任务目标、明确约束与实际条件。

允许任务语义、输入完整性、上下文和领域知识推理，不要求task逐字声明条件；允许评价维度、重要性安排、排除不当要求及同一目的下的协同动作。复杂、具体或限定任务类型不是拒绝理由，不要求适用于所有领域。

content可指导核验未来回答，trigger不能依赖已经看到的回答特征、现有rubric或Judge结果。准入排除明确缺陷：事后trigger、样本答案细节/偏好身份、目标漂移、内容与条件不匹配、无关指导拼接、程序不支持的评分机制。“太具体”“不通用”或“属于制定评价标准的方法论”不能独立成为理由。

## 3. 返回与一次重生成

返回PASS/FAIL及定位实际content/trigger的具体reason，Admission不改写候选。

```text
首次FAIL → 被拒候选 + 拒绝原因反馈同一个Critic → 重生成一次 → 再Admission
再次FAIL → 保存两个候选与理由，结束任务，不进入Generator
PASS → 固定通过候选原文 → 新Generator会话
```

拒绝重生成消耗本轮唯一准入重试机会，不能每次回到Critic就重置。只有实际应用后Judge失败进入下一轮时，才重新获得该轮的一次准入重试。两轮合计Critic业务生成最多4次。

被拒候选留档但不得出现在Generator输入、Memory或检索结果。重生成是新的候选版本/ID，不能覆盖第一次拒绝记录。

## 4. 证据边界

生成、准入、提供候选本身不产生信用。后续成功但未采用C，仍不能入池；只有PASS、采用标记和Judge成功同时成立的候选才可Fusion。

准入检查表达和明显逻辑/边界缺陷，不预先证明有效或保证无泄漏。成功应用不认证效果；候选按引用标准的P/N分别无折扣更新，不先抵消，双通道均0才不更新；没有成功后的二次Admission或额外审核门禁。
