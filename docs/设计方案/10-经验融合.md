# 经验融合（Experience Fusion）

> 上位文档：[VERGE 设计总览](../设计方案.md)
>
> 输入：[通过准入且带 Credit 的 Candidates](./09-修订信用分配与准入.md) ｜ 输出：[Experience Memory](./01-经验记忆.md)

## 1. 模块职责

决定带有 revision credit 的候选经验如何被 Experience Memory 吸收。V1 只输出：

```text
MERGE
ADD
```

Fusion 判断语义等价，不判断哪条经验最终正确。

## 2. 两阶段融合检索

### 2.1 向量召回

使用候选经验的：

```text
content + trigger
```

从经验池召回少量最相似的 canonical experiences。经验池为空时直接 `ADD`。

向量相似度不能直接触发 MERGE，因为冲突经验通常也具有较高语义相似度。

### 2.2 LLM 等价判断

LLM 只比较候选与相似经验的：

```text
content
trigger
```

判断是否存在同时满足以下条件的经验：

- rubric-generation principle 实质相同；
- 指导动作实质相同；
- trigger 的适用范围实质相同。

Reliability、source trajectory、operation log 和 credit binding 不参与等价判断。

## 3. MERGE

存在等价 canonical experience 时：

1. 保留已有 experience ID、content 和 trigger；
2. 向 `source_trajectories` 追加当前 sample ID；
3. 将候选的 revision credit 转移到 canonical Beta 状态：

$$
\alpha_e\leftarrow\alpha_e+\max(I_t(e),0)
$$

$$
\beta_e\leftarrow\beta_e+\max(-I_t(e),0)
$$

4. 在 `evidence_history` 中记录 `revision_credit` 和来源 trajectory；
5. 不重复加入候选经验的基础先验。

## 4. ADD

没有等价经验时，创建新 Experience：

$$
\alpha_e=1+\max(I_t(e),0)
$$

$$
\beta_e=1+\max(-I_t(e),0)
$$

并记录：

```text
source_trajectories: [current sample_id]
evidence_history: current revision_credit
```

如果 $I_t(e)=0$，新经验状态为 $Beta(1,1)$。

如果同一 trajectory 产生语义等价的多个候选，Fusion 会让第一个候选执行 `ADD`、后续候选执行 `MERGE`。Revision Credit Assignment 已经在共享候选之间分摊同一 operation contribution，因此不会重复放大 revision credit。

## 5. 冲突经验

候选与已有经验给出相反指导时，不属于语义等价，执行 `ADD`。

V1 不在 Fusion 阶段裁决冲突真伪。冲突通过未来使用延迟解决：

- Retrieval 可能召回两者；
- Selector 不同时选择相互冲突的经验；
- trigger、confidence 与 exploration 决定哪一条获得验证机会；
- downstream evidence 持续调整 Beta 状态。

## 6. Fusion 输出

```text
FusionResult {
    candidate_id
    decision: MERGE | ADD
    canonical_experience_id
    transferred_revision_credit
}
```

Fusion 不修改候选文本、不重新执行 Admission，也不重新计算 revision credit。
