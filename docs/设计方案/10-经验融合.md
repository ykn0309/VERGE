# 经验新增与延迟重新归纳

当前见[计划61](../plans/61-延迟归纳与正负案例经验更新.md)。路径保留用于链接；没有Fusion、MERGE或经验拆分。

候选采用且自身P>N才有资格，正常样本结束最多新增一条：合格C2优先，否则C1。保存实际原文、来源案例与信用，不要求整体成功。

已有经验只按训练R0即时累计信用，在样本收尾收录不同任务的正向、负向和同判实际使用案例，包含来源最多10条。原题不计下游任务窗口；每累计3个不同下游任务反馈归纳一次。成功输出（含保留文本）重置计数，失败保留窗口但同一新案例不重复尝试；后续新案例可再试。第10个案例强制最后归纳，之后只累计信用、冻结文本及案例。

输入signed_cases_v3：当前content/trigger；完整task/chosen/rejected；仅引用本经验的标准及两侧Judge Boolean/reason；逐标准feedback=positive/negative/neutral（同判为较轻负信用）。不提供P/N、标准权重、来源数、无关标准、整体分数、Critic分析或人工理由；实际使用文本不同才附applied_experience。案例标识仍映射为本次短数字。完整system/user UTF-8预算100,000字节，不截断。

返回JSON：

```json
{"content":"设计方法","trigger":"生成前可识别的条件"}
```

只更新原经验，不返回分组、不新增analysis、不额外审核。正负案例共同帮助识别方法不足或适用条件过宽；同判只说明本次无区分，不自动证明经验错误；Judge理由保留但不是事实认证。content≤150字符、trigger≤60字符仅提示词约束，不校验长度。

ID和Beta保持，文本变化才版本+1；保存实际使用版本及前后文本。历史信用不自动认证新文本。归纳输出/预算/拒答错误保留旧文本、信用和案例，网络、存储及程序错误fail-fast。held-out只读不归纳。历史旧协议产物保留，不迁移或跨协议resume。
