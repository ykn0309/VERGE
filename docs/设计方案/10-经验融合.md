# 经验融合（Experience Fusion）

> 上位文档：[设计总览](../设计方案.md) ｜ 输入：[准入](./09-修订信用分配与准入.md) ｜ 输出：[经验记忆](./01-经验记忆.md)

## 检索与文本融合

以候选 content + trigger 向量召回 Top-20；池为空直接 ADD。Fusion 模型只接收双方 content/trigger，不接收回答、诊断、Beta、信用或内部 ID。

融合与 Reflector/Admission 共用经验定义：供 rubric generator 使用的具体可复用设计机制，允许维度设置、权重调整及排除不当要求。同类条件任务间可复用即可，无须跨所有领域适用；同一机制可含协同动作，独立机制应分别表达。

同一核心 rubric 设计机制可等价或互补融合，允许扩展指导动作与适用范围；融合结果保留有效指导、既有约束及条件边界，trigger 全部仅凭未来 task 核验，且各条件分支足以支持对应 content 的范围与指导强度，应用仍尊重任务目标和明确约束。无关或冲突指导作为独立经验 ADD，不以话题相似代替机制兼容。融合保持可用表达，历史信用不认证新扩展；内容安全依赖提示词与既有准入，不新增审核阶段或内容门禁。

输出 `{"match_index":整数位置,"content":完整融合方法,"trigger":完整融合条件}`；无兼容机制输出三个 null。位置及非空文本由程序校验；数值信用由 Calculator 计算，LLM 不赋值。

## ADD / MERGE

ADD 使用候选文本，新 ID、Beta(1,1)。MERGE 保留原 ID，写入融合后的 content/trigger，继承已有 alpha/beta 与所有信用证据。两者都追加来源样本、文本版本及弱修订证据。

信用为 `0.25 * min(1, M(R_success) - M(R_previous_valid))`，类型 `fusion_credit`、weight=1。第二轮用最近有效修订作基线，第一轮无效时用 R0。只在准入通过且融合结果合法后写入；拒绝或无效融合不产生该证据。

新正证据增加 alpha，beta 保留，confidence=alpha/(alpha+beta)。不相加基础先验，不把 candidate.credit 作为旧操作信用恢复。每条经验 fusion_history 保存样本/候选、ADD/MERGE、修改前后 content/trigger 和本次信用；候选轨迹也记录 fusion_record。

## 解释与边界

margin 增益是修订的弱关联证据，不证明该候选的因果贡献。继承的历史证据支持旧版本，不认证新扩展；反复发现可能累积正证据。后续训练 R0 信用仍独立更新；测试不融合、不记账。旧实验只读保留，新方法必须使用新目录，不跨提示词版本续跑。
