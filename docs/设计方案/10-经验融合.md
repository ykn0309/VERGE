# 经验融合（Experience Fusion）

> 上位文档：[设计总览](../设计方案.md) ｜ 输入：[应用成功及采用记录](07-Generator对话修订.md) ｜ 输出：[经验记忆](01-经验记忆.md)
>
> 新机制已实现，离线契约验收通过；旧公式见[计划21](../plans/21-经验文本融合与弱修订证据.md)。

## 1. 进入条件

同一个候选必须同时满足：Admission PASS、在本次生成前实际提供给Generator、criterion来源声明采用该候选、Judge有效成功。

成功但未采用C不Fusion、不入池，也不追加验证证据；被拒候选、失败候选和未提供的候选均不能进入。准入和应用对象为固定原文，成功后不调用Reflector替换候选、不重复Admission。采用标记仅为模型自报，不证明语义忠实或因果性，不新增独立审核角色。

## 2. 检索与保守文本融合

以候选content+trigger向量召回Top-20，池为空直接ADD。Fusion模型只接收双方content/trigger，不看回答、私有诊断、Beta或信用。

默认ADD。只有同一评价设计问题、指导等价或同一方法的必要细化且适用条件兼容才MERGE；共享主题、质量目标、关键词、动作数或长度都不是合并依据。去重提炼而非拼接所有收获，保留生成前可识别的条件边界；无关设计目的分别保留，不设硬长度门槛。

沿用输出匹配位置及完整融合content/trigger，无匹配时三个null。程序只验证结构、位置和非空文本，不增加融合后准入或语义门禁。数值信用由确定性模块计算，不让模型给分。

## 3. 写入

ADD使用已验证候选原文、新ID、Beta(1,1)基础。MERGE保留原ID、继承已有Beta/证据并保存改写前后文本。两者记录来源样本、候选ID、实际应用结果及文本版本。

成功应用与信用证据分开。本轮候选按实际引用标准的归一化正/负判别差、多来源均分计算P/N，alpha加P、beta加N，不先抵消、不乘lambda或使用旧margin增益。ADD从(1,1)更新，MERGE在目标原Beta更新；只有P=N=0不改Beta，净方向0且P=N>0仍更新。净方向不另设入池门禁，整体成功不能消除负证据，详见[可靠性](11-可靠性更新与噪声证据.md)。

## 4. 解释边界

采用并成功不证明该经验导致成功：新会话重采样、其他E、Judge噪声、候选泄漏和问题方向错误均可能影响结果。MERGE继承信用不认证新扩展。后续训练R0下游信用仍独立维护；测试冻结，不融合不记账。

历史目录保留，不按新条件追溯改判、删证据或补造引用；新代码不兼容旧fusion_credit或轨迹解码。新方法使用新标识和目录，不迁移旧检查点，不跨版本resume。
