# 可靠性更新与正负证据

> 上位文档：[设计总览](../设计方案.md) ｜ 来源：[R0信用](05-已有经验信用分配.md)、[候选应用](07-Generator对话修订.md)
>
> 当前以[计划61](../plans/61-延迟归纳与正负案例经验更新.md)为准：保留Beta正负累计，补同判25%轻负信用，正负案例延迟归纳；历史阶段记录保留。

## 1. 职责与解释

保留Beta(1,1)基础和confidence=alpha/(alpha+beta)，作为可复算的平滑证据分数。来源是模型自报、Judge可能有噪声，confidence不是严格校准的“经验有效概率”，信用不解释为因果贡献。

R0已有经验与应用候选统一使用正负双通道，不先抵消成净信用，不使用信用衰减或margin增益；同判的负信用为标准额度25%。任务成功与经验的信用分开，入池资格和记账分开；计划48要求被选候选自身P>N，不要求整体成功。

## 2. 正负分别累计

对于本次rubric R中被声明采用的经验或候选e：

$$
P_R(e)=\sum_{i:e\in S_i}\frac{\omega_i(R)\max(d_i,0)}{|S_i|}
$$

$$
N_R(e)=\sum_{i:e\in S_i}\frac{\omega_i(R)(\max(-d_i,0)+0.25\mathbf{1}[d_i=0])}{|S_i|},
\qquad d_i=J(y^+,c_i)-J(y^-,c_i)
$$

来源均分，P,N均非负、P+N≤1。标准d=0产生额度25%的负证据。U=P−N仅展示净方向，不控制更新或记账。

- 已有经验只从R0更新，应用R1/R2再引用E不重复记本样本下游信用。
- 候选C从本轮实际应用rubric计算，不比较两个独立会话margin。
- 失败候选不入池；其P/N可在轨迹供诊断，不扣给不相关池经验。
- 未引用时不记信用；引用后全部d=0时，按标准额度25%累计N。

## 3. Beta更新与入池资格

$$
\alpha\leftarrow\alpha+P_R(e)
$$

$$
\beta\leftarrow\beta+N_R(e)
$$

不折损，首版evidence_weight固定1。P+N=0才不更新；P=N>0时同时更新两个参数，即使净方向为0。净方向控制入池/文本更新资格，不决定是否追加R0数值证据。

R0在有效Judge后、成败分支前回写，后续失败不回滚。候选需采用标记+有效Judge+自身P>N；样本正常结束后最多选一条新增，从(1,1)追加被选轮次P/N。取消Fusion/MERGE，不累加未选候选信用。已有E始终按R0双通道记账，有实际信用均收集案例，每3个不同下游任务触发有限案例文本更新，第10条强制最后尝试，不能把整体成功强行记为只有正证据。

有限案例重新归纳后，原累计证据不自动认证新文本。分数信用及相互关联标准不满足未经论证的独立Bernoulli观测假设，Beta只作证据累计模型。

## 4. 证据协议与强度

新证据分别保存positive_credit、negative_credit及样本、候选ID、权重1、来源标准和实际使用text_version。区分R0 downstream_credit与候选application_credit。净方向可派生展示，不能仅存一个净值丢失双通道。不兼容旧revision_credit/fusion_credit，不迁移历史。

Selector除confidence还看累计证据强度：

$$
A_e=\alpha_e+\beta_e-2
$$

用A表示累计强度，避免与单次负向N混淆。本次增量为P+N，不是|P−N|。A不等于独立任务数；实际应用次数可从轨迹单独统计，不能用A代替。

正负均增加不保证confidence不变：当P=N时将原比例拉向0.5；只有从对称Beta开始才维持0.5。不能把“证据量增加”解释为“经验质量更高”。

## 5. 数值例子

从alpha=beta=1开始：

| 同次经验信用项 | P / N | 更新后alpha/beta | confidence | A增加 |
|---|---|---|---:|---:|
| 仅+0.2 | 0.2 / 0 | 1.2 / 1 | 0.54545 | 0.2 |
| +0.2与−0.2 | 0.2 / 0.2 | 1.2 / 1.2 | 0.5 | 0.4 |
| +0.3与−0.2 | 0.3 / 0.2 | 1.3 / 1.2 | 0.52 | 0.5 |
| 仅−0.2 | 0 / 0.2 | 1 / 1.2 | 0.45455 | 0.2 |
| 未引用 | 0 / 0 | 1 / 1 | 0.5 | 0 |
| 引用额度0.4、两答同判 | 0 / 0.1 | 1 / 1.1 | 约0.4762 | 0.1 |

没有lambda，不缩小P/N。

## 6. 更新边界

召回、选择、提出或仅提供C不写信用。成功未采用C不入池、不记正负信用、不强迫继续验证；未入选/未应用候选仅留轨迹；整体失败但自身净正向可具入池资格。

技术错误隔离保留已完成R0信用，未知Judge不伪造。新方案不增加噪声审计角色、额外权重、衰减、分场景模型或旧协议兼容；历史产物保持原样。

held-out冻结池、文本及Beta，不提出候选、不融合、不回写信用；离线分析只能输出，不修改池。

## 延迟归纳（计划61）

取消拆分及信用继承分配；只更新同一ID的content/trigger，Beta继续累计。正负案例共同占用包含原题的10条上限，成功归纳后重新计数，失败不重置窗口，第10条后文本冻结；历史信用不自动认证改写文本。见[计划61](../plans/61-延迟归纳与正负案例经验更新.md)。
