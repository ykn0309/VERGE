# 可靠性更新与正负证据

> 上位文档：[设计总览](../设计方案.md) ｜ 来源：[R0信用](05-已有经验信用分配.md)、[候选应用](07-Generator对话修订.md)
>
> 新方案已确定无折扣、正负分别累计；代码已实现，真实效果未验证，见[计划31](../plans/31-Critic候选经验准入与新会话验证.md)。

## 1. 职责与解释

保留Beta(1,1)基础和confidence=alpha/(alpha+beta)，作为可复算的平滑证据分数。来源是模型自报、Judge可能有噪声，confidence不是严格校准的“经验有效概率”，信用不解释为因果贡献。

R0已有经验与应用候选统一使用正负双通道，不先抵消成净信用，不使用lambda或margin增益。任务成功与经验的信用分开，入池不是自动涨信度。

## 2. 正负分别累计

对于本次rubric R中被声明采用的经验或候选e：

$$
P_R(e)=\sum_{i:e\in S_i}\frac{\omega_i(R)\max(d_i,0)}{|S_i|}
$$

$$
N_R(e)=\sum_{i:e\in S_i}\frac{\omega_i(R)\max(-d_i,0)}{|S_i|},
\qquad d_i=J(y^+,c_i)-J(y^-,c_i)
$$

来源均分，P,N均非负、P+N≤1。标准d=0不产生任一通道证据。U=P−N仅展示净方向，不控制更新或记账。

- 已有经验只从R0更新，应用R1/R2再引用E不重复记本样本下游信用。
- 候选C从本轮实际应用rubric计算，不比较两个独立会话margin。
- 失败候选不入池；其P/N可在轨迹供诊断，不扣给不相关池经验。
- 未引用或全部引用标准d=0时，P=N=0，不增加Beta；不视为负证据。

## 3. Beta更新与入池资格

$$
\alpha\leftarrow\alpha+P_R(e)
$$

$$
\beta\leftarrow\beta+N_R(e)
$$

不折损，首版evidence_weight固定1。P+N=0才不更新；P=N>0时同时更新两个参数，即使净方向为0。净方向不决定是否追加数值证据。

R0在有效Judge后、成败分支前回写，后续失败不回滚。候选仍需PASS+采用标记+有效整体成功+合法Fusion：ADD从(1,1)更新；MERGE在目标原Beta追加本候选P/N并保存文本版本和来源。不新增“净信用必须为正”的入池门禁，不能把整体成功强行记为只有正证据。

MERGE继承证据不认证新文本。分数信用及相互关联标准不满足未经论证的独立Bernoulli观测假设，Beta只作证据累计模型。

## 4. 证据协议与强度

新证据分别保存positive_credit、negative_credit及样本、候选/目标经验ID、权重1、来源标准和版本关联。区分R0 downstream_credit与候选application_credit。净方向可派生展示，不能仅存一个净值丢失双通道。不兼容旧revision_credit/fusion_credit，不迁移历史。

Selector除confidence还看累计证据强度：

$$
A_e=\alpha_e+\beta_e-2
$$

用A表示累计强度，避免与单次负向N混淆。本次增量为P+N，不是|P−N|。A不等于独立任务数；实际应用次数可从轨迹单独统计，不能用A代替。

正负均增加不保证confidence不变：当P=N时将原比例拉向0.5；只有从对称Beta开始才维持0.5。不能把“证据量增加”解释为“经验质量更高”。

## 5. 数值例子

从alpha=beta=1开始：

| 同次经验信用项 | P / N | 更新后alpha/beta | confidence | A增加 |
|---|---|---|---:|---:|
| 仅+0.2 | 0.2 / 0 | 1.2 / 1 | 0.54545 | 0.2 |
| +0.2与−0.2 | 0.2 / 0.2 | 1.2 / 1.2 | 0.5 | 0.4 |
| +0.3与−0.2 | 0.3 / 0.2 | 1.3 / 1.2 | 0.52 | 0.5 |
| 仅−0.2 | 0 / 0.2 | 1 / 1.2 | 0.45455 | 0.2 |
| 只有d=0或未引用 | 0 / 0 | 1 / 1 | 0.5 | 0 |

没有lambda，不缩小P/N。

## 6. 更新边界

召回、选择、提出、准入或仅提供C不写信用。成功未采用C不入池、不记正负信用、不强迫继续验证；拒绝/失败候选仅留轨迹。

技术错误隔离保留已完成R0信用，未知Judge不伪造。新方案不增加噪声审计角色、额外权重、衰减、分场景模型或旧协议兼容；历史产物保持原样。

held-out冻结池、文本及Beta，不提出候选、不融合、不回写信用；离线分析只能输出，不修改池。
