# 训练与冻结评价流程

> 方法见[总览](../设计方案.md)，当前实施见[计划65](../plans/65-原子经验类别检索与同判独立记录.md)。

1. 根据task召回类别/未分类小经验，完整展开类别后Selector选定固定小经验E；Generator生成R0；Judge两侧独立判断。
2. 同判仅按双方满足/双方不满足计次，不扣信用、不参与归纳；训练R0有效后、成败分支前按来源计算P/N，alpha加P、beta加N。整体失败也记账，后续失败不回滚。
3. R0成功直接结束候选过程；R0失败执行最多两轮Critic提案与独立Generator应用。每轮0–1条候选，空候选正常结束。
4. 应用Judge有效后记录整体结果与候选局部P/N。引用候选且自身P>N为合格；先暂存，不立即入池。
5. 整体成功结束轮次；失败且有预算则Critic接续首轮真实消息，追加实际采用、rubric/Judge反馈。第二轮Generator仍只看固定E+新C。
6. 正常样本收尾时最多新增一条：优先合格C2，否则回退合格C1。仅写被选轮次的候选P/N。整体失败不阻止入池。
7. 对R0有信用的已有经验收录新的不同sample_id正负案例，每3个不同下游任务读取全部案例重新归纳；第10条强制最后一次，第11条起冻结文本和案例。成功归纳重置窗口，失败保留窗口、同一新案例不重复尝试。此步骤在候选过程结束后执行，R1/R2 E引用不重复记账或触发归纳。
8. 入池/正文变化进入待整理队列，默认5条小经验分类一次，失败保留队列和归属；训练完成/暂停处理剩余队列。保存入池选择、文本更新/分类及错误与完整轨迹，进入下一样本。训练始终顺序，业务轮次不因技术纠错增加。

Critic/应用Generator格式结构耗尽属于无效轮，第二轮耗尽可回退首轮合格候选；Judge错误、角色拒答、模型或Embedding请求重试耗尽是错误结束，不回退候选入池。记录错误阶段和原因，保留有效R0信用并完成有限案例收尾及轨迹保存，继续下一样本；不从头重跑已记账样本。归纳员格式结构错误、超输入预算、拒答或请求重试耗尽保存旧文本/信用/案例并记录错误，不改任务状态。鉴权/配置、数据、存储、Calculator和程序错误fail-fast。具体HTTP范围及预算见[计划63](../plans/63-请求失败样本隔离与经验排序.md)。

held-out冻结经验、文本、案例和Beta，只检索/选择/R0生成/Judge，没有Critic、候选应用、入池或归纳，不写信用。测试可以有界并发，提交顺序固定。
