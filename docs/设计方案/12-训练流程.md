# 训练、演化与冻结评价流程

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

## 1. 单样本顺序

1. 根据task混合检索Top20类别/未分类单位，完整展开类别后Selector选定最多5条活跃经验版本，冻结E的ID、文本和顺序。
2. Generator生成R0，Judge两侧独立判断；有效后在成败分支前记录E的P/N和同判计次。整体失败也记账，后续错误不撤销。
3. R0成功跳过候选；失败时Critic最多两轮，每轮0～1份草稿。非空草稿经独立Atomizer整理成原子候选集合C_r，再由新Generator(task＋固定E＋C_r)应用并Judge。
4. 每条候选独立计算采用、P/N和资格；整体成功结束轮次，失败有预算继续。第二轮Critic接续真实消息及原子化/应用反馈，Generator只替换整个C，不携带首轮候选。
5. 正常收尾入池最新合格轮的全部合格候选，第二轮无合格项则回退第一轮集合；不跨轮拼接。来源案例和实际P/N归各候选，来源不占下游归纳窗口。
6. 对有效R0中有数值信用的E，按不同任务收集本版本下游案例。每5条新反馈使用最近5条调用Updater；keep消费窗口，revise经Atomizer形成新版本。
7. 有效replace/split一次Memory提交：父退役、子新ID/独立先验及均分继承信用和演化惩罚/空窗口、演化关系、父类别成员移出和子待分类入队。失败保留父版本及合法R0信用。新版本只参与未来样本，不反向改写固定E或回填本题信用。
8. 待分类队列默认5条触发局部归类，每条检索Top10类别，逐项只写目标归属；批末对dirty类别一次更新name/description，空类别由程序删除。
9. 保存完整轨迹、实际请求/回复、信用/演化/分类/描述事件及错误，再进入下一样本。训练顺序执行，不因技术纠错增加业务轮次。

## 2. 错误边界

| 情况 | 处理 |
|---|---|
| Critic、候选Atomizer、应用Generator格式/结构纠错耗尽 | 当前轮无效，有剩余轮次可继续；正常耗尽可回退已合格集合 |
| 候选阶段Judge错误、角色拒答、请求重试耗尽 | 错误结束，不做正常候选回退入池；保存有效R0信用和可执行的有限收尾 |
| R0前Embedding/模型请求或输入失败 | 记录样本错误，不能制造R0/信用或按预测错误充数 |
| Updater/演化Atomizer格式、预算、拒答或请求失败 | 父版本和已有信用保留，记录本次尝试，不消费反馈；同一最新案例不重复调用 |
| 局部归类失败 | 保留该目标队列/归属，其他已成功项不撤销 |
| 类别描述更新失败 | 保留已提交成员关系和旧描述，保存dirty增删记录 |
| 鉴权/配置、数据/存储、Calculator和程序故障 | fail-fast，不伪装成普通样本错误 |

超时、连接、HTTP 408/429/5xx耗尽以及API拒绝输入等沿用[计划63](../plans/63-请求失败样本隔离与经验排序.md)的有限隔离边界；不从头重跑已经记账的样本，不无限重试。

## 3. 暂停、收尾与恢复

训练暂停/完成处理剩余待分类队列，并对有新变化且可尝试的dirty类别做有界描述更新；失败版本去重，不把收尾当作无限重试机会。不足5条的归纳窗口不强制演化，无新任务不反复归纳。

stop_after_train按已处理训练前缀暂停，不自动启动held-out。新协议编号实施时统一升级，resume要求代码/配置/提示词/数据一致、完整有序轨迹和无越界Memory写入；旧协议拒绝跨方法resume。Memory内原子提交不代表跨文件事务，检测到不一致必须显式报错。

## 4. 冻结评价

held-out只使用冻结的活跃版本和类别进行检索、Selector、R0与Judge；无Critic/Atomizer/Updater/归类/描述更新，无任何信用、usage、窗口或分类写入。允许只读索引缓存和有界并发评价，按固定顺序提交结果。

## 5. 验证边界

确定性测试验证账本、状态转换、权限、窗口、索引和错误隔离；每个改动模块独立复测至少20条有代表性真实历史来源输入，输出不反馈到后续样本。完整链路需后续单独实验，不从局部结果推断泛化或因果收益。
