# 训练流程

> 上位文档：[设计总览](../设计方案.md) ｜ 实施：[计划42](../plans/42-删除Admission直接应用候选经验.md)
>
> 新机制已实现，离线契约验收通过；历史7ab9bdc基线在main保留。

## 1. Online Experience Learning

池可为空，已有经验检索与Selector均不看偏好对。每个训练样本：

1. 检索/筛选得到E，固定本样本E列表和文本。
2. Generator(task+E)生成R0，Judge评价。
3. 由R0的来源标注及Boolean结果计算已有经验下游信用并立即回写Memory；不以R0总体成败统一增减。
4. R0成功，保存轨迹并结束；有效失败才进入候选应用流程。
5. 每轮Critic提出一次0–1条候选；空候选结束，有候选直接进入独立应用。
6. 候选原文固定，新Generator只看task、E和本轮候选；自主采用，不能继承旧会话。
7. Judge评价：成功且采用C才Fusion；成功未采用C则任务成功、候选未验证，不入池并结束。
8. 正常业务首轮应用Judge失败后，Critic根据实际输出/Judge/候选与采用记录重新提出指导；第二轮替换候选，不增加同轮重生成。格式/结构耗尽按既有无效轮隔离，在剩余预算内可继续，但不伪造Judge失败或新增轮次。
9. 第二轮Judge仍失败则结束，失败候选不入池。全部候选、实际会话、采用和结果留档。

最多2次Critic业务候选生成、2轮应用生成/Judge；底层请求纠错不混入业务计数。空池时E为空仍可学习候选。无可用候选可正常结束，不用普通建议替代候选经验。

## 2. 终止与Memory写入

| 终止原因 | 任务判别 | 新候选 |
|---|---|---|
| R0成功 | 成功 | 未生成 |
| 无候选 | 未获得成功应用 | 不入池 |
| 应用成功且采用C | 成功 | Fusion合法后写入 |
| 应用成功但未采用C | 成功 | 未采用/未验证，不入池 |
| 两轮应用Judge失败 | 失败 | 仅留档，不入池 |
| 无有效rubric/Judge | 未知或错误 | 不伪造验证与成功 |

R0下游信用的写入独立于候选流程，之后失败不撤销；只对实际引用且P+N>0的已有经验更新，净方向0但存在双通道证据仍更新。E在R1/R2的引用用于审计，不重复算本样本下游信用。

R0已有经验与候选统一按实际来源的P/N分别无折扣更新Beta，不先抵消；净方向只展示，双通道均0才不更新。不复用旧margin增益，整体成功仍可有候选负证据，入池资格不变。Fusion保留ADD/MERGE、版本和来源边界，不新增事后Reflector或补充审核。Memory与trajectory仍不是跨文件事务，恢复需严格审计。

## 3. Held-out Evaluation

训练结束冻结经验池、文本及alpha/beta/confidence；关闭exploration，只做已有经验检索/筛选、R0生成和Judge。无Critic候选、应用生成、融合或下游信用回写。测试可限流并行，轨迹按数据顺序；训练逐样本顺序更新。

## 4. 删除旧诊断与协议

新方案删除无经验诊断模式及experience_enabled开关，不保留旧普通对话修订分支。空池或Selector不选E不等于关闭经验，失败后的候选直接应用流程照常执行。此前两次100条运行只留历史报告，不能复用为新机制结果。

格式/结构耗尽沿用既有有限纠错和无效轮/样本错误隔离，不全局终止；Judge错误明确记录，不伪造判定。后端格式耗尽不再叠加额外格式重试；鉴权/网络服务、数据/存储和程序错误沿原全局故障策略。错误结束样本后继续后续样本，已有R0信用不撤销。

不兼容旧字段、配置、提示词或Web日志，不做历史迁移；旧目录保留且不能跨方法resume。新字段直接按目标定义。

run.stop_after_train保留绝对已处理前缀（含错误轨迹），暂停不启动测试。真实实验仍需授权及新输出目录；仅新机制自身且版本/配置/数据一致的完整检查点才可按既有严格审计方式续跑。
