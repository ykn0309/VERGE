## 1. 模块职责

本文只负责串联各模块，不重复定义模块内部公式。

## 2. Online Experience Learning

经验池初始化为空：

$$
\mathcal{E}_0=\varnothing
$$

对每个训练样本依次执行：

1. [向量召回与 LLM 筛选](./02-经验检索与筛选.md)；
2. [生成 initial rubric](./03-初始Rubric生成.md) $R_0$；
3. [归一化 importance scores 并 Judge](./04-Rubric-Judge.md)；
4. [计算已有经验信用](./05-已有经验信用分配.md)，训练时立即更新已有经验的 Beta 状态和 evidence history；
5. 如果 $R_0$ 失败，进入[失败修订](./06-失败修订.md)；
6. Critic 同次输出私有 analysis 和 operations，[Revision Executor](./07-原子操作修订.md)构造 $R_1$ 或 $R_2$；
7. Revision success 后执行[Reflection](./08-经验反思.md)；
8. 执行[operation 收益、binding、revision credit 和 Admission](./09-修订信用分配与准入.md)；
9. 对通过 Admission 的 candidates 执行[Experience Fusion](./10-经验融合.md)，在此阶段写入 ADD / MERGE 结果。

V1 不实现跨阶段回滚、崩溃恢复或重复运行去重；若后续修订流程出错，第 4 步已写入的下游信用仍保留。Judge 输出经有限重试仍无效时，记录 `judge_error_initial` 或 `judge_error_revision` 并继续下一条；初始 Judge 无效不进入第 4 步，修订 Judge 无效不产生对应 revision judgment、reflection 或新的经验。

经验池为空或没有适用经验时，generator 只根据 task 生成 $R_0$；失败时仍可进入 revision 流程。

## 3. Revision Branch

```text
R0 success
→ 不 revision，不 reflection

R0 failure
→ Critic 诊断并生成 (analysis1, O1) against R0
→ Apply(R0, O1) = R1（操作结构不合法时无 R1，保存 analysis 与校验摘要）
    ├─ success → successful operations = O1
    └─ failure（含无效操作）
        → Critic 参考真实历史并生成 (analysis2, O2) against R0
        → Apply(R0, O2) = R2（操作结构不合法时无 R2）
            ├─ success → successful operations = O2
            └─ failure（含无效操作）→ final failure
```

## 4. Experience Growth Branch

```text
Revision Success
→ Reflection 0–3 candidates
→ Revision Credit Assignment
    ├── calculate operation contributions
    ├── bind candidates to operations
    └── calculate provisional credits
        ├─ CREDIT_FAIL → discard
        └─ credit success → Admission
            ├─ FAIL → discard candidate and its credit
            └─ PASS → MERGE / ADD
```

Admission 失败不会改变其他 candidates 的 credit。

## 5. Held-out Evaluation

训练结束后冻结经验池和 Beta 状态：

```text
关闭 exploration
不执行 revision-based experience growth
不回写 downstream credit
只评估 initial rubric
```

只读测试样本可在单进程内有界并行计算，轨迹仍按原始测试数据顺序提交；训练始终逐样本顺序更新经验池。
