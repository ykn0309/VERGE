# 完整示例：原子候选、版本演化与局部归类

> **当前实现：计划68信用继承与稳定性惩罚，Manifest/Trajectory10、Memory8。** 演化修订继承历史信用，拆分均分，惩罚为最近5例累计(P+N)的20%；详见[计划68](../plans/68-演化信用继承与稳定性惩罚.md)。其余方法承接[方案14](14-原子经验版本演化与局部混合检索.md)；计划67局部结果保留其原协议解释，见[报告67](../实验分析/67-版本演化与混合检索局部验证.md)。最近完整训练仍为计划66。

以下数字和任务为协议说明，不是数据集案例、运行结果或模型效果证明。

## 1. 一份草稿生成两个原子候选

R0整体失败后，Critic提出“核对计算方向和单位”。Atomizer生成C1a“核对数量关系对应的运算方向”和C1b“核对结果单位”，各有自己的trigger。

Generator只看task＋固定E＋[C1a,C1b]，本轮Judge后：

| 候选 | P | N | 资格 |
|---|---:|---:|---|
| C1a | 0.2 | 0 | 合格 |
| C1b | 0 | 0 | 同判或未采用，不合格 |

其他标准使整体仍失败，继续第二轮；C1a暂存不入池。Critic看到真实草稿、原子化结果及应用反馈，第二轮产生新的集合[C2a,C2b]。新Generator只接收固定E＋第二轮集合，不叠加C1a/C1b。

第二轮C2a得到P=0.3、N=0.1，C2b得到P=0.1、N=0，二者都合格。正常收尾只入池C2a/C2b，分别为Beta(1.3,1.1)和Beta(1.1,1)；C1a只留轨迹，不把其信用转给第二轮。如果第二轮没有合格项则回退C1a；如果第二轮Judge错误则不执行正常回退。

若某条权重0.2的标准同时引用两个候选，双方各分得0.1的正或负额度，不能每条都获得0.2。独立来源不是独立因果验证。

## 2. 五条反馈驱动演化

C2a入池后的来源案例只留来源记录。后续5个不同任务的有效R0分别给出：

| 下游任务 | P | N |
|---|---:|---:|
| T1 | 0.2 | 0 |
| T2 | 0 | 0.1 |
| T3 | 0.1 | 0.1 |
| T4 | 0.2 | 0 |
| T5 | 0 | 0.1 |

T3虽然P=N，仍有正反区分，计一个案例。期间若还有一个只有同判的任务，只增加usage，不占这5条。

第五条到达后父版本为alpha=1.8、beta=1.4，置信度56.25%。候选流程结束后，Updater读取父文本和T1～T5，输出revise草稿，Atomizer整理为一个修订版本D。

最近5例累计P+N=0.8，本次惩罚D_penalty=0.16。程序一次提交父退役、修订版本D激活及关系；父仍保存56.25%和全部证据。D继承P=0.8、N=0.4，另加惩罚0.16，因此alpha=1.8、beta=1.56、置信度约53.57%，证据量仍为1.2。D的实际反馈/usage/案例窗口为空，需要自己的5个下游有区分任务才再归纳；继承不等于已验证。

如果Atomizer输出两个方法D/E，每条分得P=0.4、N=0.2、本次惩罚0.08，加独立先验后各为alpha=1.4、beta=1.28、置信度约52.24%。两条合计继承P=0.8、N=0.4及惩罚0.16，均守恒；父先验不拆账。如果最终单条文本完全未变，则keep，父继续活跃；T6～T10的新批次才再归纳。如果本次请求失败，保留父和未消费状态，T6到来后可使用最近T2～T6有限重试，失败窗口允许重叠。

## 3. 新版本如何归类

D激活时未分类，可以直接参与任务检索。待分类队列达到5条或训练收尾时，程序用D的trigger/content执行混合检索，取得最多10个类别。

假设类别“数量关系核验”的名称/描述或成员命中，归类器看到该类和其他候选，选择把D放入该类。程序只写D的归属，不强制继承父类别，也不重写整个经验池。拆出的D/E可以分到同类或不同类；无合适类别可新建或保持未分类。

同批若该类加入D又移出一个退役父版本，批末只调用一次CategoryDescriber，输入旧名称/描述及增删文本；它只能返回name/description，不能把D移走。描述失败仍保留D归属和旧描述，dirty变化留待后续有界重试。

## 4. 下一次任务检索

类别名称/描述与每个成员各有独立索引。向量与BM25在文档层RRF融合，成员命中映射为类别，取最相关命中而非累加成员分数。去重后Top20类别/未分类单位展开供Selector选择最多5条具体活跃版本。

Selector看到D的50%与0证据，不看到父历史被冒充为D证据；Generator只接收所选ID/trigger/content。更新、分类、检索自身都不加分，D在未来R0实际应用中才得到自己的P/N。
