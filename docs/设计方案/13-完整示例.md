# 完整示例：候选直接独立应用

> 这是协议说明，不是实测效果。实施见[计划42](../plans/42-删除Admission直接应用候选经验.md)。

## 1. R0与已有经验

Task要求“准确说明概念及区别，并尽量简洁”。Selector选出固定E，Generator生成R0。假设两条正向Boolean标准的分配权重均为0.5，Judge chosen=[false,true]、rejected=[true,false]，margin=0，失败。

已有经验按R0的实际来源和判别差分配P/N；没有实质引用则不更新，不能把整体失败统一当作E负证据。

## 2. 首轮直接应用

Critic提出C1：

- content：“任务同时要求概念准确和简洁时，分别形成内容准确与简洁的正向Boolean标准；重要性体现任务主次，不用简洁抵消实质错误。”
- trigger：“任务同时要求准确解释概念及简洁表达。”

C1原文直接提供给全新Generator。没有Admission或同轮重生成；Generator只看task+固定E+C1，不看旧标准、私有分析、偏好对或Judge。

假设Generator声明采用C1，形成两条分配权重为0.8和0.3（程序按1.1归一化）的标准。若Judge给出前述Boolean结果，则chosen=3/11、rejected=8/11，margin=-5/11，应用失败。候选不入池，真实标准/Judge及采用记录进入第二轮Critic，不宣称权重改变必然成功。

## 3. 第二轮与成功分流

Critic依据实际失败证据提出C2，Generator再次从task+固定E+C2独立生成，不积累C1。最多两次Critic提案、两轮应用；不构造C2必然成功的故事。

若第二轮Judge成功且来源引用C2，则同一候选可Fusion；若成功但未引用C2，任务成功而候选不入池，结束。第二轮失败则保存并结束；空候选或错误也明确留档。

## 4. 信用示例

成功不意味着只有正证据。候选从Beta(1,1)开始：

| P / N | 新alpha / beta | confidence |
|---|---|---:|
| 0.2 / 0 | 1.2 / 1 | 6/11 |
| 0.2 / 0.2 | 1.2 / 1.2 | 0.5 |
| 0.3 / 0.2 | 1.3 / 1.2 | 0.52 |
| 0 / 0.2 | 1 / 1.2 | 5/11 |
| 0 / 0 | 1 / 1 | 0.5 |

不先抵消、不使用lambda或margin增益；只有双通道均0不增加数值证据，仍可合法ADD。R1/R2的E引用仅审计，R0信用不重复追加。Held-out冻结Memory。引用、成功和入池均不证明因果或迁移效果。
