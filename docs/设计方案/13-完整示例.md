# 完整示例：候选先准入、新会话应用与采用记录

> 新机制的说明示例，不是实测效果。见[计划31](../plans/31-Critic候选经验准入与新会话验证.md)。

## 1. R0与已有经验

Task要求“准确说明概念及区别，并尽量简洁”。Selector选出已有经验E，Generator独立生成R0。假设两条正向Boolean标准的重要性均5，Judge chosen=[false,true]、rejected=[true,false]，margin=0，失败。

若标准没有实质引用E，则该经验不更新；若引用，按R0各项来源与判别差异分配信用，正负分别更新alpha/beta。不能把失败统一当成E负证据。

## 2. 首轮准入重试

Critic提出C1：

- content：“判别失败时，应忽略简洁要求以突出概念准确性。”
- trigger：“已有rubric未能区分两份回答。”

Admission FAIL：trigger为事后条件，指导还无条件取消task约束。被拒候选和具体reason返回同一个Critic，不进入Generator。

Critic重生成新ID的C1'：

- content：“当任务同时要求概念准确和简洁表达时，分别形成内容准确与简洁的正向Boolean标准；重要性体现任务主次，不用简洁抵消实质错误。”
- trigger：“任务同时要求准确解释概念及简洁表达。”

Admission假设PASS。它只是表达合格，不是效果认证。本轮准入重试已耗尽，若C1'再FAIL则结束任务。

## 3. 全新会话、自主采用

新Generator只接收原始task、固定E及C1'，不看旧rubric、旧analysis、对话、偏好对或Judge。它自主选择采用C1'，生成内容准确与简洁两条标准，重要性为8和3；至少一条来源标注为C1'的本次编号。

假设Judge给出与前述对应问题一致的Boolean结果，则chosen=3/11、rejected=8/11，margin=-5/11，应用失败。该候选不能入池，也不能因为“通过Admission”就加正证据。将实际rubric、Judge、C1'及采用标记交给下一轮Critic，而非宣称“权重改变必然成功”。

第二轮重新提出候选C2并独立准入，仍可有一次拒绝重生成；Generator依然全新会话，只看task+E+C2，不累积C1'。最多4次Critic生成、2轮应用。

## 4. 成功分流

不人为构造C2一定成功的故事。若实际第二轮Judge成功：

- 有C2采用标记：C2可进入Fusion；默认ADD，仅同一设计问题的等价指导/必要细化才MERGE，保留来源与文本版本；
- 无C2采用标记：任务成功，但C2未采用、未验证，不入池，不再强行尝试。

若第二轮失败或准入两次失败，结束并留档。采用标记仅为模型自报，不证明因果贡献。

C2按实际引用标准的P/N分别累计，不使用lambda或margin增益。例如整体成功时：仅+0.2从(1,1)到(1.2,1)、confidence=6/11；+0.2和−0.2分别更新到(1.2,1.2)、confidence=0.5且强度增加0.4；+0.3和−0.2更新到(1.3,1.2)、confidence=0.52，不是只加净+0.1；仅−0.2到(1,1.2)、confidence=5/11。只有两通道都0才不更新，净方向不另设入池门禁。后续任务R0同样改为正负分别累计，仍只记R0一次，不重复应用里的E引用；held-out冻结。这里只展示契约，不证明质量或因果性。
