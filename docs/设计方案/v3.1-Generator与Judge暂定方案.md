# VERGE v3.1：Generator与Judge（暂定）

2026-11-13用户暂定。Generator改用任务初稿加经验修订；Critic分析Selector、Generator和Judge三类问题。尚未实现或实测，Judge误判仍是未解决问题。

## 1. Generator两阶段生成

1. **生成任务初稿R0。**只提供task，先形成任务本身的评分要求，不提供经验、候选回答、偏好标签或人工理由。
2. **根据经验修订。**向Generator提供task、R0和所选经验集合；修订以任务或合理评价依据为准，不能仅因经验提到某种做法就增加硬性要求。

经验不适用时可以保留初稿；初稿有遗漏或错误时允许纠正，不将其冻结为不可修改的真值。修订仍需检查额外要求、原要求遗漏和评价目标变化。两阶段不保证模型正确执行。

训练时，同题的初始四路共享同一份无经验初稿：

| 实际提供的经验 | 暂定生成方式 |
|---|---|
| 无经验 | 直接使用R0 |
| 仅E1 | 从R0出发，用E1修订 |
| 仅E2 | 从R0出发，用E2修订 |
| E1＋E2 | 从R0出发，两条共同修订 |

四路分别评判，实际路径仍事前固定为全部所选经验，不按标签事后挑最优子集。一条经验时两路，无经验时一路；本次未调整信用公式。

推理沿用任务初稿加经验修订，仅执行所选集合对应路径；没有经验时使用初稿。Critic来源候选如何复用初稿及相应失败处理，留待实现前明确。

## 2. Critic检查三个环节

同一次Critic调用结合task、经验与选择理由、初稿及修订稿、Judge判断、候选回答和人工偏好理由，分析：

- **Selector：**所选经验的适用前提是否得到task支持；只有能够提炼可复用的适用边界时，才考虑候选。
- **Generator：**是否将经验强化、反向应用，或改写任务范围、评价目标；针对有依据的Rubric缺陷提案。
- **Judge：**是否按当前标准执行，是否读错、漏看或算错；如果只有Judge问题，不生成评分标准设计经验。

以上为需要文本支持的诊断，不是可靠的错误标签。允许混合原因和无法判断，不强迫逐题分配唯一责任；适用边界也不等于新增一套Selector规则。完整提案条件及人工理由边界见[Critic方案](v3.1-Critic修改暂定方案.md)。

## 3. Judge与比较口径的边界

本次没有采用重复Judge、投票、自动更正或新的Judge指南。Critic仍只在实际路径最终明确判错时触发，不能覆盖所有误判；候选准入仍使用Judge，可能继续受其噪声影响。Critic能分析疑似误判，不等于已降低误判率。

**另一个待讨论点：**暂定无经验路直接用R0，有经验路多做一次修订。因此结果差异同时包含经验与多一次修订的影响，共享初稿不能单独消除这一混杂。若要更严格地区分经验贡献，需要继续讨论无经验路是否也作一次同等修订；目前未擅自增加这一步或额外对照。

当前只记录方向，尚无减少额外要求、降低Judge误判或改善整体收益的实测证据。
