# VERGE v3.1：Generator与Judge（暂定）

2026-11-13用户暂定。训练最多三条经验平等试用，每路只用一条；无经验加三个单经验分支构成最多四路，不运行经验组合。Generator保留共享初稿和同等修订，Critic分析三个环节。尚未实现或实测，Judge误判仍未解决。

## 1. Generator两阶段生成

1. **生成任务初稿R0。**只提供task，先形成任务本身的评分要求，不提供经验、候选回答、偏好标签或人工理由。
2. **每路修订一次。**向Generator提供task、R0和该路经验集合；无经验路的集合为空，也根据task和初稿修订一次。各路使用相同的修订指令与设置，修订以任务或合理评价依据为准，不能仅因经验提到某种做法就增加硬性要求。

经验不适用时可以保留初稿；初稿有遗漏或错误时允许纠正，不将其冻结为不可修改的真值。修订仍需检查额外要求、原要求遗漏和评价目标变化。两阶段不保证模型正确执行。

训练时Selector最多选择三条适用经验，不区分首选和探索；可少选或不选。各路共享同一份无经验初稿：

| 实际提供的经验 | 暂定生成方式 |
|---|---|
| 无经验 | 从R0出发，只根据task与初稿修订一次 |
| 仅E1 | 从R0出发，根据task、初稿和E1修订一次 |
| 仅E2 | 从R0出发，根据task、初稿和E2修订一次 |
| 仅E3 | 从R0出发，根据task、初稿和E3修订一次 |

最多四路都修订一次后分别评判；无经验对照使用修订稿，不直接用R0。选中几条就运行几个单经验分支，不选时仅无经验一路。三条平等记录结果，不指定代表本题的首选路径；可以统计至少一个单经验分支成功的覆盖情况，但不能将其当作推理单路准确率。

后续独立任务信用直接采用单经验差值：

```text
c(E_i) = r(E_i) − r(∅)
```

r为最终偏好判断与训练标签一致的结果（对1、未判对0），不使用Judge原始评分差。对每条经验独立要求该路与无经验路有效，其他经验路技术失败不抹去它的有效证据。未知不补0，来源候选验证仍不计信用或关联；每题每经验一份证据，共享基线不等于增加独立任务数。不需要组合信用分摊或组合排序。

推理仍最多使用一条经验，仅执行对应路径；无经验时也根据task与初稿修订一次。如何从候选中选一条或不用，尚在讨论，不把训练三路成功后的事后选择搬到推理。Critic候选如何复用初稿及相应失败处理，留待实现前明确。

## 2. Critic检查三个环节

同一次Critic调用结合task、经验与选择理由、初稿及修订稿、Judge判断、候选回答和人工偏好理由，分析：

- **Selector：**所选经验的适用前提是否得到task支持；只有能够提炼可复用的适用边界时，才考虑候选。
- **Generator：**是否将经验强化、反向应用，或改写任务范围、评价目标；针对有依据的Rubric缺陷提案。
- **Judge：**是否按当前标准执行，是否读错、漏看或算错；如果只有Judge问题，不生成评分标准设计经验。

以上为需要文本支持的诊断，不是可靠的错误标签。允许混合原因和无法判断，不强迫逐题分配唯一责任；适用边界也不等于新增一套Selector规则。完整提案条件及人工理由边界见[Critic方案](v3.1-Critic修改暂定方案.md)。

## 3. Judge与比较口径的边界

本次没有采用重复Judge、投票、自动更正或新的Judge指南。已确定任一路（含无经验）判对就不进入Critic；仅所有单经验路及无经验路都明确未判对时，进入Critic按证据决定是否提案。无经验判对而经验路全失败时，各条信用为−1，作为本次证据参与后续排序，不直接禁用经验，也不因此提出新候选。未选经验时，保留无经验失败进入Critic的冷启动规则；不足三条时按实际试用的经验路判断。技术未知不能充当明确失败，未定技术分支在实现前明确。

候选准入仍使用Judge，可能继续受其噪声影响；Critic能分析疑似误判，不等于已降低误判率。

**决策记录：**先将组合四路收缩为单经验两路，随后为增加验证覆盖，改为三个单经验路加无经验路，三条经验平等参与。限制为每路一条，并非每道训练任务只能尝试一条；组合选择仍暂缓。无经验路同等修订继续保留，不保证模型波动或效果问题消失。

当前只记录方向，尚无减少额外要求、降低Judge误判或改善整体收益的实测证据。
